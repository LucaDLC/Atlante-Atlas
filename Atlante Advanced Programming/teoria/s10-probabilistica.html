Programmazione probabilistica con Probula

Un modello probabilistico si scrive come un programma funzionale: una distribuzione è una monade, quindi si compone con map e flatMap. Si campiona per contare quante volte succede un evento, e si condiziona per rispondere a "sapendo che…".

L'idea in una schermata

  1. Scrivi un modello: dado, urna, partita. È un valore di tipo Dist[T] (distribuzione su valori T).
  2. Campiona: modello.sample(N) pesca N esiti a caso (un IData[T]).
  3. Conta: .pr(evento) dà la frazione di esiti in cui l'evento è successo. È una stima: con più campioni è più precisa.
  4. Per "sapendo che X" usa condition o matching: scartano gli esiti in cui X non vale, prima di campionare.

Dist ha map e flatMap, quindi è una monade (S9): unit è Dirac(a), una distribuzione che dà sempre a. Il for/yield funziona uguale. La casualità è nascosta come lo stato in S5: lo "stato" è il generatore casuale, passato con un given.

Il dado: Dist, map, sample, pr

Esempio tutto eseguito (Scala 3.8.4, Probula 0.2.4, N = 20000 campioni). I valori sono stime: cambiano un po' a ogni esecuzione.

Più variabili e "sapendo che": detDep, condition

Una distribuzione su tuple tiene insieme più variabili casuali. detDep aggiunge una variabile calcolata dalle precedenti (come map, ma aggiunge alla tupla invece di sostituire). condition(p) scarta gli esiti che non soddisfano p.

.condition { (n, p, odd) => odd } con tre parametri non compila: Missing parameter type. condition vuole una funzione sulla tupla intera: scrivi .condition(_._3) oppure { case (n, p, odd) => odd }. Lo stesso per probDep: annota il tipo, probDep { (n: Int) => … }.

Estrarre senza reinserire: probDep e matching

Quando la distribuzione di una variabile dipende dalle precedenti serve probDep: è un flatMap che aggiunge la nuova variabile alla tupla. Urna con due palline rosse e una verde.

Es. 6: l'urna ignota

Ora il numero di nere n è ignoto, tra 1 e 5, con prior uniforme. Si osserva che il primo giocatore ha vinto. Quanto è probabile che n sia dispari?

  • Prob. che il primo vinca: 1/2 per n=1, 3, 5; 2/3 per n=2; 3/5 per n=4.
  • Posteriore (a mano): 1,5 / (1,5 + 2/3 + 3/5) ≈ 0,542. Stima eseguita: 0,540. È sopra 1/2 solo perché ci sono tre valori dispari e due pari.
Mostra la soluzione dell'esercizio (8 test su 8 passati)
val SampleN = 4000.sampleSize

def pick (n: Int): Dist[Ball] =
  Probula.bernoulli[Ball]((1.0 / (n + 1)).pr, Red, Black)

def move(player: Player, n: Int): Dist[Player] =
  pick(n).flatMap:
    case Red => Dirac(player)
    case Black => move(next(player), n - 1)

def probPaulaStarts: Prob = move(Paula, BallsNo - 1).sample(SampleN).pr(Paula)
def probPeterStarts: Prob = move(Peter, BallsNo - 1).sample(SampleN).pr(Paula)

def gameResult: Dist[(Player, Player)] =
  Probula.uniform(Paula, Peter).probDep { (first: Player) => move(first, BallsNo - 1) }

lazy val gameWonByPaula: Dist[(Player, Player)] = gameResult.condition(_._2 == Paula)
lazy val paulaWinning: Prob = gameResult._2.sample(SampleN).pr(Paula)
lazy val probPaulaStarted: Prob = gameWonByPaula.sample(SampleN).prMatching { case (Paula, _) => }

lazy val paulaWon: Dist[Int] =
  Probula.uniform((1 until UpperBound)*)
    .probDep { (n: Int) => move(Paula, n) }
    .condition(_._2 == Paula)
    ._1

lazy val posteriorOdd: Prob = paulaWon.sample(SampleN).pr((n: Int) => n % 2 == 1)

Dentro Probula: come è fatto Dist

Le slide 11–18 mostrano come è costruita la libreria. Non serve saperla riscrivere, ma ti fa vedere che tutto ciò che hai usato è già nel corso: map, flatMap, map2 (S3, S5, S9), liste pigre (S4), extension method (S7). Il codice sotto è copiato e semplificato dalle slide: non l'ho compilato (richiede la libreria Probula e spire), tranne la parte sulle unità di misura qui in fondo.

Un campione è una lista pigra di "particelle pesate" (slide 14): opaque type Chain[+T] = LazyList[Scored[T]], dove Scored è un valore con un peso in scala logaritmica (LogScore). Le estrazioni a priori hanno peso 1.0. condition scarta le particelle; score e likelihood le ripesano sommando un logaritmo (sommare logaritmi = moltiplicare pesi). Con tanti campioni le particelle che spiegano meglio i dati pesano di più: è l'importance sampling (slide 12). pr e mean sono quindi stimatori pesati.

Perché Dist è una monade (slide 18): ha flatMap e ha un unit, che è Dirac(a), la distribuzione che dà sempre a. for/yield funziona perché Dist ha flatMap e map. Le leggi di S9 valgono.

Le unità di misura: tipi opachi ed extension method

Per non scambiare per sbaglio un numero di campioni con una probabilità, Probula li distingue con tipi opachi (come TestCases e MaxSize di S7). L'unico modo di ottenere un SampleSize è n.sampleSize, che controlla n > 0 una volta sola. Verificato con Scala 3.8.4 (tipo definito in un file, usato in un altro):

sample(10000)   // da un altro file
Found:    (10000 : Int)
Required: units.SampleSize
Un Int semplice non basta: scrivi sample(10000.sampleSize). Lo stesso schema vale per Prob (0.3.pr) e LogScore (1.5.lscore).

Su una Dist di tuple e su una di non-tuple i combinatori devono comportarsi in modo diverso (detDep aggiunge alla tupla, non annida), e Scala 3 distingue i due casi con un vincolo NotGiven[T <:< Tuple] solo negli extension method. Se uno dei due è un extension, devono esserlo tutti: altrimenti vincerebbe il metodo del trait. Inoltre ogni passo restituisce ancora una Dist, quindi le catene possono crescere.

Trasparenza referenziale e test

  • I modelli sono referenzialmente trasparenti: puoi sostituire un nome con la sua definizione. x :* x campiona x due volte in modo indipendente, come due dadi separati. Per avere correlazione serve flatMap o map2.
  • I risultati sono stime, quindi i test usano una tolleranza (about, qui 0,05 con 4000 campioni), non ==.
  • Importance sampling: condition scarta i campioni; likelihood/observe li ripesano. Le slide lo usano per la regressione bayesiana, non serve per l'esercizio.
