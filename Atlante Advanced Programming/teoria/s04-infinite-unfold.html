Liste infinite e unfold

Esercizi 1, 10–13. Una lista infinita si definisce con una funzione che chiama se stessa nella coda: grazie a cons la chiamata non parte finché non serve. unfold generalizza l'idea: da uno stato iniziale e una regola "prossimo valore e prossimo stato" genera tutta la lista.

ones, from, to, naturals

Sulle liste normali sarebbe un ciclo infinito. Qui no: ogni chiamata costruisce una cella e si ferma. La cella successiva nasce solo quando qualcuno forza la coda. naturals.toList invece non termina mai: vuole tutto.

fibs: Fibonacci infinito (esercizio 10)

Stessa idea della settimana 1: per il prossimo numero bastano gli ultimi due. Qui però non restituisco un numero: produco la lista di tutti.

lazy val fibs: LazyList[Int] =
  def go(a: Int, b: Int): LazyList[Int] = cons(a, go(b, a + b))
  go(0, 1)

unfold: il generatore generale (esercizio 11)

def unfold[A, S](z: S)(f: S => Option[(A, S)]): LazyList[A]

Perché unfold?

Fa la stessa cosa della ricorsione scritta a mano, ma la ricorsione la scrive lui: tu descrivi un passo solo.

A mano

def map[B](f: A => B): LazyList[B] =
  this match
    case Cons(h, t) =>
      cons(f(h()), t().map(f))
    case Empty => empty

Con unfold

def mapUnfold[B](f: A => B): LazyList[B] =
  unfold(this) {
    case Cons(h, t) =>
      Some((f(h()), t()))
    case Empty => None
  }

Cambiano due cose: dove scrivevi cons(valore, <ricorsione>) scrivi Some((valore, nuovoStato)); dove scrivevi empty scrivi None. cons e la chiamata ricorsiva li mette unfold, nella sua ultima riga: case Some((a, s)) => cons(a, unfold(s)(f)).

foldRight consuma una lista e dà un valore (esercizio 8). unfold parte da un valore (lo stato) e costruisce una lista (esercizio 13). In entrambi i casi non scrivi la ricorsione: nella scala di stile del corso è il passo da forgivable a enlightened.

"naturals.zipWith(_ + _)(naturals) adds each number to itself, so it gives the even numbers 2, 4, 6, …; take(2000000000) costs nothing, because it builds one node at a time.
