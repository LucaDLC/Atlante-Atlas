Option: niente eccezioni

Alcune funzioni non hanno una risposta per certi input: la media di una lista vuota, il primo elemento di niente. Invece di lanciare un'eccezione, fai restituire un Option: Some(risultato) se c'è, None se non c'è. La prima consegna valutata del corso è su questo.

Funzioni parziali e totali

Una funzione f : A → B è totale se per ogni a in A esiste un risultato in B. Se per qualche input non c'è risposta (crash, eccezione), è parziale.

Perché non le eccezioni? Un'eccezione non è un valore: rompe la trasparenza referenziale e non compare nel tipo. L'unico vantaggio delle eccezioni, dicono le slide, è poter gestire l'errore lontano da dove succede. Option mantiene questo vantaggio (lo vedi nella catena più sotto) senza i difetti.

Option è un tipo algebrico

enum Option[+A]:
  case Some(get: A)
  case None

Due forme, come la lista: Some contiene un valore, None niente. None ha tipo Option[Nothing] e grazie al +A va bene come Option[Int], Option[String]… (varianza).

La libreria standard lo usa ovunque: Map.get(key): Option[V], List.headOption, List.find(p).

Una catena che può fallire

Il vantaggio vero: scrivi i passi come se tutto andasse bene. Se un passo fallisce, il None attraversa il resto senza fare danni, e decidi cosa fare alla fine.

Voglio…La funzione passata restituisce…Uso
trasformare il valoreun valore normale Bmap
fare un altro passo che può fallireun Option[B]flatMap
scartare il valore se non va beneun Booleanfilter
uscire dall'Option con un default—getOrElse

Nelle slide trovi "the Option monad". Per ora, informalmente: un tipo che fa da contenitore con un contesto (qui: "forse non c'è niente") e ha map e flatMap per concatenare passi senza controllare il contesto ogni volta. List è monadica, Option è monadica. La definizione precisa arriva nella settimana 9.

Either: fallire con un messaggio

None dice che qualcosa è andato storto, ma non cosa. Either porta con sé l'informazione sull'errore, come farebbe un'eccezione.

enum Either[+E, +A]:
  case Left(value: E)    // errore
  case Right(value: A)   // risultato corretto ("right" = giusto)

def mean(xs: List[Double]): Either[String, Double] =
  if xs.isEmpty then Left("lista vuota")
  else Right(xs.sum / xs.length)

Nil, None e null

Quale "vuoto" usare: Nil per la lista vuota, None per il risultato che può non esserci, null solo come valore che arriva da Java e va subito convertito con Option(x). Spiegazione e confronto nella pagina dedicata.

Errori tipici

def filter(p: A => Boolean): Option[A] = this match
  case Some(a) if p(a)  => this
  case Some(a) if !p(a) => None
  case None             => None
match may not be exhaustive.

It would fail on pattern case: Option.Some(_)
Il compilatore non sa che p(a) e !p(a) coprono tutto. Con -Werror è un errore. Metti l'ultimo caso senza guardia: case _ => None.
