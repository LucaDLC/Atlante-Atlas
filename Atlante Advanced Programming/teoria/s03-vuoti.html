Nil, None, null: quando usarli

Scala ha tre modi di dire "niente", e non sono intercambiabili. Nil è una lista vuota, None è un Option senza valore, null è il riferimento vuoto di Java. Questa pagina dice quale usare, e quando non usarlo.

Il problema: manca un valore

A volte una funzione non ha un risultato da restituire: la ricerca non trova niente, la lista non ha elementi, un dato non c'è. Ci sono tre domande diverse, e ognuna ha un tipo diverso:

  • la collezione è vuota? Risposta: Nil, che è una lista senza elementi;
  • il risultato può mancare? Risposta: Option[A], con Some(valore) oppure None;
  • sto parlando con una libreria Java che restituisce un riferimento vuoto? Risposta: null, che però va convertito subito.

Nil: la lista vuota

Nil è la lista senza elementi. È il caso base delle liste costruite con ::: la lista 1 :: 2 :: Nil è List(1, 2), e il Nil in fondo dice dove finisce. Nel pattern matching si scrive case Nil => … per il caso della lista vuota.

Quando usarlo: per costruire liste e per riconoscere la fine di una lista ricorsiva. Una lista vuota è un risultato valido: se una funzione restituisce "nessun elemento", Nil è la risposta giusta, non None.

Non confondere Nil con None. Una lista vuota è una lista: si può ancora chiamare isEmpty, map, foldLeft. None invece non è una lista: è l'assenza di un risultato.

None: il risultato che può mancare

Option[A] ha due forme: Some(a), che contiene un valore, e None, che dice "nessun valore". Una funzione che può fallire restituisce un Option invece di lanciare un'eccezione o di restituire null.

Quando usarlo: ogni volta che la risposta può non esserci (una ricerca, una divisione per zero, un campo opzionale). Il chiamante è costretto a gestire il caso None, perché il tipo è Option e non A.

Non restituire None per dire "lista vuota": se la funzione produce una lista, la lista vuota è Nil. Usa None solo quando "nessun risultato" è un'informazione diversa da "zero elementi".

null: il vuoto di Java

null è il riferimento vuoto di Java. Scala lo accetta per parlare con le librerie Java, e in Scala 3 è un valore possibile per quasi ogni tipo di riferimento, anche String. Il problema: se usi un null (per esempio chiami .length), il programma lancia una NullPointerException, e il compilatore non ti avverte.

Quando usarlo: quasi mai in Scala. Solo quando una libreria Java restituisce null: in quel punto converti subito con Option(x), che dà None se x è null e Some(x) altrimenti.

Il confronto None == null dà false: sono valori diversi. Non scrivere if x == null in codice Scala nuovo: usa Option e match.

All'esame

Quando scrivi una funzione che può non trovare un risultato, dichiara il tipo Option[A] e spiega in una frase perché None e non una lista vuota o un'eccezione. Non usare null in soluzioni Scala.
Use None when a result may be absent; use Nil for an empty list, which is a valid result; convert Java null to Option at the boundary.
