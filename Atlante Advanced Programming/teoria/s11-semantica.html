Semantica dei linguaggi e interpreti

Un interprete è una funzione ricorsiva sull'albero del programma. Se il suo risultato è una monade, cambiare effetto (eccezioni, stato, output) vuol dire cambiare monade, non riscrivere l'interprete. È l'idea dell'articolo di Wadler.

Perché serve la semantica

print(1/2) è un programma valido sia in Scala che in Python. Stessa sintassi, risultati diversi: 0 in Scala (divisione tra interi), 0,5 in Python. Un linguaggio è tre cose:

  • Sintassi: quali programmi sono validi.
  • Semantica: cosa vuol dire eseguirli.
  • Implementazione: come si realizza (compilatore, interprete).

In questa lezione il linguaggio è minuscolo: numeri e divisioni. Basta per vedere tutte le idee.

Sintassi astratta: i termini

Dopo il parsing un programma è già un albero. La grammatica e ::= num(n) | e / e in Scala è un enum (un tipo algebrico, S2):

enum Term:
  case Cons(value: Int)
  case Div(left: Term, right: Term)

Come con Tree (S3): una foglia con un valore e un nodo con due figli. Precedenza e ordine di valutazione li ha già decisi il parser: l'interprete vede solo l'albero. Esempio: (1972 / 2) / 23 è Div(Div(Cons(1972), Cons(2)), Cons(23)).

Semantica big-step: regole e codice

Le regole di inferenza dicono come si calcola: sopra le premesse, sotto la conclusione. Premessa vuota = assioma. Una regola per ogni caso dell'albero:

RegolaPremesseConclusione
NUM(nessuna)num(n) → n
DIVe → n₁ e e' → n₂e / e' → n₁ / n₂

Ogni regola diventa un case dell'interprete: le premesse sono le chiamate ricorsive.

def eval (expr: Term): Int = expr match
  case Cons(n) => n
  case Div(left, right) => eval(left) / eval(right)

Valutare è costruire una derivazione: l'albero delle regole applicate, letto dal basso. eval(answer) dà 42 (verificato).

La regola DIV non dice cosa succede con n₂ = 0. Il programma "si blocca": nessun significato. In Scala 1 / 0 lancia ArithmeticException (verificato): un'eccezione, che il corso vieta.

Eccezioni come valori

Stessa sintassi, nuovo tipo di risultato: o un valore o un'eccezione. Le regole diventano cinque:

RegolaPremesseConclusione
NUM—num(n) → Return(n)
DIV-EXCe → Return(n₁), e' → Return(0)e / e' → Raise("Division by zero")
DIV-NORMe → Return(n₁), e' → Return(n₂), n₂ ≠ 0e / e' → Return(n₁ / n₂)
EXC-PROP-1e → Raise(msg)e / e' → Raise(msg)
EXC-PROP-2e' → Raise(msg)e / e' → Raise(msg)

Il problema: ogni effetto riscrive tutto

eval di base e eval con eccezioni sono molto diversi: tipo di ritorno, pattern matching sui risultati, caso speciale. In un linguaggio imperativo basterebbe cambiare una riga (quella della divisione). Vogliamo la stessa manutenibilità.

Cosa è comune: la sintassi astratta e la struttura (ricorsione sull'albero). Cosa varia: il tipo del risultato e la gestione dei casi speciali. L'idea: nascondere ciò che varia in una monade.

Interprete monadico: unit, flatMap, for

La monade eccezione ha le solite due operazioni (S9). Tutto il pattern matching sui risultati sparisce dall'interprete: lo fa flatMap.

def unit[A](a: A): M[A] = Return(a)

extension [A](ma: M[A])
  def flatMap[B](f: A => M[B]): M[B] = ma match
    case Raise(e) => Raise(e)
    case Return(a) => f(a)
  def map[B](f: A => B): M[B] = ma.flatMap(a => Return(f(a)))

Verificato (Scala 3.8.4): eval(answer) = Return(42) e eval(Div(Cons(1), Cons(0))) = Raise(Division by zero), identici nelle tre scritture (pattern matching, flatMap, for).

Con type M[A] = A, unit(a) = a e flatMap(ma)(f) = f(ma) l'identica funzione eval con for riproduce l'interprete di base. Passare da un effetto all'altro vuol dire cambiare il tipo di ritorno e il caso speciale, come nell'imperativo.

Gli altri effetti: stato e output

Le slide arrivano a eccezioni e Identity. Stato e output sono negli esercizi (dall'articolo di Wadler): stessa struttura, monade diversa.

EffettoTipo M[A]Cosa fa il valutatoreunit(a)
EccezioniRaise(e) o Return(a)Raise sulla divisione per zeroReturn(a)
StatoM(step: Int => (A, Int))conta le divisioni: tick aggiunge 1 allo statovalore e stato invariato
OutputM(o: String, a: A)scrive una riga per ogni nodo valutatoM("", a)

Con la monade stato la stessa catena di flatMap passa il contatore da una chiamata all'altra, come State in S5. Per answer le divisioni sono 2, quindi eval(answer).step(n) = (42, n+2) (come verificano i test).

La semantica non è mai stata chiesta nelle prove 2019–2025: è nuova nel corso 2026. Aspettati domande sul pattern valutatore → monade: scrivere un eval con for, o istanza Monad per un nuovo effetto. Le leggi della monade (identità sinistra e destra, associatività) sono le stesse di S9.
