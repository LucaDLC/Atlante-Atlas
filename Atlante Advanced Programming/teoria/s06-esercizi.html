Pigrizia: esercizi 2, 3, 4, 7

Questi quattro esercizi chiedono di controllare cosa una funzione non calcola. Un risultato giusto non basta: serve una lista con le bombe messe proprio dove la funzione non deve guardare. Se il test finisce senza esplosioni, restituisce true.

  • Es. 2: headOption non forza la coda → bomba nella coda: cons(n, bomba).
  • Es. 3: take non forza né teste né code → una lista di teste-bomba e una con la coda-bomba; si chiama take(n) senza guardare il risultato.
  • Es. 4: take(n) non forza la testa numero n+1, nemmeno se forzi i primi n → n elementi buoni e poi una bomba; take(n).toList.

Mostra la soluzione (es. 2, 3, 4, 7)
// liste con le bombe
def bombe: LazyList[Int] = cons(bomba, bombe)

def buoniPoiBomba(n: Int, i: Int = 1): LazyList[Int] =
  if n == 0 then cons(bomba, empty) else cons(i, buoniPoiBomba(n - 1, i + 1))

def bombePoi(n: Int, rest: LazyList[Int]): LazyList[Int] =
  if n == 0 then rest else cons(bomba, bombePoi(n - 1, rest))

property("Ex02: headOption does not force the tail") =
  forAll { (n: Int) => cons(n, bomba).headOption == Some(n) }

property("Ex03: take does not force heads nor tails") =
  forAll(genN) { n =>
    bombe.take(n)
    cons(1, bomba).take(n)
    true }

property("Ex04: take(n) does not force the (n+1)st head") =
  forAll(genN) { n => buoniPoiBomba(n).take(n).toList == List.range(1, n + 1) }

property("Ex07: drop(n) does not force dropped heads") =
  forAll(genN) { n => bombePoi(n, LazyList(1, 2, 3)).drop(n).toList == List(1, 2, 3) }

Liste infinite: esercizio 9

"map termina su liste infinite": fai map su una lista infinita e poi prendi un pezzo finito. Se map è pigro, calcola solo quel pezzo; se è stretto, prova a calcolare tutta la lista e non finisce mai (in pratica: StackOverflowError, che conta come test fallito). Le liste infinite le dà infiniteLazyList[Int], già nel file.

Mostra la soluzione (es. 9)
property("Ex09: map terminates on infinite lists") =
  forAll(infiniteLazyList[Int], genN) { (l, n) =>
    l.map(_ + 1).take(n).toList == l.take(n).toList.map(_ + 1) }

Fallisce sulla LazyList giusta: se l è vuota, l.append(that) è that, e restituirlo vuol dire calcolarlo. La proprietà vale solo per l non vuota: forAll(genNonEmptyLazyList[Int]) { l => … }. Errore mio, trovato provando il file su lazyList00: prova sempre i tuoi test sulla versione giusta.

property("Ex10.01: append = ++ on lists") =
  forAll { (l1: LazyList[Int], l2: LazyList[Int]) =>
    l1.append(l2).toList == l1.toList ++ l2.toList }

property("Ex10.02: append does not force its argument (non-empty this)") =
  forAll(genNonEmptyLazyList[Int]) { l => l.append(bomba); true }

property("Ex10.03: infinite append anything = infinite") =
  forAll(infiniteLazyList[Int], genN) { (l, n) =>
    l.append(bomba).take(n).toList == l.take(n).toList }

I mutanti: come controllare i tuoi test

Non abbiamo i mutanti del correttore, ma se ne possono fare: si copia lazyList00, si rompe una funzione e si guarda se almeno un test fallisce. Ne ho fatti 13; con la soluzione di questa pagina li uccide tutti, e lazyList00 passa tutti i 13 test (verificato).
