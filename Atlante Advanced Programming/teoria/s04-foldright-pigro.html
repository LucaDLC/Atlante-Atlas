foldRight pigro

Sulle liste normali foldRight consuma sempre tutto. Su una LazyList no: la funzione riceve il resto come ricetta, e se non la usa il fold si ferma. Per questo funziona anche su liste infinite, ed è la base degli esercizi 6–9.

La firma del corso, pezzo per pezzo

LazyList(1, 2, 3).foldRight("z")((a, acc) => s"f($a, $acc)")
LazyList(1, 2, 3).foldLeft("z") ((a, acc) => s"f($a, $acc)")

Su LazyList parti da foldRight. Il commento del file su foldLeft lo dice: "Eager; cannot be used to work with infinite lazy lists" e "Even if f does not force z, foldLeft will continue to recurse". foldLeft serve su liste finite, quando vuoi la pila costante o proprio l'ordine invertito.

exists che si ferma

def exists(p: A => Boolean): Boolean =
  foldRight(false)((a, b) => p(a) || b)

headOption con foldRight (esercizio 7)

def headOption1: Option[A] =
  foldRight(None)((a, _) => Some(a))

È proprio il punto dell'esercizio: dimostrare che foldRight può fermarsi al primo passo. Su una List normale lo stesso codice attraverserebbe tutta la lista prima di rispondere.

map, filter, append, flatMap (esercizio 8)

Tutte con foldRight, senza ricorsione esplicita. Il trucco è sempre lo stesso: costruire con cons, così il resto (acc) resta una ricetta.

No, sono cose diverse. A è un tipo: il tipo degli elementi, nasce in enum LazyList[+A] e vale per tutti i metodi. this è un valore: la lista su cui chiami il metodo, di tipo LazyList[A]. Su LazyList(1, 2, 3).map(…): this = la lista (1, 2, 3), A = Int.

B invece non esiste finché non lo dichiari fra quadre dopo il nome: def map[B](…). Lo sceglie la f a ogni chiamata: map(_ * 2) → B = Int, map(_.toString) → B = String.

Con foldRight z finisce in fondo: è quello che c'è quando la lista finisce. Quindi in append that va dopo this:

LazyList(1, 2).append(LazyList(8, 9))
= f(1, f(2, that))  =  cons(1, cons(2, that))   // List(1, 2, 8, 9)

Per map, filter e flatMap "cosa c'è quando la lista finisce" è empty; solo per append è that.

def map(f: A => B): LazyList[B] = …
Not found: type B
B è usato ma mai dichiarato. Va fra quadre dopo il nome: def map[B](f: A => B).
foldRight(empty)((a,acc => cons(f(a), acc)))
Not found: a
Parentesi della lambda al posto sbagliato: Scala legge una coppia (a, acc => …) e a non è definito. Si scrive (a, acc) => …: parametri dentro le parentesi, freccia subito dopo.
foldRight(empty)((a,acc) => cons((a,that,acc)))
Found:    (A, adpro.lazyList.LazyList[B], adpro.lazyList.LazyList[B])
Required: B
cons prende due argomenti; con le parentesi doppie gli arriva una tripla, nello slot della testa. In append that non va nel passo ma in z: foldRight(that)((a, acc) => cons(a, acc)).
def flatMap[B](f: A => LazyList[B]): LazyList[B] =
  foldRight(empty)((a,acc) => cons(f(a), acc))
Found:    adpro.lazyList.LazyList[B]
Required: B
Copiato da map, ma qui f(a) è già una lista: non può fare da testa. Si attacca al resto: f(a).append(acc).

Esercizio 9: perché find con filter va bene qui

def find(p: A => Boolean): Option[A] = this.filter(p).headOption

Su LazyList

from(0).find(_ > 2): filter costruisce il risultato pigramente, headOption chiede solo il primo. Calcolati 0, 1, 2, 3 e basta (verificato).

Su List

List(1, 2, 3, 4).filter(_ > 2).headOption: filter è strict, controlla tutti e 4 gli elementi e crea una lista intera, poi se ne usa uno (verificato stampando).

"On a lazy list, filter does not traverse the whole list: it only produces elements when they are demanded. headOption demands just the first one, so find stops as soon as it meets the first element satisfying p. On a strict List, filter would first test every element and build a new list, only to keep its head, which wastes time and memory, and would not terminate on an infinite structure."

find può non trovare niente, quindi restituisce un Option: LazyList(1, 2, 3).find(_ > 10) → None. Dentro Some c'è l'elemento trovato, non la condizione: find(_ > 2) → Some(3). Some(x > 2) sarebbe Some(true): un Option[Boolean].

È il primo elemento che soddisfa p: LazyList(1, 2, 3, 4).find(_ > 2) → Some(3), il 4 non viene nemmeno guardato. Se ti serve solo sapere se esiste, c'è exists, che dà true/false.
