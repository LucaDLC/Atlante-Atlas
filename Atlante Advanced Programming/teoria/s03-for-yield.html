for / yield

for … yield sembra un ciclo, ma non lo è. Il compilatore lo riscrive in flatMap e map prima di fare qualsiasi altra cosa. È solo un modo più leggibile di scrivere catene di Option (o di liste). Per questo è permesso, anche se i cicli sono vietati.

È vietato il for che fa qualcosa, con do: for x <- lista do println(x) restituisce Unit e vive di effetti. Il for con yield produce un valore ed è solo un altro modo di scrivere flatMap/map: è codice puro.

Nel materiale della lezione c'è la versione F# dello stesso meccanismo, una computation expression. Si traduce simbolo per simbolo:

option { … } ⇒ for … yield …  ·  let! x1 = Some 4 ⇒ x1 <- Some(4), perché Bind è il flatMap  ·  yield r ⇒ yield r: Yield mette r dentro Some (il commento del docente: di solito si chiama Return).

Nell'esempio: x1 = 4, x2 = 4 / 2 = 2, x3 = 3, risultato Some "3". Se x1 fosse dispari, x2 sarebbe None e tutto il blocco darebbe None. Verificato con la traduzione in Scala: da 4 esce Some(3), da 3 esce None.

Funziona anche sulle liste (slide 25)

for
  x <- List(3, 4, 5)
  incremented = x + 1
  duplicated <- List(incremented, incremented)
  if incremented % 2 == 0
yield duplicated

headGrade: _._2 passo per passo

Esercizio 7: data una lista di coppie (nome, voto), il voto del primo, o None.

Perché la coppia non ha campi con nome: Scala non può sapere da solo quale pezzo vuoi. _2 è proprio il nome del metodo che restituisce il secondo pezzo. Con una tripla esisterebbe anche _3.

headOption(lst).map(_.1)
',' or ')' expected, but number literal found
Non è un indice: il metodo si chiama _1, con il trattino basso. Quindi _._1.
def r: Option[Int] = lst.headOption.map(_._1)
Found:    (_$1._1 : String)
Required: Int
_1 è il nome, una String. Il voto è _2.
for x <- Some(4) if x % 2 == 0 yield x   // con l'Option del corso
value withFilter is not a member of Option.Some[Int]
Un if dentro un for cerca il metodo withFilter, non filter. L'Option degli esercizi non ce l'ha. Nessun esercizio lo richiede: usa .filter fuori dal for.
