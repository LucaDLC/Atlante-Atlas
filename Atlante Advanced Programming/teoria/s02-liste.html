Lavorare sulle liste

tail, drop, dropWhile, init, append: cinque funzioni degli esercizi 2–5 che insegnano a scorrere una lista con il pattern matching. E a capire quanto costa ognuna, perché una lista si legge solo dall'inizio.

tail: togliere il primo, senza copiare

Perché confonderebbe due cose diverse: "la lista aveva un solo elemento, la coda è vuota" e "mi hai dato una lista vuota, non ha senso chiedere la coda". I test dell'esercizio controllano proprio che venga lanciata l'eccezione.

dropWhile: decide la condizione

init: l'operazione scomoda

Togliere l'ultimo elemento è difficile per una lista: bisogna arrivare in fondo e ricostruire tutte le celle attraversate.

append: attaccare due liste

def append[A](l1: List[A], l2: List[A]): List[A] = l1 match
  case Nil => l2
  case Cons(h, t) => Cons(h, append(t, l2))

Nil, None e null

Quale "vuoto" usare: Nil per la lista vuota, None per il risultato che può non esserci, null solo come valore che arriva da Java e va subito convertito con Option(x). Spiegazione e confronto nella pagina dedicata.

Errori tipici

def init[A](l: List[A]): List[A] = l match
  case Nil => Nil
  case Cons(h, t) => if t == Nil then h else init(h)
Found:    (h : A)
Required: List[A]
h è un elemento, ma init deve restituire una lista e riceve una lista. Ricostruisci: Cons(h, init(t)), con il caso Cons(_, Nil) => Nil sopra.
def length[A](l: List[A]): Int = l match
  case Nil => Nil
  case Cons(_, t) => 1 + length(t)
Found:    (List.Nil : List[Nothing])
Required: Int
Ogni caso deve dare il tipo di ritorno. La lunghezza della lista vuota è il numero 0, non la lista Nil.
