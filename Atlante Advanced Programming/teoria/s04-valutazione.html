Strict, by-name, lazy

Quando viene calcolato l'argomento di una funzione? Prima di entrare (strict), ogni volta che lo usi (by-name), oppure la prima volta che lo usi e poi basta (lazy). Scala li ha tutti e tre, e le LazyList di questa settimana si reggono sugli ultimi due.

Il trabocchetto del sondaggio

val a = 42
val res = if2(a < 22, () => println("a"), () => println("b"))

Quanto vale res? Risposta: () — il valore Unit. 42 < 22 è falso, quindi viene eseguita la ricetta del ramo falso, che stampa "b". Ma println restituisce Unit, quindi res = () (verificato: res = ()). La stampa è un effetto, non il valore.

lazy val: calcola una volta, poi ricorda

Un parametro by-name viene ricalcolato ogni volta che lo usi. Se vuoi calcolarlo una volta sola, mettilo in una lazy val.

Le tre strategie, definite

Gli argomenti vengono calcolati prima della chiamata; nel corpo si sostituisce il loro valore.

Gli argomenti non vengono calcolati: nel corpo si sostituisce l'espressione stessa, che viene calcolata a ogni uso.

Lazy = call-by-name + memoria: l'espressione si calcola al primo uso e il risultato viene riusato dopo.

f(x) è strict se, per ogni espressione x che non termina o fallisce, anche f(x) non termina o fallisce. if, && e || non sono strict: false && crash() vale false.

In un programma puro le tre strategie danno lo stesso risultato: cambiano solo tempo e memoria. Con gli effetti (stampe, numeri casuali) i risultati diventano diversi, per questo la laziness si usa con codice puro.

A cosa serve

  • Funzioni non strict: il default di getOrElse(default: => B) si calcola solo con None.
  • Dati grandi: calcolare solo le parti che servono davvero.
  • Generatori: la lista infinita dei naturali, dei numeri primi, di numeri casuali (le LazyList).
  • Separare il cosa dal come: descrivi un calcolo grande ed esegui solo il pezzo che ti serve.

Errori tipici: h contro h()

case Cons(h, t) => h :: t().toList
Found:    (h : () => A)
Required: A
h è la ricetta, h() è il valore. :: vuole il valore: h().
case Cons(h, t) => if p(h()) then cons(h(), t.takeWhile(p)) else empty
value takeWhile is not a member of () => LazyList[A]
t è una funzione, e le funzioni non hanno il metodo takeWhile. Prima esegui la ricetta: t().takeWhile(p).
enum LazyList[+A]:
  case Cons(h: => A, t: => LazyList[A])
val parameters may not be call-by-name
Ecco perché il Cons del corso usa () => A: i campi di un case non possono essere by-name. Il costruttore comodo cons (pagina successiva) risolve il problema.
