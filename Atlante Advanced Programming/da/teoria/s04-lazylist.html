LazyList

En LazyList har samme form som en liste, men hoved og hale er opskrifter, der kun køres, når nogen beder om værdien. Derfor kan den være uendelig: kun den del, du bruger, beregnes.

take og drop

En drop, der på n <= 0 returnerer empty, kompilerer, men er forkert: LazyList(1, 2, 3).drop(0) skal give 1, 2, 3, ikke den tomme liste. Fem tests fejler: Ex03.01, Ex03.02, Ex03.05, Ex04.01, Ex10.02 (også Fibonacci, fordi dets test bruger drop). I din fil stod netop denne linje, nu rettet.

def drop(n: Int): LazyList[A] =
  if n <= 0 then LazyList[A] else …
missing argument list for method apply in object LazyList

  def apply[A](as: A*): adpro.lazyList.LazyList[A]

where:    A is a type variable
LazyList[A] è un tipo, non un valore. Scritto in mezzo al codice, Scala prova a chiamare il costruttore LazyList(…) e gli mancano gli argomenti. Il valore che serve è this: la lista su cui è stato chiamato drop.

"It terminates because cons is non-strict in its tail: take(1000000000) only builds the first node and keeps the rest as an unevaluated thunk. drop(41) then forces 41 nodes, and take(10).toList forces 10 more. About 51 elements are ever computed; nothing is allocated for the remaining billion."

"toList is strict: it recurses until it meets Empty, which on an infinite list never happens. The recursion never returns, so it loops forever or overflows the stack."

takeWhile, forAll, exists

def takeWhile(p: A => Boolean): LazyList[A] = this match
  case Cons(h, t) if p(h()) => cons(h(), t().takeWhile(p))
  case _ => empty

def forAll(p: A => Boolean): Boolean = this match
  case Empty => true
  case Cons(h, t) => p(h()) && t().forAll(p)

def exists(p: A => Boolean): Boolean = this match
  case Empty => false
  case Cons(h, t) => p(h()) || t().exists(p)

&& og || er ikke strict: hvis venstresiden allerede afgør resultatet, beregnes højresiden ikke. Så stopper forAll ved det første element, der fejler, og exists ved det første, der lykkes.

naturals.forAll(_ < 0) terminerer? Svar: Ja, med det samme: false. 1 < 0 er falsk ved første element: && kigger ikke på resten (kontrolleret: false).

Og naturals.forAll(_ >= 0)? Svar: Nej: den finder aldrig et modeksempel og løber tør for stak. Hvert naturligt tal er ≥ 0, så den skal kontrollere i det uendelige. Teksten siger det: på uendelige lister giver forAll og exists kun mening, hvis du allerede kender svaret.

"takeWhile builds its result with cons, one node at a time, so it never scans ahead. Only the ~150 elements that drop and take actually request are evaluated. The predicate is never false here, but that does not matter: nobody asks for more."

forAll { _ >= 0 }: "forAll stops only when it finds an element that fails the predicate. Every natural is ≥ 0, so it keeps recursing over an infinite list and overflows the stack."

forAll og exists på uendelige lister: "On an infinite list forAll can only terminate by returning false, and exists only by returning true — so you may use them only when you already know the answer, and then you do not need them. On a finite list they always terminate, because in the worst case they reach the end."

To lister af tilfældige tal (slide 14)

lazy val random1: LazyList[Double] = Cons(() => Math.random, () => random1)
lazy val random2: LazyList[Double] = cons(Math.random, random2)

random1: direkte Cons

Opskriften () => Math.random køres igen ved hver læsning: random1.take(2).toList giver forskellige tal hver gang.

random2: med cons

cons lægger hovedet i en lazy val: beregnet én gang, derefter altid det samme.

Kontrolleret: to kald af random1.take(2).toList giver forskellige lister, med random2 de samme. random1 er ikke referentielt transparent, fordi Math.random er en effekt.

Hvorfor dovne lister

  • De adskiller beskrivelsen af en beregning fra dens udførelse: generatoren er den samme, uanset om der skal bruges 42 tal eller 1000.
  • Kun det, der er nødvendigt, beregnes, som om alt lå i hukommelsen.
  • lista.map(f).map(g) på en List gennemløber listen to gange; på en LazyList nul gange, indtil nogen beder om værdierne.
  • De er funktionelle iteratorer: i Java er en Iterator doven evaluering med next() som tvingelse.
