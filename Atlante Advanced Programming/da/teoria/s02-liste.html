At arbejde med lister

tail, drop, dropWhile, init, append: fem funktioner fra øvelserne 2–5, der lærer dig at gennemløbe en liste med pattern matching. Og at forstå hvad hver koster, for en liste kan kun læses fra begyndelsen.

tail: at fjerne det første uden at kopiere

Fordi det ville forveksle to forskellige ting: "listen havde ét element, og halen er tom" og "du gav mig en tom liste, og det giver ingen mening at spørge efter halen". Øvelsens tests kontrollerer netop, at undtagelsen kastes.

drop: tail gentaget n gange

dropWhile: betingelsen afgør

init: den besværlige operation

At fjerne det sidste element er svært for en liste: man må nå til enden og genopbygge alle de gennemløbne celler.

append: at hægte to lister sammen

def append[A](l1: List[A], l2: List[A]): List[A] = l1 match
  case Nil => l2
  case Cons(h, t) => Cons(h, append(t, l2))

Nil, None e null

Hvilket "tom" man skal bruge: Nil til den tomme liste, None til resultatet, der måske ikke findes, null kun som en værdi, der kommer fra Java, og straks skal omdannes med Option(x). Forklaring og sammenligning står på den dedikerede side.

Typiske fejl

def init[A](l: List[A]): List[A] = l match
  case Nil => Nil
  case Cons(h, t) => if t == Nil then h else init(h)
Found:    (h : A)
Required: List[A]
h è un elemento, ma init deve restituire una lista e riceve una lista. Ricostruisci: Cons(h, init(t)), con il caso Cons(_, Nil) => Nil sopra.
def length[A](l: List[A]): Int = l match
  case Nil => Nil
  case Cons(_, t) => 1 + length(t)
Found:    (List.Nil : List[Nothing])
Required: Int
Ogni caso deve dare il tipo di ritorno. La lunghezza della lista vuota è il numero 0, non la lista Nil.
