Dovent foldRight

På almindelige lister forbruger foldRight altid alt. På en LazyList ikke: funktionen modtager resten som en opskrift, og hvis den ikke bruger den, stopper fold'et. Derfor virker det også på uendelige lister, og det er grundlaget for øvelserne 6–9.

foldRight og foldLeft: hvor z ender

Filen har allerede begge (skrevet af underviseren). For at se dem udskriver jeg i stedet for at regne den formel, de bygger.

LazyList(1, 2, 3).foldLeft("z") ((a, acc) => s"f($a, $acc)")

På LazyList starter man fra foldRight. Kommentaren i filen om foldLeft siger det: "Eager; cannot be used to work with infinite lazy lists" og "Even if f does not force z, foldLeft will continue to recurse". foldLeft er nyttig på endelige lister, når man vil have konstant stak eller netop den omvendte rækkefølge.

exists, der stopper

def exists(p: A => Boolean): Boolean =
  foldRight(false)((a, b) => p(a) || b)

headOption med foldRight (øvelse 7)

def headOption1: Option[A] =
  foldRight(None)((a, _) => Some(a))

Det er netop pointen med øvelsen: at vise, at foldRight kan stoppe ved første trin. På en almindelig List ville den samme kode gennemløbe hele listen, før den svarer.

takeWhile med foldRight (øvelse 6)

naturals.takeWhile1(_ < 4).toList   // List(1, 2, 3)

map, filter, append, flatMap (øvelse 8)

Alle med foldRight, uden eksplicit rekursion. Tricket er altid det samme: at bygge med cons, så resten (acc) forbliver en opskrift.

Nej, de er forskellige ting. A er en type: elementernes type, født i enum LazyList[+A] og gælder for alle metoder. this er en værdi: listen, man kalder metoden på, af typen LazyList[A]. På LazyList(1, 2, 3).map(…): this = listen (1, 2, 3), A = Int.

B findes derimod ikke, før man erklærer den i firkantede parenteser efter navnet: def map[B](…). Den vælges af f ved hvert kald: map(_ * 2) → B = Int, map(_.toString) → B = String.

Med foldRight ender z nederst: det er det, der er, når listen slutter. Så i append skal that komme efter this:

LazyList(1, 2).append(LazyList(8, 9))
= f(1, f(2, that))  =  cons(1, cons(2, that))   // List(1, 2, 8, 9)

For map, filter og flatMap er "det, der er, når listen slutter", empty; kun for append er det that.

Copiato da map, ma qui f(a) è già una lista: non può fare da testa. Si attacca al resto: f(a).append(acc).

Øvelse 9: hvorfor find med filter er i orden her

def find(p: A => Boolean): Option[A] = this.filter(p).headOption

På LazyList

from(0).find(_ > 2): filter bygger resultatet dovent, headOption beder kun om det første. Beregnet 0, 1, 2, 3 og det er alt (kontrolleret).

På List

List(1, 2, 3, 4).filter(_ > 2).headOption: filter er strict, den kontrollerer alle 4 elementer og bygger en hel liste, og så bruges et af dem (kontrolleret ved udskrivning).

"On a lazy list, filter does not traverse the whole list: it only produces elements when they are demanded. headOption demands just the first one, so find stops as soon as it meets the first element satisfying p. On a strict List, filter would first test every element and build a new list, only to keep its head, which wastes time and memory, and would not terminate on an infinite structure."

find kan ikke finde noget, så den returnerer en Option: LazyList(1, 2, 3).find(_ > 10) → None. Inde i Some er der det fundne element, ikke betingelsen: find(_ > 2) → Some(3). Some(x > 2) ville være Some(true): en Option[Boolean].

Det er det første element, der opfylder p: LazyList(1, 2, 3, 4).find(_ > 2) → Some(3), 4'eren kigges ikke engang på. Hvis du kun skal vide, om der findes et, er der exists, som giver true/false.
