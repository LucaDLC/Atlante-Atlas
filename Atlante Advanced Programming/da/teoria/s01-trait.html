Traits og mixins

En trait er et stykke klasse, du kan tilføje til flere klasser: den kan have metoder, der allerede er skrevet, metoder der skal udfyldes, og felter. En klasse kan "blande" så mange, den vil. I øvelse 1 i uge 3 bruger du den til at tilføje < til en Java-klasse.

Fra Java til Scala

I Java har en klasse kun én forælder, men den kan implementere flere interfaces. En trait er som et Java-interface, der også kan indeholde kode og felter.

Øvelse 1, uge 3: OrderedPoint

Mål: at kunne skrive p < q mellem to java.awt.Point, en Java-klasse, som du ikke kan ændre. Scala-biblioteket har allerede traiten Ordered[T]: hvis du skriver metoden compare, giver den dig <, >, <=, >=.

trait OrderedPoint extends scala.math.Ordered[java.awt.Point]:
  override def compare(that: java.awt.Point): Int =
    if this.x < that.x then -1 else 1
value x is not a member of OrderedPoint
Senza this: java.awt.Point => il trait non sa di essere dentro un Point, quindi this.x non esiste.

Den virker kun, hvis du opretter objektet selv, for du skal skrive with OrderedPoint. Et Point, der kommer til dig færdigt fra et bibliotek, har ikke traiten. Øvelsesarket annoncerer, at type classes vil blive gennemgået senere, og de løser netop dette.

To traits med samme metode: hvem vinder?

Hvis to traits definerer den samme metode igen, sætter Scala dem i en række: den yderst til højre vinder, og super går videre til den næste i rækken.

trait Base:
  def saluta: String = "Base"
trait A extends Base:
  override def saluta: String = "A>" + super.saluta
trait B extends Base:
  override def saluta: String = "B>" + super.saluta

class X extends A, B     // X().saluta == "B>A>Base"
class Y extends B, A     // Y().saluta == "A>B>Base"

Resultater kontrolleret ved kompilering. I kurset er det nok at kende reglen "den yderst til højre vinder".
