Regole e divieti

Ogni foglio esercizi inizia con la stessa frase: "Do not use variables, side effects, exceptions or return statements (unless explicitly asked for)." Il compilatore non te lo impedisce: var e return compilano. Il voto sì.

"Unless explicitly asked for": in alcuni esercizi il testo chiede proprio un'eccezione. Esempio: tail, drop e init della settimana 2 devono lanciare NoSuchElementException. Lì va fatto.

È la griglia con cui il corso giudica il codice. Ogni riga va da sinistra (peggio) a destra (meglio). "Always choose the best possible style for an exercise and your abilities."

Nota a piè di slide: la regola vale "unless asked for explicitly, or really important for memory use". Per esempio la ricorsione in coda si usa se serve davvero a non esaurire la pila.

Dalla settimana 2: la ricorsione esplicita "puzza"

"From now on, the use of explicit recursion is bad-smell for us. Only use explicit recursion when dealing with a non-standard iteration. Otherwise, you should use a suitable HOF. Similarly, you should only use fold if any of the other simpler HOFs cannot."

Ordine di scelta: API dedicata (map, filter, exists…) → fold → ricorsione solo se l'iterazione è insolita.

Quando il compilatore ti boccia da solo

Il project.scala del corso compila con -Werror: ogni avviso diventa un errore. Quindi il file non compila, e un homework che non compila non passa.
