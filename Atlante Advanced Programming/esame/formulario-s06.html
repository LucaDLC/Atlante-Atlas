S6–S7 · Testing e property-based testing

Formulario della lezione: la teoria, gli atomi (simboli, tipi, costruttori, funzioni) con cosa chiedono tra parentesi, i pezzi di codice dei tuoi esercizi e in fondo il codice completo animato, con ogni pezzo evidenziato. Torna all'indice del formulario.

Teoria

  • Asserzione = condizione booleana che nelle esecuzioni corrette è vera. require(c): pre-condizione, colpa di chi chiama (IllegalArgumentException: requirement failed). x.ensuring(r => P(r)): post-condizione, colpa della funzione (AssertionError). assert(c): deve valere il programma (AssertionError: assertion failed). assume(c): un'ipotesi (AssertionError: assumption failed).
  • Property-based testing: al posto di pochi esempi scrivi una proprietà che deve valere per tutti gli input; ScalaCheck ne genera 100 a caso e cerca un controesempio. Se lo trova fa lo shrinking: lo riduce al più piccolo che fallisce.
  • Come si inventa una proprietà: (1) legge algebrica: l.drop(n).drop(m) == l.drop(n + m); (2) idempotenza: l.take(n).take(n) == l.take(n); (3) identità: l.map(identity) == l; (4) oracolo: confronto con l'implementazione standard (list2lazyList(la).take(n).toList == la.take(n)); (5) pigrizia: un valore che lancia un'eccezione se viene forzato (tailForceFinder) e verifico che non scatti.
  • Specificare un minimum richiede due proprietà insieme: (P1) tutti gli elementi sono ≥ m; (P2) m è nella lista. Una sola non basta: restituire Int.MinValue soddisfa P1, restituire un numero qualunque della lista soddisfa P2. Le proprietà sono funzioni di minimum per poterle provare su implementazioni sbagliate (mutanti).
  • Gen[A] = State[RNG, A] (un generatore è un automa a stati: S5). Prop = (MaxSize, TestCases, RNG) => Result. Result = Passed oppure Falsified(failure, successes). SGen[A] = Int => Gen[A]: generatore che dipende dalla taglia, per provare da input piccoli a grandi.
  • opaque type: dentro il file Gen è un State; fuori nessuno lo sa. Non è una classe, quindi non ha un corpo per i metodi: si aggiungono con extension method (g.listOfN(5) funziona lo stesso con il punto).
  • Type class: given definisce un'istanza, using la chiede, summon[T] la recupera. def f[A: Gen] è zucchero per def f[A](using Gen[A]).
  • In ScalaCheck: forAll { (x: Int) => … }, p1 && p2, cond ==> prop (pre-condizione: scarta i casi che non la soddisfano), prop :| "etichetta".

Pezzi di codice e cosa fanno

Test di LazyList (settimana 6)

def tailForceFinder[A]: A = throw RuntimeException("Tail Forced!")
def headForceFinder[A]: A = throw RuntimeException("Head Forced!")
def ForceFinder: LazyList[Int] = cons(tailForceFinder, ForceFinder)

property("Ex02.01: headOption does not force the tail of a lazy list") =
  cons(3, tailForceFinder).headOption == Some(3)

property("Ex05.01: l.take(n).take(n) == l.take(n)") =
  forAll(arbitrary[LazyList[Int]], Genn) { (l, n) =>
    l.take(n).take(n).toList == l.take(n).toList } :| "finite" &&
  forAll(infiniteLazyList[Int], Genn) { (l, n) =>
    l.take(n).take(n).toList == l.take(n).toList } :| "infinite"

property("Ex10.02: append does not force its argument (non-empty lazy list)") =
  forAll(genNonEmptyLazyList[Int]) { l =>
    l.append(tailForceFinder)
    true }

Cosa fanno. tailForceFinder è una "trappola": se il codice forza la coda, lancia e il test fallisce. Se il test passa, la funzione è davvero pigra. Genn = generatore di numeri 0–50. infiniteLazyList prova la proprietà anche su liste infinite. :| "finite" etichetta il pezzo che fallisce.

Specificare minimum (Exercise 3 e 16)

val intList =
  org.scalacheck.Gen.listOf(org.scalacheck.Gen.choose(0, 100)).suchThat (_.nonEmpty)

def p1Min (minimum: List[Int] => Int): org.scalacheck.Prop =
  org.scalacheck.Prop.forAll(intList) { list =>
    val m = minimum(list)
    list.forall { elemento => elemento >= m } }

def p2Min (minimum: List[Int] => Int): org.scalacheck.Prop =
  org.scalacheck.Prop.forAll(intList) { list =>
    val m = minimum(list)
    list.contains(m) }

Cosa fanno. intList genera liste non vuote di numeri 0–100 (minimum di una lista vuota non ha senso). p1Min: ogni elemento è ≥ m. p2Min: m compare nella lista. Insieme dicono "m è il più piccolo". La versione dell'esercizio 16 è identica ma usa Prop.forAll(nonEmptyList), con liste di taglia crescente.

Gen: choose · unit · boolean · listOfN · flatMap · map · listOf · union

opaque type Gen[+A] = State[RNG, A]

object Gen:
  def choose (start: Int, stopExclusive: Int): Gen[Int] =
    State(RNG.nonNegativeInt).map { n => start + n % (stopExclusive - start) }

  def unit[A] (a: =>A): Gen[A] = State.unit(a)
  def boolean: Gen[Boolean] = State(RNG.boolean)

  extension [A](self: Gen[A])
    def listOfN(n: Int): Gen[List[A]] =
      State.sequence(List.fill(n)(self))

    def flatMap[B](f: A => Gen[B]): Gen[B] =
      State.flatMap(self)(f)

    def map[B](f: A => B): Gen[B] =
      self.flatMap { a => unit(f(a)) }

    def listOf(size: Gen[Int]): Gen[List[A]] =
      size.flatMap { n => self.listOfN(n) }

    def union (that: Gen[A]): Gen[A] =
      boolean.flatMap { b => if b then self else that }

Cosa fanno. choose(a, b): un intero in [a, b) (non negativo del generatore, resto della divisione, spostato di a). listOfN(n): n copie del generatore in sequenza. flatMap: scegli il generatore successivo in base al valore. listOf(size): prima genera la lunghezza, poi la lista. union: lancia una moneta e usa uno dei due generatori.

given · using · summon (Exercise 12)

def listOfN[A: Gen](n: Int): Gen[List[A]] =
  summon[Gen[A]].listOfN(n)

def listOfN__ [A](n: Int)(using genA: Gen[A]): Gen[List[A]] =
  genA.listOfN(n)

def listOf[A: Gen](using genInt: Gen[Int]): Gen[List[A]] =
  summon[Gen[A]].listOf(genInt)

Cosa fanno. A: Gen significa "esiste un Gen[A] nel contesto". summon[Gen[A]] lo prende. Le due scritture di listOfN sono equivalenti: la seconda dà un nome al generatore.

Result · Prop · forAll · && · ||

enum Result:
  case Passed
  case Falsified(failure: FailedCase, successes: SuccessCount)

  def isFalsified: Boolean = this match
    case Passed => false
    case Falsified(_, _) => true

opaque type Prop = (MaxSize, TestCases, RNG) => Result

def forAll[A](as: Gen[A])(f: A => Boolean): Prop =
  (max, n, rng) =>
    randomLazyList(as)(rng)
      .zip(LazyList.from(0))
      .take(n)
      .map { (a, i) =>
             try if f(a) then Passed else Falsified(a.toString, i)
             catch case e: Exception => Falsified(buildMsg(a, e), i) }
      .find(_.isFalsified)
      .getOrElse(Passed)

extension (self: Prop)
  infix def && (that: Prop): Prop = (maxSize, tcs, rng) =>
    val first = self(maxSize, tcs, rng)
    if first.isFalsified then first else that(maxSize, tcs, rng)

  infix def || (that: Prop): Prop = (maxSize, tcs, rng) =>
    val first = self(maxSize, tcs, rng)
    if first.isFalsified then that(maxSize, tcs, rng) else first

Cosa fanno. forAll: genera una lista pigra di valori casuali, li numera, ne prende n, prova f su ognuno (un'eccezione conta come fallimento) e find si ferma al primo fallito. Nessun fallito → Passed. &&: se la prima fallisce restituisce quel fallimento, altrimenti prova la seconda. ||: se la prima fallisce prova la seconda.

SGen · unsized · list · Prop.forAll con taglia

opaque type SGen[+A] = Int => Gen[A]

extension [A](self: Gen[A])
  def unsized: SGen[A] = n => self
  def list: SGen[List[A]] = n => self.listOfN(n)

val nonEmptyList: SGen[List[Int]] =
  (n: Int) => Gen.choose(-100, 100).listOfN(n max 1)

Cosa fanno. SGen è una funzione "taglia → generatore". unsized ignora la taglia. list usa la taglia come lunghezza. nonEmptyList usa n max 1 per non generare mai la lista vuota. SGen.Prop.forAll prova taglie 0, 1, 2… fino a MaxSize (piccoli prima: il controesempio trovato è già piccolo).
