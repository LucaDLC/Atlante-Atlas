Domande in stile esame

Scritte per l'atlante sul modello degli esercizi del corso: non sono prove ufficiali. Ogni soluzione è stata compilata con Scala 3.8.4.

1 · Contare con un fold

Implementa, senza ricorsione esplicita, una funzione che conta gli elementi di una lista che soddisfano p.

def count[A](l: List[A])(p: A => Boolean): Int = ???
Mostra la soluzione
def count[A](l: List[A])(p: A => Boolean): Int =
  l.foldLeft(0)((acc, a) => if p(a) then acc + 1 else acc)

z = 0 (lista vuota: zero elementi). Il passo aggiunge 1 solo se p(a). count(List(1,2,3,4,5))(_ % 2 == 1) dà 3.

2 · L'ultimo elemento, forse

Implementa lastOption con un fold, senza pattern matching.

def lastOption[A](l: List[A]): Option[A] = ???
Mostra la soluzione
def lastOption[A](l: List[A]): Option[A] =
  l.foldLeft[Option[A]](None)((_, a) => Some(a))

Ogni passo butta l'accumulatore e tiene l'elemento attuale: alla fine resta l'ultimo. Il tipo [Option[A]] serve perché None da solo avrebbe tipo None.type. Risultati: Some(9) per List(7, 8, 9), None per la lista vuota.

3 · Filtrare e trasformare insieme

Data una funzione che può fallire, tieni solo i risultati riusciti.

def filterMap[A, B](l: List[A])(f: A => Option[B]): List[B] = ???
// filterMap(List("1", "x", "3"))(_.toIntOption) == List(1, 3)
Mostra la soluzione
def filterMap[A, B](l: List[A])(f: A => Option[B]): List[B] =
  l.foldRight(List.empty[B])((a, acc) => f(a).map(_ :: acc).getOrElse(acc))

foldRight mantiene l'ordine. Se f(a) è Some(b), map lo mette davanti al resto; se è None, getOrElse restituisce il resto invariato.

4 · Profondità di un albero

Usando fold sugli alberi della settimana 3, calcola la profondità: una foglia ha profondità 0, un ramo 1 + la profondità del figlio più profondo.

Mostra la soluzione
def depth[A](t: Tree[A]): Int =
  fold[A, Int](t)((l, r) => 1 + (l max r))(_ => 0)

g per le foglie: 0, ignorando il valore. f per i rami: 1 più il massimo dei due. depth(Branch(Branch(Leaf(1), Leaf(5)), Leaf(3))) dà 2.

5 · forAll su Option senza pattern matching

Implementa forAll (vero se l'Option è vuoto o se il valore soddisfa p) usando solo map e getOrElse.

Mostra la soluzione
def forAll[A](o: Option[A])(p: A => Boolean): Boolean =
  o.map(p).getOrElse(true)

map(p) trasforma Some(a) in Some(p(a)). Su None, "per tutti gli elementi" è vero a vuoto: default true.

6 · Cosa stampa?

def twice(x: => Int): Int = x + x
def twiceLazy(x: => Int): Int =
  lazy val y = x
  y + y

println(twice({ println("hi"); 1 }))
println(twiceLazy({ println("hi"); 1 }))
Mostra la soluzione
hi
hi
2
hi
2

twice: x è by-name e compare due volte, quindi il blocco viene eseguito due volte. twiceLazy: la lazy val lo calcola una volta e poi lo ricorda.

7 · Una lista infinita con unfold

Implementa iterate: la LazyList a, f(a), f(f(a)), …, usando unfold.

Mostra la soluzione
def iterate[A](a: A)(f: A => A): LazyList[A] =
  unfold(a)(x => Some((x, f(x))))

Lo stato è il valore attuale: lo emetto e il nuovo stato è f(x). Mai None: la lista è infinita. iterate(1)(_ * 3).take(4).toList dà List(1, 3, 9, 27).

8 · Varianza

Con class Cat extends Animal: compila val o: Option[Animal] = Some(Cat())? E val a: Array[Animal] = cats se cats: Array[Cat]? Perché?

Mostra la soluzione

La prima sì: Option[+A] è covariante, quindi Option[Cat] <: Option[Animal]. La seconda no: gli array sono mutabili e in Scala invarianti (Found: Array[Cat], Required: Array[Animal]). Se lo fossero, potresti scrivere un Dog in un array di Cat.

9 · Domanda aperta, in inglese

Why is foldLeft on a strict List tail-recursive while foldRight is not? When would you still prefer foldRight?

Mostra una risposta modello

"In foldLeft the combining function is applied before the recursive call, so the call is the last thing the function does and the compiler can turn it into a loop with constant stack space. foldRight must first compute the result for the tail and only then apply f to the head, so each element leaves a pending call on the stack. I would still use foldRight when the result must preserve the order of the list, for example when building a list with Cons, and on lazy lists, where f may return without forcing the rest and the fold can stop early."
