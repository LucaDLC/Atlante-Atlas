Esameanalisi delle prove

Le famiglie di domande

Le 78 domande delle prove 2019–2025 si riducono a dodici famiglie. Per ognuna: cosa descrive il testo, l'idea, lo schema di codice, una figura che lo esegue passo per passo, le trappole e in quali anni è comparsa.

0 · Le famiglie e dove cadono i punti

Ogni famiglia è un modo diverso di ragionare. Riconoscerla dal testo è metà dell'esame: dopo, la risposta ha quasi sempre una forma standard. La colonna "anni" dice in quante delle 7 prove la famiglia è comparsa.

A · Funzioni, curry, funzioni di ordine superiore

S1 · compare nel 2024 (4 domande su 12) · si risolve seguendo i tipi

Cosa descrive il testo

Una firma con tante frecce: "trasforma goodPairs in una funzione curried", "scrivi curriedNested". Non c'è un problema da risolvere: c'è un puzzle di tipi.

Idea

Le uniche cose che hai in mano sono i parametri e le funzioni date. L'implementazione è quasi sempre forzata dai tipi: scrivi il tipo che devi produrre, apri una lambda per ogni freccia, e chiama la funzione data con i soli valori disponibili.

Schema

def curry[A, B, C](f: (A, B) => C): A => (B => C) = a => b => f(a, b)
def compose[A, B, C](f: B => C, g: A => B): A => C = a => f(g(a))

// 2024 Q1–Q4 (compilati con Scala 3.8.4)
def goodPairs[A](l: List[A], good: (A, A) => Boolean): Boolean =
  l.zip(l.drop(1)).forall(good.tupled)
def goodPairsCurried[A]: List[A] => ((A, A) => Boolean) => Boolean =
  goodPairs[A].curried
def curriedNested[A, B, C, D](f: ((A, B) => C) => D): (A => B => C) => D =
  f.compose(Function.uncurried)
def goodPairsHotCurry[A]: List[A] => (A => A => Boolean) => Boolean =
  goodPairs[A].curried.andThen(curriedNested)

Trappole

  • goodPairs[A] è un metodo: viene trasformato in funzione (eta-espansione) prima di .curried. Se non usi curried, perdi punti.
  • f.curried su curriedNested è sbagliato: f ha un solo argomento. Confondere compose (f dopo g) con andThen (g poi f).
  • Liste vuote e di un elemento in goodPairs: true. sliding(2) con case List(a,b) non è esaustivo.

B · Liste, tipi algebrici, fold

S2 · 2019 Q1, 2021 Q1, 2024 Q1 · è il "riscaldamento" di molte prove

Cosa descrive il testo

Una funzione su liste o su un enum da scrivere "con una funzione di ordine superiore", "senza ricorsione" o "con un fold". Oppure un pattern matching su un tipo semplice (winner, hello).

Idea

Scegli lo strumento nell'ordine che il corso premia: funzione dedicata (map, filter, forall, zip) → fold → ricorsione esplicita. Un match su coppia gestisce due valori insieme.

Schema

// 2019 Q1: match sulla coppia, il caso "_" prende solo i pareggi
def winner(a: Move, b: Move): Result = (a, b) match
  case (Rock, Scissors) | (Paper, Rock) | (Scissors, Paper) => Some(P1)
  case (Scissors, Rock) | (Rock, Paper) | (Paper, Scissors) => Some(P2)
  case _ => None

// 2023 Q1: fold con la stessa semantica della ricorsione
l.foldLeft(0)((z, n) => if n % 2 == 1 then z + 1 else z)

Trappole

  • Nel 2023 la versione "elegante" z + (n % 2) è sbagliata: per i negativi -3 % 2 == -1. Tieni n % 2 == 1.
  • Una ricorsione "a mano" dove il testo dice choose the right higher order function prende meno punti.
  • Qualifica i casi di un enum (Printable.Triangle) o importali.

C · Option, Either, for

S3 · 2020 Q1, 2021 Q2, 2022 Q1–Q2 · funzioni totali, errori come valori

Cosa descrive il testo

"Scrivi la versione pura, nella monade Option" (smashOption), "restituisci None se c'è un'eccezione" (SafeTotal), "l'ultimo errore" (sequence per Either).

Idea

Il fallimento diventa un valore nel tipo (Option, Either). Si concatena con flatMap o con for: se un passo è None/Left tutto il resto è saltato. Scrivi sempre il tipo di ritorno quando il testo lo chiede.

Schema (compilati con Scala 3.8.4)

def smashOption[A](l: List[A]): Option[List[(A, A)]] = l match
  case Nil => Some(Nil)
  case h1 :: h2 :: tl => for s <- smashOption(tl) yield (h1, h2) :: s
  case _ => None                          // lunghezza dispari

def sequence[Err, A](as: List[Either[Err, A]]): Either[Err, List[A]] =
  as.foldRight[Either[Err, List[A]]](Right(Nil)): (ea, eas) =>
    for xs <- eas; a <- ea yield a :: xs   // eas PRIMA: vince l'ultimo errore

def safeTotal[A, B](f: A => B): A => Option[B] =
  a => try Some(f(a)) catch case _: Throwable => None

Trappole

  • Ordine degli errori: foldLeft o ricorsione in coda danno il primo; foldRight con eas valutato per primo dà l'ultimo.
  • Tradurre in Option perde l'errore. SafeTotal restituisce una funzione A => Option[B], non un Option.
  • Propaga sempre il None: non lanciare eccezioni dove il testo chiede il valore puro.

D · LazyList e pigrizia

S4 · 2019, 2020, 2021, 2022, 2023, 2025 · codice e spiegazione in inglese

Cosa descrive il testo

Una lista infinita o potenzialmente lunga ("stream of results", "primes", "running RMSE") e una funzione da scrivere senza forzarla. Spesso segue una domanda in inglese: "perché size(s) >= 10 è un problema?", "cosa succederebbe se questi operatori fossero stretti?".

Idea

Compone solo operazioni pigre (map, filter, zip, take, zipWith, unfold) e forza alla fine, dopo un take. toList su una lista infinita non termina.

Schema (compilati su LazyList della libreria standard)

// 2019 Q4: take PRIMA di filter e toList, divisione in Double
results.take(500).filter(_ == Some(P1)).toList.size / 500.0

// 2025 Q1: RMSE su liste finite, senza ricorsione
val (sum, n) = gs.zip(ps).foldLeft((0.0, 0)):
  case ((s, k), (g, p)) => (s + (g - p) * (g - p), k + 1)
math.sqrt(sum / n)

// 2025 Q3: running RMSE su liste infinite: lo stato è (code, somma, n)
def runningRMSE(gs: LazyList[Double], ps: LazyList[Double]): LazyList[Double] =
  LazyList.unfold((gs, ps, 0.0, 0)):
    case (g #:: gt, p #:: pt, s, n) =>
      val s1 = s + (g - p) * (g - p)
      Some((math.sqrt(s1 / (n + 1)), (gt, pt, s1, n + 1)))
    case _ => None

// 2023 Q1 / 2021 Q8: take è non stretta
def checkIfLongerEqThan[A](s: LazyList[A])(n: Int): Boolean = size(s.take(n)) == n

Verificato: runningRMSE(LazyList(0.8,1.0,2.2), LazyList(1.0,1.0,2.0)) dà 0.2, 0.141…, 0.163…, come nel testo del 2025.

Trappole

  • toList, size, foldLeft sono stretti: su una lista infinita non terminano. Metti sempre un take prima.
  • Divisione intera: / 500 invece di / 500.0. Ricorsione quando il testo dice "do not use recursion".
  • Ricalcolare rmse su ogni prefisso è O(n²): "running" vuol dire portarsi lo stato (somma e n).
  • Con -Xfatal-warnings (2025) un match non esaustivo non compila: aggiungi case _ =>.

"size traverses the whole list until Empty, so on an infinite list it never terminates, and on a long list it does useless work, because after 10 elements the answer is already known."

"If filter, zip and cons were strict, primeFrom would try to build all the primes, which are infinitely many, and run out of time and memory before primesApart could return its first pair."

"Without liveness, filter keeps looking for the next success and never finds it: the program hangs when the head is forced. As long as nothing is forced the bug stays hidden."

E · State e numeri casuali

S5 · 2021 Q4 · è la base di Gen (F) e dei parser (G)

Cosa descrive il testo

"Genera una tripla casuale (a, b, x) con a ≤ x ≤ b usando Rand" (riid). Si devono combinare più valori casuali senza toccare lo stato a mano.

Idea

Ogni passo prende lo stato e restituisce (valore, stato nuovo). Un for su State fa passare lo stato al posto tuo: x <- m significa "esegui m, prendi il valore, usa lo stato aggiornato per il passo dopo".

Schema

lazy val riid: Rand[(Int, Int, Double)] = for
  a <- State(RNG.int)
  b <- State(RNG.int)
  x <- State(RNG.double)
yield
  val l = a min b
  val r = a max b
  (l, r, l + (r.toDouble - l) * x)    // r.toDouble - l: evita l'overflow di r - l

Trappole

  • Ordina a e b: a caso può essere a > b. Tre valori scollegati sono una soluzione debole.
  • Niente nextInt a mano e niente API imperative (penalizzato). RNG.double è in [0, 1).
  • La sottrazione r - l tra Int può andare in overflow prima di .toDouble.

F · Property-based testing

S6–S7 · compare in tutte e 7 le prove · è l'investimento più sicuro

Cosa descrive il testo

"Scrivi una proprietà che dice…", "dai un Arbitrary per…", "scrivi un generatore di…", "scrivi le due leggi come Prop". Si tratta quasi sempre di ScalaCheck standard (forAll, Gen, Arbitrary), non del Gen del libro.

Idea

Una proprietà è una frase "per ogni input che soddisfa X, vale Y". Il difficile è tradurre la frase e scegliere il generatore giusto. Quando serve un tipo con vincoli, componi i generatori con for.

Schema

// 2021 Q9: precondizione con ==>
forAll { (s: LazyList[Int]) => (s != LazyList.Empty) ==> checkIfLongerEqThan(s.append(s))(2) }

// 2022 Q5: generatore ristretto ai pari + take su lista infinita
forAll(Gen.choose(2, 20).suchThat(_ % 2 == 0)) { n =>
  primesApart(n).take(5).forAll { (a, b) => b - a == n } }

// 2023 Q8: due forAll annidati (tabella, poi posizione)
forAllNoShrink(qGen(2, 3)) { q =>
  forAll(Gen.choose(0, 1), Gen.choose(0, 2)) { (s, a) => update(q, s, a)(q(s)(a), 0.0) ?= q } }

// 2024 Q7: Arbitrary come parametro implicito, ritenta se entrambe None
def genEither[A, B](using Arbitrary[Option[A]], Arbitrary[Option[B]]): Gen[Either[A, B]] = ...

// 2025 Q2: given generico per coppie di liste di EGUALE lunghezza
given [A: Arbitrary]: Arbitrary[(LazyList[A], LazyList[A])] = Arbitrary(for
  n <- Gen.choose(1, 50)
  xs <- Gen.listOfN(n, arbitrary[A])
  ys <- Gen.listOfN(n, arbitrary[A])
yield (LazyList(xs*), LazyList(ys*)))

Trappole

  • Un solo esempio non è PBT. Dimentichi la precondizione ==>. whenever scarta molti casi: meglio una proprietà combinata.
  • given o implicit def con context bound [A: Arbitrary]: la versione generica vale i punti pieni, quella per Int no.
  • Gen.choose ha estremi inclusi. Annidato dentro una lista infinita usa take.
  • Se entrambe le opzioni sono None, .get crasha: devi riprovare.

G · Parser combinators

S8 · 2020, 2023, 2024, 2025 · si incollano parser piccoli

Cosa descrive il testo

Una grammatica a parole ("righe di interi separati da virgole", "alberi (42()())") e un parser da scrivere. Spesso un parser è già dato e il compito è riusarlo (2023 Q2–Q3).

Idea

Una riga di grammatica diventa una riga di codice. Operatori: ** coppia, |* scarta il sinistro, *| scarta il destro, | alternativa, .? zero o una, .* zero o più, .map trasforma. Se un parser esiste già, non riscriverlo: parser.map(...).

Schema

// 2023 Q2, Q3: riusa il parser dato
lazy val longestLine: Parser[Int] = parser.map(l => l.map(_.size).max)
lazy val allLinesTheSame: Parser[Boolean] = parser.map(l => l.map(_.size).toSet.size == 1)

// 2020 Q9: CSV di interi (il caso del file vuoto e dell'ultimo \n)
val row = (WS.? |* INT ** ("," |* WS.? |* INT).* *| WS.?).map((h, t) => h :: t)
val csv = (row ** (NL |* row).* *| NL.?).map((h, t) => h :: t)
lazy val parser = csv.?.map(_.getOrElse(Nil))

// 2025 Q9: alberi, grammatica LL(1): T -> '(' (B | L), B -> INT T T ')', L -> ')'
lazy val parser: Parser[Tree[Int]] = char('(') |* (branch | leaf)
lazy val branch = (int ** parser ** parser *| char(')')).map { case ((v, l), r) => Branch(v, l, r) }
lazy val leaf   = char(')').map(_ => Leaf)

Trappole

  • I parser non tornano indietro dopo aver consumato input: se due alternative iniziano con lo stesso carattere, scrivi la grammatica in forma LL(1) (2025 Q9).
  • Parser ricorsivi o che si richiamano a vicenda: lazy val, altrimenti NPE/StackOverflow.
  • File vuoto (.? + getOrElse(Nil)), \n finale opzionale (NL.?), spazi attorno ai numeri.
  • 2024 Q8: lo scheletro dice Parser[Int], il testo dice Parser[Option[Int]]: segui il testo. Su Parsers astratto non esiste regex: costruisci con char, |, many1.

H · Monoid, Functor, Monad e type class

S9 · 2019, 2020, 2021, 2024, 2025 · given, using, context bound

Cosa descrive il testo

"Dai l'evidenza che Tree è un Functor", "scrivi sequence/loop per una monade qualunque", "la firma deve richiedere che A sia Splittable", "implementa Monad[Dist]".

Idea

Un'istanza è un given con i metodi richiesti. Una funzione che pretende un'istanza la chiede con un context bound [A: Splittable] (cioè (using Splittable[A])). Per la monade scrivi solo unit e flatMap; map arriva gratis.

Schema

// 2020 Q2 (compilato): la firma "esige" l'istanza; il dispari va splittato, non scartato
def smash[A: Splittable](l: List[A]): List[(A, A)] = l match
  case Nil => Nil
  case List(h) => summon[Splittable[A]].split(h) :: Nil
  case h1 :: h2 :: tl => (h1, h2) :: smash(tl)

// 2025 Q7: Functor di un albero con il valore nel nodo
given Functor[Tree]:
  extension [A](t: Tree[A])
    def map[B](f: A => B): Tree[B] = t match
      case Leaf => Leaf
      case Branch(v, l, r) => Branch(f(v), l.map(f), r.map(f))

// 2021 Q13: il "while" come ricorsione nella monade (unit rimette body(a) dentro)
def loop[A, M[_]: Monad](initial: M[A])(body: A => A)(p: A => Boolean): M[A] =
  initial.flatMap { a => if p(a) then loop(summon[Monad[M]].unit(body(a)))(body)(p) else initial }

// 2024 Q5, Q6: Dist è una monade; multUni richiede l'istanza nella firma
given distMonad: Monad[Dist]:
  def unit[A](a: => A) = Dirac(a)
  extension [A](fa: Dist[A]) override def flatMap[B](f: A => Dist[B]) = fa.flatMap(f)
def multUni[T](n: Int, values: T*)(using Monad[Dist]): Dist[List[T]] =
  summon[Monad[Dist]].sequence(List.fill(n)(Pigaro.uniform(values*)))

Trappole

  • Dimenticare il context bound o using nella firma quando il testo dice "the signature must enforce…".
  • unit di Dist è Dirac (valore certo), non uniform. unit è by-name. override sull'extension flatMap.
  • Nel loop: p è la condizione per continuare, e body(a) va rimesso nella monade con unit.
  • 2021 Q3: la firma sequence[Err, A, F[_]: Foldable] ha ritorno Either[Err, F[A]].
  • L'istanza given va in un posto visibile alle funzioni che la usano (2025 Q7 → Q8).

I · Sistema di tipi: varianza, tipi indicizzati, extension

S3, S9 · 2020 Q7–Q8, 2022 Q6–Q11 (circa metà del 2022)

Cosa descrive il testo

Un tipo costruito apposta (SizedList[+A, S] con Inc[S] che conta gli elementi, Box, Better[T]). Domande: "annota il tipo di l1", "scrivi third che si può chiamare solo con almeno 3 elementi", "marca la chiamata polimorficamente ricorsiva", "invariante, covariante o contravariante?".

Idea

Qui il tipo è il programma: conta i Inc. Una funzione che accetta solo liste di almeno 3 elementi lo dichiara nella firma con tre Inc. Una ricorsione è polimorfa quando la chiamata ricorsiva usa parametri di tipo diversi da quelli esterni.

Schema (compilato con Scala 3.8.4)

case class Inc[A]()
sealed trait SizedList[+A, S]
case object Empty extends SizedList[Nothing, Null]
case class Cons[A, S](hd: A, tl: SizedList[A, S]) extends SizedList[A, Inc[S]]

val l2: SizedList[Int, Inc[Inc[Inc[Null]]]] = Cons(3, Cons(1, Cons(4, Empty)))

def third[A, S](l: SizedList[A, Inc[Inc[Inc[S]]]]): A =
  head(tail(tail[A, Inc[Inc[S]]](l)))        // la lista deve avere 3 Inc nel TIPO

// 2022 Q7: extension infissa che richiede l'istanza
extension [T: Better](self: T)
  infix def betterThan(that: T): Boolean = summon[Better[T]].leftBetter(self, that)

Varianza: la risposta tipo del 2022 Q11

  • SizedList[+A, S]: covariante in A, invariante in S (nessun segno = invariante).
  • Esempio corretto: SizedList[Nothing, Inc[Null]] <: SizedList[Int, Inc[Null]].
  • Sbagliato (viola solo A): SizedList[Int, Null] <: SizedList[Nothing, Null]. Sbagliato (viola solo S): SizedList[Int, Null] <: SizedList[Int, Inc[Inc[Null]]].

Trappole

  • Null, non Nothing, per la lista vuota. Esplicita i parametri di tail per aiutare l'inferenza.
  • Ogni esempio sbagliato deve violare un solo parametro. infix serve in Scala 3 per scrivere a betterThan b.
  • 2020 Q8 (Box[+A], Pack(hd: A, tl: Box[List[A]])): h :: flattenBox[List[A]](t).flatten, con l'annotazione [List[A]].

J · Programmazione probabilistica

S10 · 2019 (Figaro), 2023 (Pigaro); nel 2024 Dist compare come monade (H) · nel 2026 la libreria è Probula

Cosa descrive il testo

Un gioco o un esperimento ("Alice sceglie a caso, Bob mai Scissors") e: "costruisci le distribuzioni", "componi la partita", "stima con 10000 campioni la probabilità che Alice vinca".

Idea

Una distribuzione è una monade: map/flatMap/map2 compongono modelli, sample(N) pesca N esiti, .pr(evento) ne dà la frequenza. Variabili indipendenti hanno nomi distinti.

Schema (2023, Pigaro) e la stessa idea in Probula (2026)

// 2023 Q4–Q6
val Alice = Pigaro.uniform("alice")(Rock, Paper, Scissors)
val Bob   = Pigaro.uniform("bob")(Rock, Paper)               // 0.5 e 0.5, mai Scissors
def game(p1: Strategy, p2: Strategy): Dist[Result] = p1.map2(p2)(winner)
lazy val aliceFraction: Double = game(Alice, Bob).sample(10000).pr(Some(P1))

// 2026, esercizio 10 (Probula): urna con n nere e 1 rossa
def pick(n: Int): Dist[Ball] = Probula.bernoulli[Ball]((1.0 / (n + 1)).pr, Red, Black)
def move(player: Player, n: Int): Dist[Player] =
  pick(n).flatMap:
    case Red   => Dirac(player)
    case Black => move(next(player), n - 1)

Trappole

  • Il primo argomento di uniform è il nome della variabile: due strategie con lo stesso nome risultano correlate.
  • L'evento è Some(P1), non P1. Serve il given rng in scope. Non chiamare winner direttamente su una Dist: usa map/map2.
  • Probula: condition vuole una funzione sulla coppia intera (_._2 == Paula), non due parametri.

K · Lenses

S14 · 2019 Q13–Q15, 2023 Q9, 2025 Q6 · una lente è un getter e un setter con tre leggi

Cosa descrive il testo

"Scrivi una lente tra Gen e Arbitrary", "riscrivi update usando la lente", "questa lente è totale o parziale? Lens o Optional? Quali leggi soddisfa?".

Idea

Una Lens[S, A] ha get: S => A e replace: A => S => S. Se il valore può non esistere (indice fuori range) è un Optional, con getOption. Le leggi: Get-Put (rimettere ciò che leggi non cambia nulla), Put-Get (leggi ciò che hai scritto), Put-Put (la seconda scrittura vince).

Schema

// 2025 Q6: Gen e Arbitrary sono "la stessa cosa" con un involucro
def lens[A]: Lens[Arbitrary[A], Gen[A]] =
  Lens[Arbitrary[A], Gen[A]](_.arbitrary)(g => _ => Arbitrary(g))
// Put-Get: sì.  Get-Put: sì.  Put-Put: sì (replace ignora il vecchio valore)

// 2023 Q9: Optional, quindi getOption e replace(valore)(struttura)
val qsa = lens(s, a).getOption(q).get
val value = (1 - alpha) * qsa + alpha * (reward + gamma * estimate)
lens(s, a).replace(value)(q)

Trappole

  • Un'Optional non è una Lens: getOption restituisce Option. Rispondere "Lens" per un valore parziale è l'errore del 2019 Q13.
  • Dai l'argomento di 1–2 righe per ogni legge, non solo Sì/No.
  • Ordine di replace: prima il valore, poi la struttura.

L · Semantica e interpreti

S11 · mai chiesta nelle prove 2019–2025 · nuova nel 2026, quindi poco prevedibile

Cosa descrive il testo (negli esercizi del corso)

Un valutatore per termini Cons(n) e Div(l, r) con un effetto: eccezioni, stato (contare le divisioni), output (una traccia). Poi riscriverlo con unit/flatMap e con for.

Idea

La struttura dell'interprete (ricorsione sull'albero) è sempre la stessa. Cambia solo il tipo del risultato e il caso speciale: se il risultato è una monade, cambiare effetto vuol dire cambiare monade, non riscrivere l'interprete.

Schema (dalle slide)

enum Term:
  case Cons(value: Int)
  case Div(left: Term, right: Term)

enum M[+A]:                        // eccezioni
  case Raise(e: String) extends M[Nothing]
  case Return(a: A)

def evalForYield(t: Term): M[Int] = t match
  case Cons(n) => unit(n)
  case Div(l, r) => for
    lv <- evalForYield(l)
    rv <- evalForYield(r)
    res <- if rv == 0 then Raise("Division by zero") else unit(lv / rv)
  yield res
