Dizionario dei pezzi, per tipo

Qui sotto c'è ogni pezzo con cui sono scritti i blocchi di codice, dal più piccolo al più grande. Per ogni pezzo: cosa vuol dire, cosa chiede tra le parentesi e un esempio. I risultati dopo la freccia → sono stati eseguiti in Scala 3.8.4 (sulle liste standard, che si comportano come le tue). Poi, in fondo, tre righe di codice vere smontate pezzo per pezzo.

Segui l'ordine: simboli → parole chiave → tipi → costruttori → metodi per tipo → come si incastrano.

Regole di stile (valgono su ogni risposta)

  • Vietati salvo richiesta esplicita: var, assegnamenti, cicli (while, for … do), return, eccezioni, println e altri effetti, Any/Object.
  • Scala di stile: variabili < val · eccezioni < Option/Either · ricorsione in coda < ricorsione semplice < fold < funzioni dedicate · if < pattern matching.
  • Dalla settimana 2: ricorsione esplicita solo per iterazioni non standard; altrimenti HOF; fold solo se le altre HOF non bastano.
  • Eccezioni richieste dal testo (tail, drop, init): lanciarle, non restituire Nil.
  • Dettagli e punteggi: Regole e divieti. Messaggi del compilatore: Errori del compilatore.

Frasi pronte in inglese

  • toList fails on infinite lists because it is strict: it keeps forcing the tail until it reaches Empty, and an infinite list never reaches it.
  • naturals.take(1000000000).drop(41).take(10).toList terminates because take and drop are lazy: only the elements that toList finally demands are computed, here about 51.
  • naturals.forAll(_ >= 0) never terminates because the predicate is always true, so forAll never finds a counterexample to stop at. exists stops at the first witness.
  • foldRight on List is not stack-safe: after the recursive call there is still f to apply, so every element keeps a stack frame. foldLeft is tail recursive.
  • The second argument is by-name, so it is evaluated only when needed. Otherwise many would call itself forever before reading a single character.
  • listOfN is an extension method because Gen is an opaque type, not a class: there is no body in which to define a member.
  • The laws are written only with the abstract operations of the trait, so they hold for every implementation.
  • A pure function always returns the same output for the same input and has no side effects, so a call can be replaced by its value (referential transparency).
  • Associativity lets us group the combinations in any way, so a fold with a monoid can be split and combined in parallel.
  • I use Option instead of an exception because the possible failure is visible in the type, and the caller is forced to handle it.
