Pezzi atomici: ogni simbolo, ogni metodo

Qui sotto c'è ogni pezzo con cui sono scritti i blocchi di codice, dal più piccolo al più grande. Per ogni pezzo: cosa vuol dire, cosa chiede tra le parentesi e un esempio. I risultati dopo la freccia → sono stati eseguiti in Scala 3.8.4 (sulle liste standard, che si comportano come le tue). Poi, in fondo, tre righe di codice vere smontate pezzo per pezzo.

Segui l'ordine: simboli → parole chiave → tipi → costruttori → metodi per tipo → come si incastrano.

12 · Come si incastrano: tre righe vere, pezzo per pezzo

Premi Avanti: a ogni passo si accende un solo pezzo. Colori: dato blu = ciò che entra, ora arancio = il pezzo che guardi, due viola = un secondo ruolo, ok verde = il risultato.

S1 · Funzioni, ricorsione, funzioni come valori

Nozioni

  • Funzione pura: stesso input, stesso output, nessun effetto (niente println, var, eccezioni, I/O). Si può sostituire la chiamata con il suo valore (referential transparency).
  • val non cambia mai. def è una funzione, valutata a ogni chiamata. if e match sono espressioni: restituiscono un valore, quindi niente return.
  • Tipo di una funzione: A => B. Due argomenti: (A, B) => C. Curried: A => B => C, che si legge A => (B => C) (la freccia associa a destra).
  • Ricorsione in coda (tail recursion): la chiamata ricorsiva è l'ultima cosa che la funzione fa. Il compilatore la trasforma in un ciclo, pila costante. @annotation.tailrec dà errore di compilazione se non è davvero in coda.
  • Ricorsione semplice (1 + f(n-1)): dopo il ritorno resta da fare il +1, quindi ogni livello occupa un frame di pila → StackOverflowError su input lunghi.
  • Funzione di ordine superiore (HOF): prende o restituisce funzioni. Polimorfismo: [A] dopo il nome, la funzione vale per ogni tipo.
  • Quando i tipi sono generici l'implementazione è spesso forzata dai tipi (curry, compose): se sei bloccato, segui i tipi.
  • Int in overflow non dà errore: è aritmetica modulo 232.

fib · Fibonacci in tempo lineare

    else bonacci(n-1, next, next+curr)

Cosa fa. Porta avanti solo gli ultimi due numeri (curr, next). A ogni passo scala n e sposta la finestra. Numerazione dal 1: fib(1)=0, fib(2)=1, fib(3)=1, fib(5)=3. La versione ovvia fib(n-1)+fib(n-2) costa O(φn); questa O(n), pila costante.

Cosa fa. Controlla solo le coppie adiacenti: basta se ordered è transitiva. Appena una coppia è sbagliata risponde false. Array vuoto o con un elemento: nessuna coppia da violare, quindi true. Il criterio d'ordine è un parametro (HOF).

curry · uncurry · compose

def curry[A, B, C](f: (A, B) => C): A => (B => C) =
  a => b => f(a, b)

def uncurry[A, B, C](f: A => B => C): (A, B) => C =
  (a, b) => f(a)(b)

  a => f(g(a))

Cosa fanno. curry trasforma una funzione a due argomenti in una che ne prende uno alla volta (applicazione parziale: fisso a, resto con una funzione di b). uncurry è l'inversa: uncurry(curry(f)) == f. compose(f, g) = "f dopo g": prima g, poi f. È associativa e ha identity come neutro.

S2 · Tipi algebrici, liste, fold

Nozioni

  • ADT (algebraic data type) = somma di prodotti. Somma: i case di un enum (o l'uno o l'altro). Prodotto: i campi di un case (e questo e quello).
  • enum List[+A]: case Nil; case Cons(head: A, tail: List[A]). +A = covariante: List[Cat] è anche List[Animal]. Nil è List[Nothing], quindi serve per ogni tipo.
  • Pattern matching: i case sono provati dall'alto in basso, vince il primo che combacia (un caso generale messo prima oscura quelli specifici). _ = non mi interessa. Una variabile nel pattern lega il valore. Il compilatore controlla l'esaustività.
  • Condivisione: i dati sono immutabili, quindi tail, drop, dropWhile restituiscono un pezzo della stessa lista, senza copiare (eq è vero). Costo: tail O(1), drop(n) O(n), append(l1,l2) O(|l1|), init O(n) (ricostruisce tutto).
  • Quando una funzione non ha risposta sensata (tail(Nil), init(Nil)) il corso chiede NoSuchElementException; quando ce l'ha (dropWhile su Nil) restituisce il valore vuoto.
  • foldRight: f(a1, f(a2, f(a3, z))). Associa a destra, non è in coda: pila O(n). foldLeft: f(f(f(z, a1), a2), a3). Associa a sinistra, è in coda: è il "ciclo for" funzionale.
  • Il valore iniziale z è il neutro dell'operazione: 0 per +, 1 per *, Nil per append, identity per la composizione.
  • foldLeft con Cons costruisce la lista al contrario (reverse); foldRight con Cons la ricostruisce nello stesso ordine (map, filter).
  • flatMap contiene map (f restituisce un singoletto) e filter (f restituisce Nil o un singoletto).
  • Ordine di stile (settimana 2 in poi): API dedicata (map, filter, exists…) → fold → ricorsione esplicita solo se l'iterazione è insolita.

List, apply, head, append, foldRight, map (dati dal corso)

enum List[+A]:
  case Nil
  case Cons(head: A, tail: List[A])

object List:
  def apply[A] (as: A*): List[A] =
    if as.isEmpty then Nil
    else Cons(as.head, apply(as.tail*))

  def append[A] (l1: List[A], l2: List[A]): List[A] = l1 match
    case Nil => l2
    case Cons(h, t) => Cons(h, append(t, l2))

  def foldRight[A, B] (l: List[A], z: B, f: (A, B) => B): B = l match
    case Nil => z
    case Cons(a, as) => f(a, foldRight(as, z, f))

  def map[A, B] (l: List[A], f: A => B): List[B] =
    foldRight[A, List[B]] (l, Nil, (a, z) => Cons(f(a), z))

Cosa fanno. apply permette List(1,2,3) (A* = numero variabile di argomenti, as.tail* li ripassa uno a uno). append ricopia solo l1 e aggancia l2 in fondo. map è un foldRight che rimette f(a) davanti al risultato del resto.

tail · drop · dropWhile · init

def tail[A] (l: List[A]): List[A] = l match
  case Nil => throw NoSuchElementException()
  case Cons(_,t) => t

def drop[A] (l: List[A], n: Int): List[A] =
  if n<=0 then l
  else l match
    case Nil => throw NoSuchElementException()
    case Cons(_,t) => drop(t, n-1)

def dropWhile[A] (l: List[A], p: A => Boolean): List[A] = l match
  case Nil => Nil
  case Cons(h,t) => if p(h) then dropWhile(t,p) else l

def init[A] (l: List[A]): List[A] = l match
  case Nil => throw NoSuchElementException()
  case Cons(_,Nil) => Nil
  case Cons(h,t) => Cons(h, init(t))

Cosa fanno. tail toglie la testa, restituisce la coda così com'è (nessuna copia). drop la toglie n volte; n guida la ricorsione, se la lista finisce prima: errore. dropWhile toglie finché p vale e restituisce l al primo elemento che resta. init toglie l'ultimo: il caso base è Cons(_, Nil); deve ricostruire ogni Cons al ritorno.

  case Cons(_,Nil) => 1

  case Nil => 1

  foldLeft(l, Nil, (acc, a) => Cons(a, acc))

Cosa fanno. length semplice: il +1 avviene dopo il ritorno, quindi non è in coda. foldLeft porta in avanti l'accumulatore z: nessun lavoro dopo la chiamata, quindi è in coda. product: neutro 1 (con 0 il risultato sarebbe sempre 0). length1 ignora l'elemento e incrementa. reverse: ogni elemento visitato va in testa all'accumulatore, quindi l'ultimo finisce davanti.

Cosa fanno. foldRight1: inverto la lista e uso foldLeft, scambiando gli argomenti di f; non va in StackOverflow. foldLeft1: faccio produrre a foldRight una funzione B => B (calcolo rimandato): per ogni a costruisco b => g(f(b, a)), il neutro è identity; alla fine applico il tutto a z.

  foldRight[A, List[A]] (l, Nil, (a, z) => if p(a) then Cons(a, z) else z)

Cosa fanno. concat appiattisce una lista di liste con foldRight: ogni lista è ricopiata una volta sola, costo lineare (con foldLeft l'accumulatore crescente verrebbe ricopiato a ogni passo: quadratico). filter: tengo a (lo rimetto davanti) o scarto (passo z invariato). flatMap = map poi concat. filter1: tenere = singoletto, scartare = Nil.

S3 · Alberi, Option, for

Nozioni

  • Tree: enum Tree[+A]: case Leaf(value: A); case Branch(left, right). Funzioni sull'albero = ricorsione sui due casi. Un solo fold(t)(f)(g): g trasforma una foglia, f combina i due risultati dei rami. size, maximum, map sono casi particolari.
  • Option: Some(a) oppure None. Il fallimento diventa un valore nel tipo: niente null, niente eccezioni. Chi chiama è obbligato a gestire l'assenza.
  • map(f: A => B): applica f dentro, None resta None. flatMap(f: A => Option[B]): serve quando f può a sua volta fallire (con map verrebbe Option[Option[B]]). filter(p): Some diventa None se p è falso.
  • getOrElse[B >: A](default: => B): B: default è by-name (valutato solo se serve); B >: A perché Option è covariante e A non può stare in posizione di argomento.
  • for/yield è zucchero sintattico: for a <- ao; b <- bo yield f(a,b) = ao.flatMap(a => bo.map(b => f(a,b))). Le frecce <- diventano flatMap, l'ultima map. Se un passo è None, tutto è None.
  • map2(ao, bo)(f): combina due Option, Some solo se entrambe lo sono. sequence: List[Option[A]] => Option[List[A]], Some solo se tutti sono Some. traverse(as)(f): come sequence dopo map(f), ma in un solo passaggio.
  • Varianza: T[+A] covariante (produce A, si legge: List, Option). T[-A] contravariante (consuma A, si scrive: funzioni sull'argomento). T[A] invariante (legge e scrive: Array). Regola: un +A non può comparire come tipo di argomento di un metodo, per questo getOrElse[B >: A] e append[B >: A].
  • Dispatch dinamico: il metodo eseguito dipende dal tipo a runtime dell'oggetto, non dal tipo statico. Un self type this: java.awt.Point => dice a un trait che sarà mescolato a un Point.
  • Nil = lista vuota (valore valido). None = assenza di valore. null = da non usare. Nothing = tipo senza valori, sottotipo di tutti.

Cosa fanno. Ogni metodo guarda i due casi: su None propaga None (o il default); su Some(a) lavora su a. flatMap non ri-avvolge: f(a) è già un Option. forAll su None è true (nessun elemento viola p).

Cosa fanno. map2: se ao è Some(a) guardo bo; se anche bo è Some(b), applico f. sequence: parto da Some(Nil) e per ogni elemento (da destra) aggancio a :: resto solo se entrambi sono Some. S4 · Laziness: LazyList

Nozioni

  • Strict (eager): gli argomenti sono calcolati prima della chiamata. By-name (x: => Int): calcolato a ogni uso, anche più volte. lazy val: calcolato al primo uso, poi ricordato. Verificato: con def f(x: => Int) = x + x l'argomento si valuta due volte; con lazy val una.
  • Cons(h: () => A, t: () => LazyList[A]): testa e coda sono thunk (() => … = ricetta senza argomenti, non ancora eseguita). cons(hd: => A, tl: => LazyList[A]) mette i valori in lazy val e crea i thunk: ogni parte è calcolata al più una volta (memoization).
  • Operazioni intermedie (map, filter, take, drop, append…) restituiscono una nuova LazyList senza calcolare quasi nulla. Operazioni terminali (toList, forAll, exists, headOption, find) forzano il calcolo.
  • Liste infinite: naturals = from(1). Si usano con take/takeWhile/exists. naturals.toList non termina (toList è stretta: cerca Empty che non arriva). naturals.forAll(_ >= 0) non termina (il predicato è sempre vero, non trova mai un controesempio). naturals.exists(_ > 10) termina.
  • foldRight pigro: foldRight(z: => B)(f: (A, => C) => C). Il resto arriva a f by-name: se f non lo usa, il resto non viene calcolato. Per questo takeWhile, headOption, map, filter, append, flatMap si scrivono con foldRight e restano pigre. foldLeft invece è stretta e non vale su liste infinite.
  • Interleaving: l.map(f).filter(p) su LazyList lavora un elemento alla volta (map e filter si alternano), su List fa due passate complete. Per questo find(p) = filter(p).headOption va bene qui e non sulle liste strette.
  • unfold: unfold(z)(f) con f: S => Option[(A, S)]. None = fine. Some((a, s)) = emetti a e continua dallo stato s. Genera fibs, map, take, zipWith senza ricorsione esplicita.
  • Il foldRight non è in coda: va in StackOverflow se f scende in profondità.

LazyList · cons · empty · apply

enum LazyList[+A]:
  case Empty
  case Cons(h: () => A, t: () => LazyList[A])

  def cons[A](hd: => A, tl: => LazyList[A]): LazyList[A] =
    lazy val head = hd
    lazy val tail = tl
    Cons(() => head, () => tail)

    if as.isEmpty then empty
    else cons(as.head, apply(as.tail*))

Cosa fanno. cons non calcola né testa né coda: li mette in due lazy val e restituisce due thunk che le leggono. La prima volta che qualcuno chiama il thunk il valore viene calcolato; le volte dopo si riusa.

S5 · State e numeri casuali puri

Nozioni

  • Un generatore con stato nascosto (Random.nextInt) non è puro: due chiamate danno numeri diversi. Soluzione: nextInt: (Int, RNG) restituisce il numero e il nuovo stato. Stesso seme → stessa sequenza (riproducibile, testabile).
  • Mai riusare lo stato vecchio: chiamare due volte nextInt sullo stesso rng dà due volte lo stesso numero.
  • type Rand[+A] = RNG => (A, RNG): "una ricetta per ottenere una A consumando un RNG". I combinatori (unit, map, map2, flatMap, sequence) passano lo stato al posto tuo, in ordine.
  • Il pattern generale: State[S, +A](run: S => (A, S)). get legge lo stato, set(s) lo sostituisce, modify(f) lo trasforma. Si compone anche con for.
  • nonNegativeInt: se n < 0 restituisce -(n+1) e non -n, perché -Int.MinValue va in overflow e resta negativo. double in [0, 1): n / (Int.MaxValue.toDouble + 1) (+1 per escludere l'1).
  • nonNegativeLessThan(bound): usa double (numero in [0,1)) e lo scala: (d * bound).toInt dà un intero da 0 a bound-1. Come un dado con bound facce.
  • stateToLazyList: da un automa a stati a una sequenza infinita (collega S4 e S5).

S6–S7 · Testing e property-based testing

Nozioni

  • Asserzione = condizione booleana che nelle esecuzioni corrette è vera. require(c): pre-condizione, colpa di chi chiama (IllegalArgumentException: requirement failed). x.ensuring(r => P(r)): post-condizione, colpa della funzione (AssertionError). assert(c): deve valere il programma (AssertionError: assertion failed). assume(c): un'ipotesi (AssertionError: assumption failed).
  • Property-based testing: al posto di pochi esempi scrivi una proprietà che deve valere per tutti gli input; ScalaCheck ne genera 100 a caso e cerca un controesempio. Se lo trova fa lo shrinking: lo riduce al più piccolo che fallisce.
  • Come si inventa una proprietà: (1) legge algebrica: l.drop(n).drop(m) == l.drop(n + m); (2) idempotenza: l.take(n).take(n) == l.take(n); (3) identità: l.map(identity) == l; (4) oracolo: confronto con l'implementazione standard (list2lazyList(la).take(n).toList == la.take(n)); (5) pigrizia: un valore che lancia un'eccezione se viene forzato (tailForceFinder) e verifico che non scatti.
  • Specificare un minimum richiede due proprietà insieme: (P1) tutti gli elementi sono ≥ m; (P2) m è nella lista. Una sola non basta: restituire Int.MinValue soddisfa P1, restituire un numero qualunque della lista soddisfa P2. Le proprietà sono funzioni di minimum per poterle provare su implementazioni sbagliate (mutanti).
  • Gen[A] = State[RNG, A] (un generatore è un automa a stati: S5). Prop = (MaxSize, TestCases, RNG) => Result. Result = Passed oppure Falsified(failure, successes). SGen[A] = Int => Gen[A]: generatore che dipende dalla taglia, per provare da input piccoli a grandi.
  • opaque type: dentro il file Gen è un State; fuori nessuno lo sa. Non è una classe, quindi non ha un corpo per i metodi: si aggiungono con extension method (g.listOfN(5) funziona lo stesso con il punto).
  • Type class: given definisce un'istanza, using la chiede, summon[T] la recupera. def f[A: Gen] è zucchero per def f[A](using Gen[A]).
  • In ScalaCheck: forAll { (x: Int) => … }, p1 && p2, cond ==> prop (pre-condizione: scarta i casi che non la soddisfano), prop :| "etichetta".

S8 · Parser combinators

Nozioni

  • Un parser è un valore Parser[A] che legge una stringa e produce una A (o un errore). Si costruiscono parser grandi incollando parser piccoli con operatori (combinators). Il tipo concreto: Parser[+A] = ParseState => Result[A].
  • Progetto algebrico: prima l'interfaccia astratta trait Parsers[ParseError, Parser[+_]] (operazioni + leggi), poi l'implementazione (Sliceable). Le leggi (object Laws) sono proprietà ScalaCheck scritte con le sole operazioni astratte, quindi valgono per ogni implementazione.
  • Primitive (da implementare): string(s), regex(r), succeed(a), flatMap, or (|), slice, run. Derivate (scritte con le primitive): map, map2, product (**), many, many1, listOfN, ?, *, |*, *|.
  • Operatori: p ** q = prima p poi q, coppia dei risultati. p |* q = tieni solo il risultato di q (scarta il sinistro). p *| q = tieni solo quello di p. p | q = prova p, se fallisce prova q. p.? = zero o una volta (Option). p.many = zero o più. p.many1 = almeno una.
  • Il secondo argomento di map2, product, or è by-name (=>): è valutato solo se serve. In many è indispensabile: p.many si richiama dentro sé stesso, senza by-name andrebbe in ricorsione infinita prima di leggere un carattere.
  • Fallimento committed: Failure(errore, isCommitted). or prova la seconda alternativa solo se il primo fallimento non è committed (cioè se il primo parser non ha già consumato input). attempt annulla il commit.
  • Slice: se mi interessa solo il testo riconosciuto, non il valore, slice evita di costruire valori inutili.
  • Errori: ParseError(stack: List[(Location, String)]); Location(input, offset) sa calcolare riga e colonna e disegnare il segno ^.
  • JSON: la grammatica diventa codice, un parser per ogni forma. Le definizioni sono lazy val perché si richiamano a vicenda (json usa jarray, che usa json).

    case None =>
      Failure(s.loc.toError(s"regex $r"), false)

Cosa fanno. succeed: riesce subito consumando 0 caratteri. or: prova p; solo se è un fallimento non committed prova p2 dallo stesso punto; un successo (o un fallimento committed) resta com'è. regex: cerca una corrispondenza all'inizio dell'input rimanente (findPrefixOf) e consuma tanti caratteri quanti ne ha riconosciuti.

S9 · Monoid, Foldable, Functor, Monad

Nozioni

  • Monoid = un tipo A + combine(a1, a2): A + empty: A. Due leggi: associatività combine(combine(a,b),c) == combine(a,combine(b,c)); neutro combine(a, empty) == a == combine(empty, a). L'ordine degli argomenti non deve per forza essere commutativo.
  • Esempi: (Int, +, 0), (Int, *, 1), (Boolean, ||, false), (Boolean, &&, true), (String, +, ""), (List, ++, Nil), (A => A, composizione, identity) (endoMonoid). optionMonoid: primo Some (combine(None, Some(3)) = Some(3), combine(Some(1), Some(2)) = Some(1)); optionMonoidLift: se entrambi Some combina i contenuti (con intAddition: Some(1)+Some(2) = Some(3)).
  • foldMap(as)(f): trasforma ogni elemento con f in un valore del monoide e li combina partendo da empty. Esempio: foldMap(List("a","bb","ccc"))(_.length) con intAddition = 1+2+3 = 6; con stringMonoid e identity = "abbccc".
  • Omomorfismo f: A => B tra monoidi: f(combine(a1,a2)) == combine(f(a1), f(a2)) e f(empty) == empty. Isomorfismo: due omomorfismi f, g che si annullano a vicenda (g(f(a)) == a). Esempi: String ≅ List[Char] (toList, mkString); booleanOr ≅ booleanAnd (la negazione).
  • Dual: stesso monoide con combine a rovescio. productMonoid: due monoidi in parallelo sulla coppia.
  • Foldable[F]: contenitori che si possono ridurre. Primitiva: foldMap; da lì foldRight (monoide endoMonoid sulle funzioni B => B), foldLeft (monoide dual(endoMonoid)), combineAll, toList.
  • Functor[F]: contenitori su cui si può fare map. Legge: fa.map(identity) == fa (la forma non cambia). Derivati: distribute (F[(A,B)] => (F[A], F[B])), codistribute (Either[F[A], F[B]] => F[Either[A, B]]).
  • Monad[F] = Functor + unit + flatMap. Da flatMap + unit si ricavano map e map2. Leggi: associatività x.flatMap(f).flatMap(g) == x.flatMap(a => f(a).flatMap(g)); identità sinistra unit(y).flatMap(f) == f(y); identità destra x.flatMap(unit) == x. Sono le stesse leggi del monoide (associatività + neutro).
  • Sulle monadi: sequence (lista di F[A] → F[List[A]]), replicateM(n, ma) (ma ripetuta n volte; nella monade List dà tutte le combinazioni, per esempio replicateM(2, List(1,2)) = List(List(1,1), List(1,2), List(2,1), List(2,2)); con Option dà Some solo se ma è Some), compose (f: A => F[B] e g: B => F[C] → A => F[C]).
  • Gerarchia: ogni Monad è un Functor. Option, List, State, Gen, Parser, LazyList sono monadi: tutti i flatMap visti nel corso sono lo stesso schema.

Monoid · leggi

trait Monoid[A]:
  def combine(a1: A, a2: A): A
  def empty: A

  object laws:
    def associative(using Arbitrary[A], Equality[A]): Prop =
      forAll { (a1: A, a2: A, a3: A) =>
        combine(combine(a1, a2), a3) === combine(a1, combine(a2, a3)) } :| "monoid-associative"

    def unit(using Arbitrary[A], Equality[A]): Prop =
      forAll { (a: A) =>
        (combine(a, empty) === a) :| "right-empty" &&
        (combine(empty, a) === a) :| "left-empty" } :| "monoid-unit"

    def monoid (using Arbitrary[A], Equality[A]): Prop =
      (associative && unit) :| "monoid-laws"

Cosa fa. Il trait ha le due operazioni e, dentro laws, le leggi come proprietà ScalaCheck: associatività e neutro a destra e sinistra. Per provare un monoide: intAddition.laws.monoid. === è l'uguaglianza che passa da Equality (serve per confrontare funzioni).

optionMonoid · optionMonoidLift · endoMonoid

def optionMonoid[A]: Monoid[Option[A]] = new Monoid[Option[A]]:
  def combine(a1: Option[A], a2: Option[A]) = a1 match
    case None => a2
    case _ => a1
  val empty = None

def optionMonoidLift[A: Monoid]: Monoid[Option[A]] = new Monoid[Option[A]]:
  def combine(a1: Option[A], a2: Option[A]) = (a1, a2) match
    case (None, _) => a2
    case (_, None) => a1
    case (Some(x), Some(y)) => Some(summon[Monoid[A]].combine(x, y))
  val empty = None

def endoMonoid[A]: Monoid[A => A] = new Monoid[A => A]:
  def combine(f: A => A, g: A => A) = x => f(g(x))
  val empty = (x: A) => x

Cosa fanno. optionMonoid: vince il primo Some, None è il neutro. optionMonoidLift: se ce ne sono due, combina i contenuti con il monoide di A; se ce n'è uno solo, quello. endoMonoid: funzioni da A in A, combine è la composizione, empty è identity.

foldMap · homomorphism · isomorphism

extension [B](mb: Monoid[B])
  def foldMap[A](as: List[A])(f: A => B): B =
    as.foldLeft(mb.empty)((acc, a) => mb.combine(acc, f(a)))

extension [A: {Arbitrary, Equality}](ma: Monoid[A])
  def homomorphism[B](f: A => B)(mb: Monoid[B]): Prop =
    forAll { (a1: A, a2: A) => f(ma.combine(a1, a2)) === mb.combine(f(a1), f(a2)) } :| "combine" &&
    (f(ma.empty) === mb.empty) :| "empty"

  def isomorphism[B: Arbitrary](f: A => B, g: B => A)(mb: Monoid[B]): Prop =
    ma.homomorphism(f)(mb) && mb.homomorphism(g)(ma) &&
    forAll { (a: A) => g(f(a)) === a } && forAll { (b: B) => f(g(b)) === b }

// usi nei test
stringMonoid.isomorphism[List[Char]](_.toList, _.mkString)(listMonoid[Char])
booleanOr.isomorphism[Boolean](!_, !_)(booleanAnd)

Cosa fanno. foldMap: parte da empty, per ogni elemento fa f(a) e lo combina all'accumulatore. homomorphism controlla che f rispetti l'operazione e il neutro. isomorphism controlla i due versi e anche che g(f(a)) == a e f(g(b)) == b. De Morgan: !(a || b) == !a && !b è il motivo per cui la negazione collega booleanOr e booleanAnd.

productMonoid · dual

def productMonoid[A, B](ma: Monoid[A])(mb: Monoid[B]): Monoid[(A, B)] = new Monoid[(A, B)]:
  def combine(x: (A, B), y: (A, B)) = (ma.combine(x._1, y._1), mb.combine(x._2, y._2))
  val empty = (ma.empty, mb.empty)

def dual[A](m: Monoid[A]): Monoid[A] = new:
  def combine(x: A, y: A): A = m.combine(y, x)
  val empty = m.empty

Cosa fanno. productMonoid: combina la prima componente con ma e la seconda con mb; il neutro è la coppia dei neutri. Serve a calcolare due cose in un solo passaggio (per esempio somma e lunghezza). dual scambia gli argomenti di combine: trasforma un fold da destra in uno da sinistra.

trait Foldable[F[_]]:
  extension [A](as: F[A])
    def foldMap[B](f: A => B)(using mb: Monoid[B]): B

      as.foldMap[B => B](f.curried)(using endoMonoid[B])(z)

    def foldLeft[B](z: B)(f: (B, A) => B): B =
      as.foldMap[B => B](a => b => f(b, a))(using dual(endoMonoid[B]))(z)

      as.foldLeft(m.empty)(m.combine)

Cosa fanno. L'unica cosa da scrivere per un contenitore è foldMap. trait Monad[F[_]]
  extends Functor[F]:

  def unit[A](a: => A): F[A]

  extension [A](fa: F[A])
    def flatMap[B] (f: A => F[B]): F[B]

    def map[B](f: A => B): F[B] =
      fa.flatMap[B] { a => unit(f(a)) }

    def map2[B, C](fb: F[B])(f: (A, B) => C): F[C] =
      fa.flatMap { a => fb.map { b => f(a,b) } }

def associative[A, B, C](using ...): Prop =
  forAll { (x: F[A], f: A => F[B], g: B => F[C]) =>
    val left = x.flatMap[B](f).flatMap[C](g)
    val right = x.flatMap[C] { a => f(a).flatMap[C](g) }
    (left === right) :| s"left:$left right:$right" }

def identityRight[A](using ...) =
  forAll { (x: F[A], f: A => F[A]) =>
    val result = x.flatMap[A](unit[A])
    (result === x) :| s"got:$result expected:$x" }

def identityLeft[A: Arbitrary](using ...) =
  forAll { (y: A, f: A => F[A]) =>
    val left = unit[A](y).flatMap[A](f)
    val right = f(y)
    (left === right) :| s"left:$left right:$right" }

Cosa fanno. associative: concatenare f e g da fuori o da dentro è lo stesso. identityRight: flatMap(unit) non cambia nulla. identityLeft: unit(y).flatMap(f) è proprio f(y). (Le firme complete con i parametri using sono in 09-monad/Exercises.scala.)

Frasi pronte in inglese

  • toList fails on infinite lists because it is strict: it keeps forcing the tail until it reaches Empty, and an infinite list never reaches it.
  • naturals.take(1000000000).drop(41).take(10).toList terminates because take and drop are lazy: only the elements that toList finally demands are computed, here about 51.
  • naturals.forAll(_ >= 0) never terminates because the predicate is always true, so forAll never finds a counterexample to stop at. exists stops at the first witness.
  • foldRight on List is not stack-safe: after the recursive call there is still f to apply, so every element keeps a stack frame. foldLeft is tail recursive.
  • The second argument is by-name, so it is evaluated only when needed. Otherwise many would call itself forever before reading a single character.
  • listOfN is an extension method because Gen is an opaque type, not a class: there is no body in which to define a member.
  • The laws are written only with the abstract operations of the trait, so they hold for every implementation.
  • A pure function always returns the same output for the same input and has no side effects, so a call can be replaced by its value (referential transparency).
  • Associativity lets us group the combinations in any way, so a fold with a monoid can be split and combined in parallel.
  • I use Option instead of an exception because the possible failure is visible in the type, and the caller is forced to handle it.
