S4 · Laziness: LazyList

Formulario della lezione: la teoria, gli atomi (simboli, tipi, costruttori, funzioni) con cosa chiedono tra parentesi, i pezzi di codice dei tuoi esercizi e in fondo il codice completo animato, con ogni pezzo evidenziato. Torna all'indice del formulario.

Teoria

  • Strict (eager): gli argomenti sono calcolati prima della chiamata. By-name (x: => Int): calcolato a ogni uso, anche più volte. lazy val: calcolato al primo uso, poi ricordato. Verificato: con def f(x: => Int) = x + x l'argomento si valuta due volte; con lazy val una.
  • Cons(h: () => A, t: () => LazyList[A]): testa e coda sono thunk (() => … = ricetta senza argomenti, non ancora eseguita). cons(hd: => A, tl: => LazyList[A]) mette i valori in lazy val e crea i thunk: ogni parte è calcolata al più una volta (memoization).
  • Operazioni intermedie (map, filter, take, drop, append…) restituiscono una nuova LazyList senza calcolare quasi nulla. Operazioni terminali (toList, forAll, exists, headOption, find) forzano il calcolo.
  • Liste infinite: naturals = from(1). Si usano con take/takeWhile/exists. naturals.toList non termina (toList è stretta: cerca Empty che non arriva). naturals.forAll(_ >= 0) non termina (il predicato è sempre vero, non trova mai un controesempio). naturals.exists(_ > 10) termina.
  • foldRight pigro: foldRight(z: => B)(f: (A, => C) => C). Il resto arriva a f by-name: se f non lo usa, il resto non viene calcolato. Per questo takeWhile, headOption, map, filter, append, flatMap si scrivono con foldRight e restano pigre. foldLeft invece è stretta e non vale su liste infinite.
  • Interleaving: l.map(f).filter(p) su LazyList lavora un elemento alla volta (map e filter si alternano), su List fa due passate complete. Per questo find(p) = filter(p).headOption va bene qui e non sulle liste strette.
  • unfold: unfold(z)(f) con f: S => Option[(A, S)]. None = fine. Some((a, s)) = emetti a e continua dallo stato s. Genera fibs, map, take, zipWith senza ricorsione esplicita.
  • Il foldRight non è in coda: va in StackOverflow se f scende in profondità.

Pezzi di codice e cosa fanno

LazyList · cons · empty · apply

enum LazyList[+A]:
  case Empty
  case Cons(h: () => A, t: () => LazyList[A])

object LazyList:
  def empty[A]: LazyList[A] = Empty

  def cons[A](hd: => A, tl: => LazyList[A]): LazyList[A] =
    lazy val head = hd
    lazy val tail = tl
    Cons(() => head, () => tail)

  def apply[A](as: A*): LazyList[A] =
    if as.isEmpty then empty
    else cons(as.head, apply(as.tail*))

Cosa fanno. cons non calcola né testa né coda: li mette in due lazy val e restituisce due thunk che le leggono. La prima volta che qualcuno chiama il thunk il valore viene calcolato; le volte dopo si riusa.

headOption · tail · toList

def headOption: Option[A] = this match
  case Empty => None
  case Cons(h,t) => Some(h())

def tail: LazyList[A] = this match
  case Empty => Empty
  case Cons(h,t) => t()

def toList: List[A] = this match
  case Empty => Nil
  case Cons(h,t) => h() :: t().toList

Cosa fanno. h() e t() con le parentesi forzano il thunk. headOption forza solo la testa, non la coda. toList forza tutto, fino a Empty: su una lista infinita non termina.

from · to · naturals

def from(n: Int): LazyList[Int] = cons(n, from(n+1))
def to(n: Int): LazyList[Int] = cons(n, to(n-1))
lazy val naturals: LazyList[Int] = from(1)

Cosa fanno. Liste infinite: la ricorsione non si esaurisce perché il secondo argomento di cons è by-name e non viene calcolato finché non serve. from(1) dà 1, 2, 3, … naturals parte da 1 (lo vuole il test del corso).

take · drop · takeWhile

def take(n: Int): LazyList[A] =
  if n <= 0 then empty else
    this match
      case Empty => empty
      case Cons(h, t) => cons(h(), t().take(n-1))

def drop(n: Int): LazyList[A] =
  if n <= 0 then this else
    this match
      case Empty => empty
      case Cons(_, t) => t().drop(n-1)

def takeWhile(p: A => Boolean): LazyList[A] = this match
  case Empty => empty
  case Cons(h,t) => if p(h()) then cons(h(), t().takeWhile(p)) else empty

Cosa fanno. take è pigra: crea una cella e rimanda il resto dentro cons. drop invece avanza subito di n code (non guarda le teste scartate). takeWhile si ferma al primo elemento che viola p. naturals.take(1000000000).drop(41).take(10).toList termina perché nessuno chiede più di 51 elementi.

forAll · exists

def forAll(p: A => Boolean): Boolean = this match
  case Cons(h,t) => if p(h()) then t().forAll(p) else false
  case Empty => true

def exists(p: A => Boolean): Boolean = this match
  case Cons(h,t) => if p(h()) then true else t().exists(p)
  case Empty => false

Cosa fanno. Si fermano appena sanno la risposta: forAll al primo elemento che viola p, exists al primo che la soddisfa. Entrambe in coda. Su una lista infinita terminano solo se la risposta arriva prima della fine.

Con foldRight: takeWhile1 · headOption1 · map · filter · append · flatMap

def takeWhile1(p: A => Boolean): LazyList[A] =
  foldRight(empty)((a,acc) => if p(a) then cons(a,acc) else empty)

def headOption1: Option[A] =
  foldRight(None)((a,_) => Some(a))

def map[B](f: A => B): LazyList[B] =
  foldRight(empty)((a,acc) => cons(f(a), acc))

def filter(p: A => Boolean): LazyList[A] =
  foldRight(empty)((a,acc) => if p(a) then cons(a,acc) else acc)

def append[B >: A](that: => LazyList[B]): LazyList[B] =
  foldRight(that)((a,acc) => cons(a,acc))

def flatMap[B](f: A => LazyList[B]): LazyList[B] =
  foldRight(empty)((a,acc) => f(a).append(acc))

Cosa fanno. In ognuna acc è "il resto, ancora da calcolare". Se la funzione non lo tocca (takeWhile1 quando p è falso, headOption1 sempre) il resto non viene mai calcolato. filter: se p(a) è falso restituisce acc, cioè forza il resto fino al prossimo elemento valido. append non forza that finché non si arriva in fondo.

fibs · unfold · fibsUnfold

lazy val fibs: LazyList[Int] =
  def bonacci(a: Int,b: Int): LazyList[Int] = cons(a, bonacci(b,a+b))
  bonacci(0,1)

def unfold[A,S](z: S)(f: S => Option[(A, S)]): LazyList[A] = f(z) match
  case None => empty
  case Some((a,s)) => cons(a, unfold(s)(f))

lazy val fibsUnfold: LazyList[Int] =
  unfold(0,1)((a,s) => Some(a,(s,s+a)))

Cosa fanno. fibs = 0, 1, 1, 2, 3, 5, … Lo stato è la coppia (a, b). unfold è la forma generale: chiedi a f "che valore emetto e quale stato passo avanti?". Se f risponde None, la lista finisce.

mapUnfold · takeUnfold · takeWhileUnfold · zipWith

def mapUnfold[B](f: A => B): LazyList[B] =
  unfold(this) {
    case Cons(h, t) => Some((f(h()), t()))
    case _ => None }

def takeUnfold(n: Int): LazyList[A] =
  unfold((this, n)) {
    case (Cons(h, t), m) if m > 0 => Some((h(), (t(), m - 1)))
    case _  => None }

def takeWhileUnfold(p: A => Boolean): LazyList[A] =
  unfold(this) {
    case Cons(h, t) if p(h()) => Some((h(), t()))
    case _ => None }

def zipWith[B >: A, C](ope: (=> B, => B) => C)(bs: LazyList[B]): LazyList[C] =
  unfold((this, bs)) {
    case (Cons(h1, t1), Cons(h2, t2)) => Some((ope(h1(), h2()), (t1(), t2())))
    case _ => None }

Cosa fanno. Lo stato è "quanto resta da leggere": la lista stessa (map, takeWhile), la lista più un contatore (take), due liste (zipWith). Ogni case con Some dice cosa emettere e il nuovo stato; case _ => None chiude.

Why does toList fail on infinite lists? Why does naturals.take(1000000000).drop(41).take(10).toList terminate? Why would naturals.forAll { _ >= 0 } crash? Risposte pronte in fondo alla pagina.
