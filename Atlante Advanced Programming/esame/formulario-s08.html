S8 · Parser combinators

Formulario della lezione: la teoria, gli atomi (simboli, tipi, costruttori, funzioni) con cosa chiedono tra parentesi, i pezzi di codice dei tuoi esercizi e in fondo il codice completo animato, con ogni pezzo evidenziato. Torna all'indice del formulario.

Teoria

  • Un parser è un valore Parser[A] che legge una stringa e produce una A (o un errore). Si costruiscono parser grandi incollando parser piccoli con operatori (combinators). Il tipo concreto: Parser[+A] = ParseState => Result[A].
  • Progetto algebrico: prima l'interfaccia astratta trait Parsers[ParseError, Parser[+_]] (operazioni + leggi), poi l'implementazione (Sliceable). Le leggi (object Laws) sono proprietà ScalaCheck scritte con le sole operazioni astratte, quindi valgono per ogni implementazione.
  • Primitive (da implementare): string(s), regex(r), succeed(a), flatMap, or (|), slice, run. Derivate (scritte con le primitive): map, map2, product (**), many, many1, listOfN, ?, *, |*, *|.
  • Operatori: p ** q = prima p poi q, coppia dei risultati. p |* q = tieni solo il risultato di q (scarta il sinistro). p *| q = tieni solo quello di p. p | q = prova p, se fallisce prova q. p.? = zero o una volta (Option). p.many = zero o più. p.many1 = almeno una.
  • Il secondo argomento di map2, product, or è by-name (=>): è valutato solo se serve. In many è indispensabile: p.many si richiama dentro sé stesso, senza by-name andrebbe in ricorsione infinita prima di leggere un carattere.
  • Fallimento committed: Failure(errore, isCommitted). or prova la seconda alternativa solo se il primo fallimento non è committed (cioè se il primo parser non ha già consumato input). attempt annulla il commit.
  • Slice: se mi interessa solo il testo riconosciuto, non il valore, slice evita di costruire valori inutili.
  • Errori: ParseError(stack: List[(Location, String)]); Location(input, offset) sa calcolare riga e colonna e disegnare il segno ^.
  • JSON: la grammatica diventa codice, un parser per ogni forma. Le definizioni sono lazy val perché si richiamano a vicenda (json usa jarray, che usa json).

Pezzi di codice e cosa fanno

L'interfaccia astratta

trait Parsers[ParseError, Parser[+_]]:
  self =>
  def string(s: String): Parser[String]
  def char(c: Char): Parser[Char] = string(c.toString).map { _.charAt(0) }
  def succeed[A](a: A): Parser[A]
  def regex(r: Regex): Parser[String]

  extension [A](p: Parser[A])
    def run(input: String): Either[ParseError, A]
    infix def or(p2: => Parser[A]): Parser[A]
    def |(p2: => Parser[A]): Parser[A] = p.or (p2)
    def slice: Parser[String]
    def flatMap[B](f: A => Parser[B]): Parser[B]

Cosa fa. Elenca le primitive senza dire come sono fatte. self => dà un nome a "questo oggetto" per poterlo usare dentro i blocchi annidati (Laws). char è già definita: legge una stringa di un carattere e prende il primo.

map2 · product · ** · |* · *| · ? · *

extension [A](p1: Parser[A])
  def map2[B, C](p2: => Parser[B]) (f: (A, B) => C): Parser[C] =
    p1.flatMap{ elem => p2.map{ elem2 => f(elem,elem2)}}

  def product[B] (p2: => Parser[B]): Parser[(A,B)] =
    p1.flatMap{ elem => p2.map{ elem2 => (elem,elem2)}}

  def **[B](p2: => Parser[B]): Parser[(A, B)] = p1.product(p2)
  def |*[B](p2: => Parser[B]): Parser[B] = p1.flatMap { s => p2 }
  def *| (p2: => Parser[Any]): Parser[A] = (p1 ** p2).map { (a, _) => a }
  def ? : Parser[Option[A]] = { p1.map { Some(_) } } | succeed(None)
  def * : Parser[List[A]] = p1.many

Cosa fanno. map2: esegui p1, poi p2, combina i due risultati con f. product = map2 con f che fa la coppia. |* ignora il risultato sinistro (utile per saltare una virgola o una parentesi). *| ignora il destro. ?: se p1 fallisce senza consumare, succeed(None) al suo posto.

map · many · manyA · many1 · listOfN · digitTimesA

extension [A](p: Parser[A])
  def map[B](f: A => B): Parser[B] =
    p.flatMap{ elem => succeed(f(elem))}

  def many: Parser[List[A]] =
    p.map2(p.many)(_::_) | succeed(List.empty[A])

  def many1: Parser[List[A]] =
    p.map2(p.many)(_ :: _)

  def listOfN(n: Int): Parser[List[A]] =
    if n <= 0 then succeed(List.empty[A])
    else p.map2(p.listOfN(n - 1))(_ :: _)

def manyA: Parser[Int] =
  char('a').many.map{_.size}

def digitTimesA: Parser[Int] =
  regex("[0-9]".r).map {_.toInt}.flatMap { elem => char('a').listOfN(elem).map { _.size}}

Cosa fanno. map = flatMap + succeed. many: provo p seguito da many, aggiungo in testa (::); se p fallisce, lista vuota. many1 richiede la prima occorrenza. listOfN(n): esattamente n volte. manyA conta le a di fila. digitTimesA legge una cifra d e poi esattamente d lettere a: il parser successivo dipende dal valore letto, per questo serve flatMap (map2 non basta).

Sliceable: succeed · string · or · regex

def succeed[A](a: A): Parser[A] =
  (s: ParseState) => Success(a, 0)

extension [A](p: Parser[A])
  def or(p2: => Parser[A]): Parser[A] =
    (s: ParseState) =>
      p(s) match
        case Failure(_, false) =>  p2(s)
        case pval => pval

def regex(r: Regex): Parser[String] = (s: ParseState) =>
  r.findPrefixOf(s.input) match
    case Some(m) =>
      if s.isSliced then Slice(m.length) else Success(m, m.length)
    case None =>
      Failure(s.loc.toError(s"regex $r"), false)

Cosa fanno. succeed: riesce subito consumando 0 caratteri. or: prova p; solo se è un fallimento non committed prova p2 dallo stesso punto; un successo (o un fallimento committed) resta com'è. regex: cerca una corrispondenza all'inizio dell'input rimanente (findPrefixOf) e consuma tanti caratteri quanti ne ha riconosciuti.

Result e ParseError

type Parser[+A] = ParseState => Result[A]

enum Result[+A]:
  case Success(get: A, length: Int)
  case Failure(get: ParseError, isCommitted: Boolean) extends Result[Nothing]
  case Slice(length: Int) extends Result[String]

Cosa fa. Un parser guarda ParseState (dov'è, e se è in modalità slice) e restituisce: Success (valore + caratteri consumati), Slice (solo caratteri consumati), Failure (errore + flag committed). Slice e Failure sono sottotipi con tipo raffinato (GADT).

JSON: QUOTED · DOUBLE · ws · jnull · jbool · jstring · jnumber

enum JSON:
  case JNull
  case JNumber(get: Double)
  case JString(get: String)
  case JBool(get: Boolean)
  case JArray(get: IndexedSeq[JSON])
  case JObject(get: Map[String, JSON])

lazy val QUOTED: Parser[String] =
  regex("\"[^\"]*\"".r).map { _.drop(1).dropRight(1) }

lazy val DOUBLE: Parser[Double] =
  regex("""[-+]?([0-9]*\.)?[0-9]+([eE][-+]?[0-9]+)?""".r).map { _.toDouble }

lazy val ws: Parser[Unit] =
  regex("""\s+""".r).map { _ => () }

lazy val jnull: Parser[JSON] =
  string("null").map { _ => JNull }

lazy val jbool: Parser[JSON] =
  string("true").map { _ => JBool(true) } | string("false").map { _ => JBool(false) }

lazy val jstring: Parser[JString] = QUOTED.map { JString(_) }
lazy val jnumber: Parser[JNumber] = DOUBLE.map { JNumber(_) }

Cosa fanno. QUOTED: legge "…" (virgolette, niente virgolette dentro) e toglie la prima e l'ultima. DOUBLE: numero con segno, parte decimale ed esponente opzionali. ws: uno o più spazi. Le forme semplici sono un string o una regex + map che mette il risultato nel costruttore giusto.

JSON: jarray · field · jobject · json

private lazy val commaSeparatedVals: Parser[List[JSON]] =
  json.map2((string(",") |* json).many)(_ :: _) | succeed(Nil)

lazy val jarray: Parser[JArray] =
  (char('[') |* ws.? |* (commaSeparatedVals *| ws.?) *| char(']')).map { l => JArray(l.toVector) }

lazy val field: Parser[(String,JSON)] =
  (ws.? |* (QUOTED *| ws.?)) ** (char(':') |* json)

private lazy val commaSeparatedFields: Parser[List[(String,JSON)]] =
  field.map2((string(",") |* field).many)(_ :: _) | succeed(Nil)

lazy val jobject: Parser[JObject] =
  (char('{') |* ws.? |* (commaSeparatedFields *| ws.?) *| char('}')).map { l => JObject(l.toMap) }

lazy val json: Parser[JSON] =
  ws.? |* ((jobject | jarray | jstring | jnumber | jbool | jnull) *| ws.?)

Cosa fanno. commaSeparatedVals: un json, poi zero o più coppie "virgola + json" (|* scarta la virgola); oppure lista vuota. jarray: [, spazi opzionali, elementi, spazi opzionali, ], poi lista → JArray. field: chiave tra virgolette, :, valore: coppia. jobject: come l'array con le parentesi graffe e toMap. json: spazi opzionali, una tra le sei forme (la prova va in ordine), spazi opzionali.

Why is the second argument of map2 by-name? Perché se non lo fosse many chiamerebbe sé stessa senza fine. Why can the laws live inside the abstract trait? Perché sono scritte solo con le operazioni astratte: valgono per ogni implementazione. When do you need flatMap and not map2? Quando il parser successivo dipende dal valore appena letto (digitTimesA).
