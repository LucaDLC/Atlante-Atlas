FormularioS3

S3 · Alberi, Option, for

Formulario della lezione: la teoria, gli atomi (simboli, tipi, costruttori, funzioni) con cosa chiedono tra parentesi, i pezzi di codice dei tuoi esercizi e in fondo il codice completo animato, con ogni pezzo evidenziato. Torna all'indice del formulario.

Teoria

  • Tree: enum Tree[+A]: case Leaf(value: A); case Branch(left, right). Funzioni sull'albero = ricorsione sui due casi. Un solo fold(t)(f)(g): g trasforma una foglia, f combina i due risultati dei rami. size, maximum, map sono casi particolari.
  • Option: Some(a) oppure None. Il fallimento diventa un valore nel tipo: niente null, niente eccezioni. Chi chiama è obbligato a gestire l'assenza.
  • map(f: A => B): applica f dentro, None resta None. flatMap(f: A => Option[B]): serve quando f può a sua volta fallire (con map verrebbe Option[Option[B]]). filter(p): Some diventa None se p è falso.
  • getOrElse[B >: A](default: => B): B: default è by-name (valutato solo se serve); B >: A perché Option è covariante e A non può stare in posizione di argomento.
  • for/yield è zucchero sintattico: for a <- ao; b <- bo yield f(a,b) = ao.flatMap(a => bo.map(b => f(a,b))). Le frecce <- diventano flatMap, l'ultima map. Se un passo è None, tutto è None.
  • map2(ao, bo)(f): combina due Option, Some solo se entrambe lo sono. sequence: List[Option[A]] => Option[List[A]], Some solo se tutti sono Some. traverse(as)(f): come sequence dopo map(f), ma in un solo passaggio.
  • Varianza: T[+A] covariante (produce A, si legge: List, Option). T[-A] contravariante (consuma A, si scrive: funzioni sull'argomento). T[A] invariante (legge e scrive: Array). Regola: un +A non può comparire come tipo di argomento di un metodo, per questo getOrElse[B >: A] e append[B >: A].
  • Dispatch dinamico: il metodo eseguito dipende dal tipo a runtime dell'oggetto, non dal tipo statico. Un self type this: java.awt.Point => dice a un trait che sarà mescolato a un Point.
  • Nil = lista vuota (valore valido). None = assenza di valore. null = da non usare. Nothing = tipo senza valori, sottotipo di tutti.

Pezzi di codice e cosa fanno

Tree · size · maximum · map

enum Tree[+A]:
  case Leaf(value: A)
  case Branch(left: Tree[A], right: Tree[A])

def size[A](t: Tree[A]): Int = t match
  case Leaf(_) => 1
  case Branch(left,right) => 1 + size(left) + size(right)

def maximum(t: Tree[Int]): Int = t match
  case Leaf(value) => value
  case Branch(left, right) => maximum(left).max(maximum(right))

def map[A, B](t: Tree[A])(f: A => B): Tree[B] = t match
  case Leaf(value) => Leaf(f(value))
  case Branch(left, right) => Branch(map(left)(f), map(right)(f))

Cosa fanno. size conta nodi interni e foglie (1 per ogni nodo). maximum prende il massimo dei due lati. map mantiene la forma e trasforma solo le foglie. Stesso schema tre volte: è quello che fold riassume.

fold sugli alberi e le tre funzioni riscritte

def fold[A,B](t: Tree[A])(f: (B, B) => B)(g: A => B): B = t match
  case Leaf(value) => g(value)
  case Branch(left, right) => f(fold(left)(f)(g), fold(right)(f)(g))

def size1[A](t: Tree[A]): Int =
  fold[A, Int](t)((l, r) => 1 + l + r)(_ => 1)

def maximum1(t: Tree[Int]): Int =
  fold[Int, Int](t)((l, r) => l.max(r))(identity)

def map1[A, B](t: Tree[A])(f: A => B): Tree[B] =
  fold[A, Tree[B]](t)(Branch(_, _))(a => Leaf(f(a)))

Cosa fa. g dice cosa fare di una foglia, f come unire i risultati dei due figli. size1: foglia vale 1, ramo = 1 + sx + dx. maximum1: foglia = il valore stesso (identity), ramo = massimo. map1: foglia = nuova foglia, ramo = ricostruisco Branch.

Option: map · getOrElse · flatMap · filter · forAll

enum Option[+A]:
  case Some(get: A)
  case None

  def map[B](f: A => B): Option[B] = this match
    case None => None
    case Some(a) => Some(f(a))

  def getOrElse[B >: A] (default: => B): B = this match
    case None => default
    case Some(a) => a

  def flatMap[B](f: A => Option[B]): Option[B] = this match
    case None => None
    case Some(a) => f(a)

  def filter(p: A => Boolean): Option[A] = this match
    case Some(a) => if p(a) then this else None
    case _ => None

  def forAll(p: A => Boolean): Boolean = this match
    case None => true
    case Some(a) => p(a)

Cosa fanno. Ogni metodo guarda i due casi: su None propaga None (o il default); su Some(a) lavora su a. flatMap non ri-avvolge: f(a) è già un Option. forAll su None è true (nessun elemento viola p).

map2 · sequence · traverse

def map2[A, B, C](ao: Option[A], bo: Option[B])(f: (A,B) => C): Option[C] =
  ao.flatMap(a => bo.map(b => f(a, b)))

def sequence[A](aos: List[Option[A]]): Option[List[A]] =
  aos.foldRight[Option[List[A]]](Some(Nil))((ao, acc) => map2(ao,acc)(_ :: _))

def traverse[A, B](as: List[A])(f: A => Option[B]): Option[List[B]] =
  as.foldRight[Option[List[B]]](Some(Nil))((a, acc) => map2(f(a), acc)(_ :: _))

Cosa fanno. map2: se ao è Some(a) guardo bo; se anche bo è Some(b), applico f. sequence: parto da Some(Nil) e per ogni elemento (da destra) aggancio a :: resto solo se entrambi sono Some. Esempio verificato: List(Some(1), Some(2)) → Some(List(1, 2)); List(Some(1), None) → None. traverse applica f a ogni elemento e fa la stessa cosa.

headOption · headGrade · for/yield · mean · variance

def headOption[A](lst: List[A]): Option[A] = lst match
  case Nil => None
  case h:: t => Some(h)

def headGrade(lst: List[(String,Int)]): Option[Int] =
  headOption(lst).map(_._2)

def headGrade1(lst: List[(String,Int)]): Option[Int] =
  for p <- headOption(lst) yield p._2

def mean(xs: Seq[Double]): Option[Double] =
  if xs.isEmpty then None
  else Some(xs.sum / xs.length)

def variance(xs: Seq[Double]): Option[Double] =
  mean(xs).flatMap(mp => mean(xs.map(x => math.pow(x - mp, 2))))

Cosa fanno. headOption: primo elemento se c'è. headGrade prende il voto (._2, secondo elemento della coppia) del primo studente; headGrade1 è lo stesso con for. mean è parziale: lista vuota → None. variance = media degli scarti al quadrato; usa mean due volte, quindi flatMap.

OrderedPoint · self type

trait OrderedPoint
  extends scala.math.Ordered[java.awt.Point]:
  this: java.awt.Point =>
  override def compare(that: java.awt.Point): Int =
    if this.x != that.x then if this.x < that.x then -1 else 1
    else if this.y == that.y then 0 else if this.y < that.y then -1 else 1

Cosa fa. Ordine lessicografico sui punti: prima per x, a parità per y. Restituisce −1, 0, 1. this: java.awt.Point => permette di usare x e y dentro il trait. Uso: new java.awt.Point(0,1) with OrderedPoint.

Perché getOrElse ha B >: A e default: => B? Scrivi map2 con for e senza. Quando si usa flatMap invece di map? Cosa restituisce sequence(List(Some(1), None))?
