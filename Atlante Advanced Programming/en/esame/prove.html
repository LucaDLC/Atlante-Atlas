Exam-style questions

Written for the atlas on the model of the course exercises: they are not official exams. Every solution was compiled with Scala 3.8.4.

1 · Counting with a fold

Implement, without explicit recursion, a function that counts the elements of a list that satisfy p.

def count[A](l: List[A])(p: A => Boolean): Int = ???
Show the solution
def count[A](l: List[A])(p: A => Boolean): Int =
  l.foldLeft(0)((acc, a) => if p(a) then acc + 1 else acc)

z = 0 (empty list: zero elements). The step adds 1 only if p(a). count(List(1,2,3,4,5))(_ % 2 == 1) gives 3.

2 · The last element, perhaps

Implement lastOption with a fold, without pattern matching.

def lastOption[A](l: List[A]): Option[A] = ???
Show the solution
def lastOption[A](l: List[A]): Option[A] =
  l.foldLeft[Option[A]](None)((_, a) => Some(a))

Each step discards the accumulator and keeps the current element: at the end the last one remains. The type [Option[A]] is needed because None alone would have type None.type. Results: Some(9) for List(7, 8, 9), None for the empty list.

3 · Filtering and transforming together

Given a function that can fail, keep only the successful results.

def filterMap[A, B](l: List[A])(f: A => Option[B]): List[B] = ???
// filterMap(List("1", "x", "3"))(_.toIntOption) == List(1, 3)
Show the solution
def filterMap[A, B](l: List[A])(f: A => Option[B]): List[B] =
  l.foldRight(List.empty[B])((a, acc) => f(a).map(_ :: acc).getOrElse(acc))

foldRight keeps the order. If f(a) is Some(b), map puts it in front of the rest; if it is None, getOrElse returns the rest unchanged.

4 · Depth of a tree

Using fold on the trees of week 3, compute the depth: a leaf has depth 0, a branch 1 + the depth of the deeper child.

Show the solution
def depth[A](t: Tree[A]): Int =
  fold[A, Int](t)((l, r) => 1 + (l max r))(_ => 0)

g for the leaves: 0, ignoring the value. f for the branches: 1 plus the maximum of the two. depth(Branch(Branch(Leaf(1), Leaf(5)), Leaf(3))) gives 2.

5 · forAll on Option without pattern matching

Implement forAll (true if the Option is empty or if the value satisfies p) using only map and getOrElse.

Show the solution
def forAll[A](o: Option[A])(p: A => Boolean): Boolean =
  o.map(p).getOrElse(true)

map(p) turns Some(a) into Some(p(a)). On None, "for all elements" is vacuously true: default true.

6 · What does it print?

def twice(x: => Int): Int = x + x
def twiceLazy(x: => Int): Int =
  lazy val y = x
  y + y

println(twice({ println("hi"); 1 }))
println(twiceLazy({ println("hi"); 1 }))
Show the solution
hi
hi
2
hi
2

twice: x is by-name and appears twice, so the block is run twice. twiceLazy: the lazy val computes it once and then remembers it.

7 · An infinite list with unfold

Implement iterate: the LazyList a, f(a), f(f(a)), …, using unfold.

Show the solution
def iterate[A](a: A)(f: A => A): LazyList[A] =
  unfold(a)(x => Some((x, f(x))))

The state is the current value: I emit it and the new state is f(x). Never None: the list is infinite. iterate(1)(_ * 3).take(4).toList gives List(1, 3, 9, 27).

8 · Variance

With class Cat extends Animal: does val o: Option[Animal] = Some(Cat()) compile? And val a: Array[Animal] = cats if cats: Array[Cat]? Why?

Show the solution

The first yes: Option[+A] is covariant, so Option[Cat] <: Option[Animal]. The second no: arrays are mutable and in Scala invariant (Found: Array[Cat], Required: Array[Animal]). If they were, you could write a Dog into an array of Cats.

9 · Open question, in English

Why is foldLeft on a strict List tail-recursive while foldRight is not? When would you still prefer foldRight?

Show a model answer

"In foldLeft the combining function is applied before the recursive call, so the call is the last thing the function does and the compiler can turn it into a loop with constant stack space. foldRight must first compute the result for the tail and only then apply f to the head, so each element leaves a pending call on the stack. I would still use foldRight when the result must preserve the order of the list, for example when building a list with Cons, and on lazy lists, where f may return without forcing the rest and the fold can stop early."
