Week 9

Monad: unit and flatMap

The monad is the most general concept of the week: a type with unit (putting a value inside) and flatMap (chaining calculations that depend on the previous value). Option, List, LazyList, Gen, Parser and State are all monads.

The Monad trait

In the slides the trait is this (simplified):

trait Monad[F[_]] extends Functor[F], with two methods:

  • unit[A](a: => A): F[A]: puts a value inside the container. For Option it is Some(a), for List it is List(a). The type => A means that the argument is passed by name, that is evaluated only when needed.
  • flatMap[B](f: A => F[B]): F[B]: takes the value inside the container and passes it to f, which chooses the next calculation based on that value. f already returns a container, and flatMap flattens it into one only.

From these two one gets map: fa.flatMap(a => unit(f(a))). That is why a monad is also a functor: the trait extends it.

The slides note that the name could be FlatMappable: a container on which you can chain calculations, where each step depends on the value of the step before.

The laws

The laws (from the slides and the book) concern unit and flatMap:

  • Left identity: unit(y).flatMap(f) === f(y);
  • Right identity: x.flatMap(unit) === x;
  • Associativity: x.flatMap(f).flatMap(g) === x.flatMap(a => f(a).flatMap(g)).

The laws are read like this: unit is the neutral element of the chaining (like the 0 of the monoid), and flatMap is associative. On the slides they are written as ScalaCheck properties, as for the monoid.

sequence: the generalised zip

sequence(lfa: List[F[A]]): F[List[A]] takes a list of containers and returns a container of lists. For the List monad it means all the possible choices; for Option it means "all present or nothing". On the slides the result is described as a generalised n-ary zip: a zip of n containers instead of two.

The code of sequence is exercise 17 of the course: here you see only the behaviour.

replicateM and compose

replicateM(n, ma) repeats the container n times and collects the values in a list inside the container: F[List[A]]. The meaning changes with the monad, as the scene shows.

compose (Kleisli composition) combines two functions that return a container: f: A => F[B] and g: B => F[C] give a new function A => F[C]. It is obtained with flatMap: you apply f, then pass the value inside to g. The implementation is exercise 19.

Where it is used

The code of unit, flatMap and of the examples with Option and List is in the side-by-side examples page. State, already seen in the week 5, is another monad: flatMap on State chains automata.

If an exercise asks you to "sequence" containers, think of flatMap and the laws: write which monad you are using and what behaviour you expect (all present, all the combinations, the first that fails).
