sequence (exercise 7)

In the recursive version case h :: t =>, the two names are born in the pattern: h is the first generator, t the list of all the others. After case, :: takes apart the list instead of building it.

_ :: _ is the short form of (a, b) => a :: b: each _ is a parameter, in the order it appears. It is the function that map2 uses to put the value of h in front of the list produced by the others.

List.fill(0)(int) and also List.fill(-3)(int) give the empty list, and sequence(Nil) is unit(Nil): the base case is already inside sequence. ints2(0)(SimpleRNG(42))._1 = List() (checked).

It is your first idea: if n >= bound then nonNegativeLessThan(bound) else unit(n). If it ends, the result is right (a number < bound), but it almost never ends.

With bound = 6 and SimpleRNG(42): first number 16159453 → it is ≥ 6 → retry. The numbers < 6 are 6 out of 2³¹ = 2147483648: on average about 358 million attempts are needed. Each attempt is a call inside another (flatMap → g → nonNegativeLessThan → flatMap …) and the stack runs out much earlier.

The solution: do not discard 16159453, reduce it with the remainder. 16159453 % 6 = 1, and the check 16159453 + 5 − 1 ≥ 0 is true → result (1, SimpleRNG(1059025964525)). One retries only in the little piece at the top, almost never.

def nonNegativeLessThan(bound: Int): Rand[Int] =
  flatMap(nonNegativeInt) { n =>
    if n >= bound then nonNegativeLessThan(bound) else unit(n) }

% is the remainder of the division (17 % 6 = 5, because 17 = 6 × 2 + 5). It is not in the slides, but it is already in the exercise file: nonNegativeEven does i - i % 2. If you do not like it, you can use double of exercise 2, which gives a number in [0, 1):

def nonNegativeLessThan(bound: Int): Rand[Int] =
  flatMap(double) { d => unit((d * bound).toInt) }

d * bound lies in [0, bound); .toInt cuts off the decimals (it does not round), so the result goes from 0 to bound − 1. With SimpleRNG(42): d = 0.0075…, × 6 = 0.045…, toInt = 0. The highest case: 0.99999… × 6 = 5.99999…, toInt = 5, never 6. All 44 tests pass (checked). It never retries, so flatMap is not indispensable here (map would suffice), and it has the same small imbalance as the plain %. Five dice from SimpleRNG(42): 1, 4, 1, 6, 5.

In plain words: (1) write flatMap, that is a map in which the function returns a generator instead of a value; (2) use it to make a die with bound faces: a random number between 0 and bound − 1. The tests check only that the result is ≥ 0 and < bound.

double or nonNegativeInt: from the same SimpleRNG(42) come out 16159453 (nonNegativeInt) and 0.0075248… (double), which is 16159453 / 2147483648. They are the same number on two different scales. The trick "× 6 then toInt" works only on the small scale [0, 1). On the large scale: 16159453 × 6 = 96956718, which is not a die, and Int.MaxValue × 6 = −6 (overflow). A large number must be scaled down, and for that % is needed: 16159453 % 6 = 1. So: with nonNegativeInt one uses %, with double one uses × bound and .toInt.
