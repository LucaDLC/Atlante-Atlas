Working on lists

tail, drop, dropWhile, init, append: five functions of exercises 2–5 that teach you to go through a list with pattern matching. And to understand how much each costs, because a list can only be read from the beginning.

tail: removing the first, without copying

Because it would confuse two different things: "the list had one element, its tail is empty" and "you gave me an empty list, it makes no sense to ask for the tail". The tests of the exercise check precisely that the exception is thrown.

init: the awkward operation

Removing the last element is hard for a list: you must reach the end and rebuild all the cells traversed.

append: joining two lists

def append[A](l1: List[A], l2: List[A]): List[A] = l1 match
  case Nil => l2
  case Cons(h, t) => Cons(h, append(t, l2))

Nil, None e null

Which "empty" to use: Nil for the empty list, None for the result that may not be there, null only as a value that arrives from Java and must be converted at once with Option(x). Explanation and comparison in the dedicated page.

Typical errors

def init[A](l: List[A]): List[A] = l match
  case Nil => Nil
  case Cons(h, t) => if t == Nil then h else init(h)
Found:    (h : A)
Required: List[A]
h è un elemento, ma init deve restituire una lista e riceve una lista. Ricostruisci: Cons(h, init(t)), con il caso Cons(_, Nil) => Nil sopra.
def length[A](l: List[A]): Int = l match
  case Nil => Nil
  case Cons(_, t) => 1 + length(t)
Found:    (List.Nil : List[Nothing])
Required: Int
Ogni caso deve dare il tipo di ritorno. La lunghezza della lista vuota è il numero 0, non la lista Nil.
