A fold written with the other

Exercises 10 and 11 of week 2. The first is solved by reversing the list. The second, for the exercise sheet "perhaps the hardest of the course", requires a new idea: instead of accumulating a value, you accumulate a function and run it at the end.

Exercise 10: foldRight with foldLeft

foldRight combines starting from the last element, foldLeft from the first. If I reverse the list, the first of the reversed list is the last of the original.

Advantage: it is in tail position, so it does not exhaust the stack on long lists. Disadvantage: it traverses the list twice.

Before exercise 11: a function as accumulator

The new idea, on a small example. Instead of calculating right away, I note down what to do, composing functions. Then I run everything at once.

Building the functions in one order, you run them in the opposite order. foldRight builds starting from the last element: if it accumulates functions, it will run them starting from the first. Which is exactly the order of foldLeft.

Exercise 11: foldLeft with foldRight

The text says it: do not use reverse here. reverse is a special case of foldLeft, so using it would mean writing foldLeft using foldLeft.

Typical error

def foldLeft1[A, B](l: List[A], z: B, f: (B, A) => B): B =
  def aiuto(x: B): B = f(x, ???)
Found:    Unit
Required: B

Maybe the enclosing block is missing a final expression after the definition of `aiuto`?
Un blocco che finisce con un def non ha un valore. Dopo le definizioni interne serve un'espressione finale che le usi. Spesso la causa è l'indentazione: la riga con foldRight(…)(z) è finita dentro il def precedente, o è stata dimenticata.
