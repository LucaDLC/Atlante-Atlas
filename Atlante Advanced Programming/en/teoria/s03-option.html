Option: no exceptions

Some functions have no answer for certain inputs: the mean of an empty list, the first element of nothing. Instead of throwing an exception, you make it return an Option: Some(result) if there is one, None if there is not. The first assessed delivery of the course is on this.

Partial and total functions

A function f : A → B is total if for every a in A there exists a result in B. If for some input there is no answer (crash, exception), it is partial.

Why not exceptions? An exception is not a value: it breaks referential transparency and does not appear in the type. The only advantage of exceptions, the slides say, is being able to handle the error far from where it happens. Option keeps this advantage (you see it in the chain below) without the defects.

Option is an algebraic type

enum Option[+A]:
  case Some(get: A)
  case None

Two shapes, as with the list: Some contains a value, None nothing. None has type Option[Nothing] and thanks to the +A it works as Option[Int], Option[String]… (variance).

The standard library uses it everywhere: Map.get(key): Option[V], List.headOption, List.find(p).

The API: map, flatMap, filter, getOrElse

Exercise 6: written as methods inside the enum, with pattern matching. It is your solution.

A chain that can fail

The real advantage: you write the steps as if everything went well. If a step fails, the None goes through the rest without doing harm, and you decide what to do at the end.

In the slides you find "the Option monad". For now, informally: a type that acts as a container with a context (here: "perhaps there is nothing") and has map and flatMap to chain steps without checking the context every time. List is monadic, Option is monadic. The precise definition comes in week 9.

Either: failing with a message

None says that something went wrong, but not what. Either carries the information about the error, as an exception would.

enum Either[+E, +A]:
  case Left(value: E)    // errore
  case Right(value: A)   // risultato corretto ("right" = giusto)

def mean(xs: List[Double]): Either[String, Double] =
  if xs.isEmpty then Left("lista vuota")
  else Right(xs.sum / xs.length)

Nil, None e null

Which "empty" to use: Nil for the empty list, None for the result that may not be there, null only as a value that arrives from Java and must be converted at once with Option(x). Explanation and comparison in the dedicated page.

Typical errors

def filter(p: A => Boolean): Option[A] = this match
  case Some(a) if p(a)  => this
  case Some(a) if !p(a) => None
  case None             => None
match may not be exhaustive.

It would fail on pattern case: Option.Some(_)
Il compilatore non sa che p(a) e !p(a) coprono tutto. Con -Werror è un errore. Metti l'ultimo caso senza guardia: case _ => None.
