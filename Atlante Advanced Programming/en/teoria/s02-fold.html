foldRight and foldLeft

A fold reduces a list to a single value: you start from an initial value z and combine the elements one at a time with a function f. It is the for loop of functional programming. The two folds differ only in the direction in which they put the brackets.

The ingredients

Think of how you would sum a list in Java: a variable starting from 0, a loop, a +=. A fold has the same pieces, but without a variable.

Choose z by asking yourself: "what must the fold of an empty list be worth?" Sum → 0. Product → 1. Length → 0. Constructed list → Nil.

foldLeft: the accumulator goes forward

foldRight: the operations wait

With subtraction the result changes

With + the order of the brackets does not matter. With - it does: that is why the two folds are really different.

The two signatures, compared

What do I put as arguments? Three examples

The procedure is always the same: 1) what is worth on the empty list → z; 2) given the accumulator and an element, how do I update → f.

def product(as: List[Int]): Int = foldLeft(as, 1, _ * _)       // z = 1, mai 0
def map[A, B](l: List[A], f: A => B): List[B] =
  foldRight[A, List[B]](l, Nil, (a, z) => Cons(f(a), z))       // dalla testa del file

The exercise sheet: "from now on explicit recursion is a bad smell". Use a dedicated function (map, filter…) if it exists; a fold only if those are not enough; hand-written recursion only for non-standard iterations.

The course's preferred style (slide 11)

For each exercise the course asks for the best style you know how to use. The slide puts in a row, from "condemned" (makes you fail) to "enlightened" (high grade): variables against values, assignments against value bindings, return against the value of the expression, Any/Object against parametric polymorphism, exceptions against Option or Either.

For iteration the scale is long: loops, then tail recursion, then simple recursion, then fold, then dedicated higher-order functions composed together (map, filter, flatMap…). To decide: if, then pattern matching, then a dedicated API. Tail recursion and fold remain right when the exercise asks for them explicitly or when memory (the stack) matters. It is the same rule as the exercise sheet: "from now on explicit recursion is a bad smell".
