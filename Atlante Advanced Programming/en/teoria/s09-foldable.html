Foldable: reducing with a monoid

A fold reduces a collection to a single value. If the operation is a monoid, the result no longer depends on the order and the groupings: the work can be reordered, or split among several processors.

From the fold to the monoid

foldLeft(z)(f) takes an initial value z and an operation f, and reduces the collection from the left; foldRight(z)(f) reduces from the right. With any operation the direction counts. Example with subtraction on List(1, 2, 3):

  • foldLeft(0)(_ - _) does ((0 − 1) − 2) − 3 = −6;
  • foldRight(0)(_ - _) does 1 − (2 − (3 − 0)) = 2.

With a monoid, z is the neutral element and f is combine. The associativity makes the grouping irrelevant, and the neutral element makes the starting value harmless. That is why foldLeft and foldRight give the same result on the sum.

foldMap: map and then reduce

The signature is def foldMap[B: Monoid](f: A => B): B. Read it this way:

  • f: A => B transforms each element into a value of another type B;
  • [B: Monoid] says that B is a monoid: there is an instance of Monoid[B] to use for combining;
  • the result is a single value of type B.

In practice foldMap is map(f) followed by concatenate. The type B can be different from A: here A = Int and B = Int, but in other cases B is a string, a length, a maximum. The implementation of foldMap is exercise 5 of the course: here you see the idea.

F[_]: the container is a parameter

In Foldable[F[_]] the letter F is not a type, but a type constructor: a rule that, given a type A, produces a type such as List[A], Option[A], Tree[A]. The symbol [_] says that F takes a type as argument. It is called a higher-kinded type.

Why it is useful: a single interface covers all the containers. Lists, options, trees, LazyList and iterators are all foldable: they can be reduced with the same foldMap.

concatenate and reductions in pieces

concatenate(as) reduces a collection of values already in a monoid: it starts from the neutral element and combines all the elements with combine. It is the basis of the fold: foldLeft(m.empty)(m.combine).

The advantage of the monoid is that the work can be split. Each piece reduces to a value, and the values are recombined. On several processors it is the principle of MapReduce (used by Spark): each worker does its part, then the partial results are combined.

Parallelism works only if the type really is a monoid. With subtraction, splitting the list changes the result: the compiler does not signal it.
