Strict, by-name, lazy

When is the argument of a function computed? Before entering (strict), every time you use it (by-name), or the first time you use it and then no more (lazy). Scala has all three, and the LazyLists of this week rest on the last two.

The trap of the poll

val a = 42
val res = if2(a < 22, () => println("a"), () => println("b"))

What is res worth? Answer: () — the Unit value. 42 < 22 is false, so the recipe of the false branch is run, which prints "b". But println returns Unit, so res = () (checked: res = ()). Printing is an effect, not the value.

lazy val: computes once, then remembers

A by-name parameter is recomputed every time you use it. If you want to compute it only once, put it in a lazy val.

The three strategies, defined

The arguments are computed before the call; in the body their value is substituted.

The arguments are not computed: in the body the expression itself is substituted, and it is computed at each use.

Lazy = call-by-name + memory: the expression is computed at first use and the result is reused afterwards.

f(x) is strict if, for every expression x that does not terminate or fails, f(x) also does not terminate or fails. if, && and || are not strict: false && crash() is false.

In a pure program the three strategies give the same result: only time and memory change. With effects (prints, random numbers) the results become different, which is why laziness is used with pure code.

What it is for

  • Non-strict functions: the default of getOrElse(default: => B) is computed only with None.
  • Large data: computing only the parts that are really needed.
  • Generators: the infinite list of naturals, of prime numbers, of random numbers (the LazyLists).
  • Separating what from how: you describe a large calculation and run only the piece you need.
