Lazy foldRight

On ordinary lists foldRight always consumes everything. On a LazyList no: the function receives the rest as a recipe, and if it does not use it the fold stops. That is why it works also on infinite lists, and it is the basis of exercises 6–9.

map, filter, append, flatMap (exercise 8)

All with foldRight, without explicit recursion. The trick is always the same: build with cons, so that the rest (acc) stays a recipe.

No, they are different things. A is a type: the type of the elements, born in enum LazyList[+A] and valid for all methods. this is a value: the list on which you call the method, of type LazyList[A]. On LazyList(1, 2, 3).map(…): this = the list (1, 2, 3), A = Int.

B instead does not exist until you declare it in square brackets after the name: def map[B](…). It is chosen by the f at each call: map(_ * 2) → B = Int, map(_.toString) → B = String.

With foldRight z ends at the bottom: it is what is there when the list ends. So in append that goes after this:

LazyList(1, 2).append(LazyList(8, 9))
= f(1, f(2, that))  =  cons(1, cons(2, that))   // List(1, 2, 8, 9)

For map, filter and flatMap "what is there when the list ends" is empty; only for append is it that.

Exercise 9: why find with filter is fine here

def find(p: A => Boolean): Option[A] = this.filter(p).headOption

On LazyList

from(0).find(_ > 2): filter builds the result lazily, headOption asks only for the first. Computed 0, 1, 2, 3 and that is all (checked).

On List

List(1, 2, 3, 4).filter(_ > 2).headOption: filter is strict, it checks all 4 elements and builds a whole list, then one of them is used (checked by printing).

"On a lazy list, filter does not traverse the whole list: it only produces elements when they are demanded. headOption demands just the first one, so find stops as soon as it meets the first element satisfying p. On a strict List, filter would first test every element and build a new list, only to keep its head, which wastes time and memory, and would not terminate on an infinite structure."

find may find nothing, so it returns an Option: LazyList(1, 2, 3).find(_ > 10) → None. Inside Some there is the element found, not the condition: find(_ > 2) → Some(3). Some(x > 2) would be Some(true): an Option[Boolean].

It is the first element that satisfies p: LazyList(1, 2, 3, 4).find(_ > 2) → Some(3), the 4 is not even looked at. If you only need to know whether one exists, there is exists, which gives true/false.
