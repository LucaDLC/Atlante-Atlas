From loop to recursion

Without var and without for, you repeat a calculation with a function that calls itself on a smaller problem. Here you turn a loop into recursion one step at a time, and see when the recursion is "tail".

The recipe: from while to recursion

It is the file 01-intro/Purification.scala. You start from an imperative factorial and "purify" it. Follow the colours: each variable becomes a parameter.

The simplest version, and how it unrolls

For the factorial there is also a direct recursion, copied from the mathematical definition n! = n · (n − 1)!:

def factorial(n: Int): Int =
  if n <= 1 then 1
  else n * factorial(n - 1)

Tail recursion

A call is in tail (in tail position) when the caller returns its result straight away, without doing anything more on it.

Not in tail

else n * factorial(n - 1)

After the call there remains to multiply by n.

In tail

else f(n - 1, n * acc)

The result of the call is the result. The multiplication has already been done, in the argument acc.

The trick to go from one to the other has a name: the accumulator parameter. Instead of combining the results while you go back, you combine them while you go forward and carry the partial result with you.

The compiler turns a tail recursion into a loop, with constant space. With @annotation.tailrec you ask it to check that it really is tail: if it is not, it does not compile.

The exercise sheet says it clearly: do not insist on tail recursion if it is not required. The course prefers simplicity. It is needed when there is a real risk of running out of stack.

Fibonacci: why @tailrec did not accept your version

In the first version of exercise 3 there were two recursive calls added together. The compiler rejects it:

def fib(n: Int): Int =
  @annotation.tailrec
  def bonacci(n: Int, acc: Int): Int =
    if n == 1 then acc
    else if n == 2 then 1
    else bonacci(n-1, acc) + bonacci(n-2, acc)
  bonacci(n, 0)
Cannot rewrite recursive call: it is not in tail position
Dopo le due chiamate resta da fare il +: nessuna delle due è in coda. E anche senza @tailrec sarebbe lentissima, perché ricalcola gli stessi numeri moltissime volte.

The solution: to compute the next number you need only the last two. Carry them with you as parameters and go on.
