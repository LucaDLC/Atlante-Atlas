Infinite lists and unfold

Exercises 1, 10–13. An infinite list is defined by a function that calls itself in the tail: thanks to cons the call does not start until it is needed. unfold generalises the idea: from an initial state and a rule "next value and next state" it generates the whole list.

ones, from, to, naturals

On ordinary lists it would be an infinite loop. Here not: each call builds one cell and stops. The next cell is born only when someone forces the tail. naturals.toList instead never terminates: it wants everything.

fibs: infinite Fibonacci (exercise 10)

Same idea as week 1: for the next number the last two are enough. Here however I do not return a number: I produce the list of all of them.

lazy val fibs: LazyList[Int] =
  def go(a: Int, b: Int): LazyList[Int] = cons(a, go(b, a + b))
  go(0, 1)

unfold: the general generator (exercise 11)

def unfold[A, S](z: S)(f: S => Option[(A, S)]): LazyList[A]

Why unfold?

It does the same thing as the recursion written by hand, but the recursion is written by it: you describe one step only.

By hand

def map[B](f: A => B): LazyList[B] =
  this match
    case Cons(h, t) =>
      cons(f(h()), t().map(f))
    case Empty => empty

With unfold

def mapUnfold[B](f: A => B): LazyList[B] =
  unfold(this) {
    case Cons(h, t) =>
      Some((f(h()), t()))
    case Empty => None
  }

Two things change: where you wrote cons(valore, <ricorsione>) you write Some((valore, nuovoStato)); where you wrote empty you write None. cons and the recursive call are put by unfold, in its last line: case Some((a, s)) => cons(a, unfold(s)(f)).

foldRight consumes a list and gives a value (exercise 8). unfold starts from a value (the state) and builds a list (exercise 13). In both cases you do not write the recursion: in the course's style scale it is the step from forgivable to enlightened.
