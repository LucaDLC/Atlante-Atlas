Nil, None, null: when to use them

Scala has three ways of saying "nothing", and they are not interchangeable. Nil is an empty list, None is an Option without a value, null is Java's empty reference. This page says which one to use, and when not to use it.

The problem: a value is missing

Sometimes a function has no result to return: the search finds nothing, the list has no elements, a datum is missing. There are three different questions, and each has a different type:

  • is the collection empty? Answer: Nil, which is a list with no elements;
  • can the result be missing? Answer: Option[A], with Some(value) or None;
  • am I talking to a Java library that returns an empty reference? Answer: null, which however must be converted at once.

Nil: the empty list

Nil is the list with no elements. It is the base case of the lists built with ::: the list 1 :: 2 :: Nil is List(1, 2), and the Nil at the end says where it ends. In pattern matching one writes case Nil => … for the case of the empty list.

When to use it: to build lists and to recognise the end of a recursive list. An empty list is a valid result: if a function returns "no elements", Nil is the right answer, not None.

Do not confuse Nil with None. An empty list is a list: you can still call isEmpty, map, foldLeft. None instead is not a list: it is the absence of a result.

None: the result that may be missing

Option[A] has two shapes: Some(a), which contains a value, and None, which says "no value". A function that can fail returns an Option instead of throwing an exception or returning null.

When to use it: every time the answer may not exist (a search, a division by zero, an optional field). The caller is forced to handle the None case, because the type is Option and not A.

Do not return None to say "empty list": if the function produces a list, the empty list is Nil. Use None only when "no result" is information different from "zero elements".

null: Java's emptiness

null is Java's empty reference. Scala accepts it to talk to Java libraries, and in Scala 3 it is a possible value for almost every reference type, even String. The problem: if you use a null (for example you call .length), the program throws a NullPointerException, and the compiler does not warn you.

When to use it: almost never in Scala. Only when a Java library returns null: at that point you convert at once with Option(x), which gives None if x is null and Some(x) otherwise.

The comparison None == null gives false: they are different values. Do not write if x == null in new Scala code: use Option and match.

At the exam

When you write a function that may not find a result, declare the type Option[A] and explain in one sentence why None and not an empty list or an exception. Do not use null in Scala solutions.
Use None when a result may be absent; use Nil for an empty list, which is a valid result; convert Java null to Option at the boundary.
