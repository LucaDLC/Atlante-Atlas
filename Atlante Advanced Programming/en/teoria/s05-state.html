State[S, A]: the general pattern

Week 5, exercises 9–11 and slides. None of what we did with Rand depends on the state being a number generator: it holds for any state. State[S, A] is a transition: from a state S it produces a value A and the next state. It is a monad, like Option and LazyList.

From Rand to State

The API of State (exercise 9)

You have already written map, map2, flatMap, sequence for Rand (state = RNG). Rewrite them identical for any state S. Only two things change: the function now sits in a box, so one builds it with State { s => … } and runs it with .run(s).

Image: the ticket machine of the turn (the same as ex. 10–11). The display is the state; run = you tear off a ticket and the display advances. All of exercise 9 is a single rule: whoever comes after starts from the display left by whoever comes before.

Variant written like your ex. 7 (all 44 tests pass also like this):

def map2[B,C](sb: State[S, B])(f: (A, B) => C): State[S, C] =
  flatMap(a => sb.map(b => f(a, b)))

def sequence[S,A](sas: List[State[S, A]]): State[S, List[A]] = sas match
  case Nil => unit(Nil)
  case h :: t => h.map2(sequence(t))(_ :: _)

With get, set, modify and for/yield the code with State looks imperative ("read the state, change it"), but it remains pure: it is only the description of a transition, which starts when run is called.

Composing automata: map, flatMap, map2 (slides 11–13)

State is a monad: it has the same key operations as List, Option and LazyList. Thinking of a State as an automaton, these operations serve to build new automata from existing ones, without ever writing by hand the passing of the state.

map changes the values produced and leaves the transition as it is: val even: Rand[Int] = int.map(n => n * 2) is a generator of even numbers. flatMap uses the value produced to choose the next automaton: int.flatMap(n => ints(n)) generates a list of random length, and the length is drawn with a state different from that of the numbers, because flatMap passes on the new state. map2 "zips" two automata on the same space of states: with C = (A, B) it is the product automaton, which advances two calculations in step. sequence lines up a list of automata.

Slide 8 summarises why it is needed: everything that has a state is written with this pattern. A random number generator (state: the seed), a site with a session (state: the session), an application with a database (state: the database), a communication protocol (state: the phase of the protocol). And one always composes with the same four tools.

States and lazy lists (exercises 10–11)

Ex. 10: you have an automaton (a State) and a starting state. Run it forever and line up the values that come out, in a LazyList. Ex. 11: the random number generator is an automaton too (state = RNG, step = nextInt): put it in a State, pass it to ex. 10 → infinite list of random numbers; then take 10 of them in an ordinary List.

Image: the ticket machine of the turn. The state is the number on the display; run = you tear off a ticket: it gives you the number and the display advances. The LazyList is the roll: a ticket is printed only when someone tears it off (take).

def stateToList[S, A](s: State[S, A])(initial: S): List[A] =
  val (a, next) = s.run(initial)
  a :: stateToList(s)(next)
