Week 9

Monoid: combine and have a neutral element

The first of the four concepts of the week (monoid, foldable, functor, monad). A monoid is the simplest thing that can be reduced in pieces: an operation that combines two values and a value that changes nothing. From here come folds and parallel reductions.

Definition

A monoid on a type A has two parts:

  • a binary operation ⊕, in Scala combine: it takes two values of A and returns one. The symbol ⊕ means "combine".
  • a neutral element 0, in Scala empty: a value of A that, combined with another value, does not change it.

Examples from the slides, written as a triple (type, neutral, operation):

The two laws

For the combination to be useful, combine and empty must respect two laws, for every value x, y, z of A:

  • Associativity: (x ⊕ y) ⊕ z = x ⊕ (y ⊕ z). It does not matter where you put the brackets. This allows splitting a list into two halves and reducing them separately.
  • Identity (neutral): x ⊕ 0 = x and 0 ⊕ x = x. The neutral element changes nothing on either side.

The Scala compiler does not check these laws: it accepts any combine. The laws are checked with tests (property-based, see Property-based testing).

Associativity does not mean commutativity. The monoid does not require x ⊕ y = y ⊕ x: subtraction is not a monoid because it is not associative: (5 − 3) − 1 ≠ 5 − (3 − 1). Strings with concatenation are a monoid, even though "ab" ≠ "ba".

The type class in Scala

A type class is an interface parameterised on the type. Monoid[A] describes how a type A behaves, without A having to "know" that it is a monoid. Each instance is a value that is passed together with the data.

Instances: one value for each type

To make String a monoid you write a value of type Monoid[String]. An instance is a value: it is created by instantiating the trait.

Write val stringMonoid: Monoid[String] = new Monoid[String]: …, with combine and empty inside. The type after the colon says which type is becoming a monoid.

Homomorphisms and isomorphisms

A homomorphism between a monoid (M, ⊕, 0) and a monoid (N, ⊗, 1) is a function f: M → N that respects the structure:

  • distributivity: f(x ⊕ y) = f(x) ⊗ f(y) for every x, y in M;
  • neutral: f(0) = 1.

So you can combine first and apply f afterwards, or apply f first and combine afterwards: the result is the same. Example from the slides: f(s) = s.size from String (with concatenation and "") to Int (with + and 0). It holds that "foo".size + "bar".size = ("foo" + "bar").size.

An isomorphism is a homomorphism in both directions: f and its inverse g are both homomorphisms. Examples from the slides:

  • String and List[Char], with toList and mkString: one moves from one to the other without losing information;
  • (Boolean, false, ||) and (Boolean, true, &&), with negation: De Morgan's law says ¬(x ∨ y) = ¬x ∧ ¬y, and ¬false = true.
If two monoids are isomorphic, a calculation done in one can be carried over to the other. This is why a string and a list of characters are treated the same way in calculations in pieces.

Where it is used

The monoid is the minimal condition to reduce a collection in any order and in pieces. On the next page you will see the fold and foldMap built on a monoid. The code of the concepts is in the side-by-side examples page.
