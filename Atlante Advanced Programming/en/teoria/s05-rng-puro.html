Random numbers without effects

Week 5, exercises 1–4 (chapter 6 of the book). An ordinary random number generator has a hidden state that changes at every call: it is not pure. The functional solution is to make the state explicit: each call receives the state and returns a new one. It is the first step towards the State monad.

Each call has its own variables r1 and r2 — same names, different boxes — but the value that comes out is the same at all levels: the state born after the last number drawn, which climbs back up.

ints(3)(G0):   r1 = G1  →  chiama ints(2)(G1)
  ints(2)(G1):   r1 = G2  →  chiama ints(1)(G2)
    ints(1)(G2):   r1 = G3  →  chiama ints(0)(G3)
      ints(0)(G3):            →  (Nil, G3)
    ints(1):  r2 = G3       →  (i1 :: Nil, G3)
  ints(2):    r2 = G3       →  (i2 :: …,  G3)
ints(3):      r2 = G3       →  (i3 :: …,  G3)

It must be the last: whoever calls ints(3) and then wants other numbers must restart from after the three already used. Returning r1 would make the second number come out again.

All these functions have the form RNG => (A, RNG), and all share the same tedium: take the state, call, extract the pair, pass the new state. The next page gives a name to this form, Rand[A], and hides it: Rand[A]: composable generators.
