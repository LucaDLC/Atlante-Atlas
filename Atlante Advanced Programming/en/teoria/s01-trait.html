Traits and mixins

A trait is a piece of class that you can add to several classes: it can have methods already written, methods to complete, and fields. A class can "mix in" as many as it wants. In exercise 1 of week 3 you use it to add < to a Java class.

From Java to Scala

In Java a class has only one parent, but it can implement several interfaces. A trait is like a Java interface that can also contain code and fields.

Exercise 1, week 3: OrderedPoint

Goal: to be able to write p < q between two java.awt.Point, a Java class that you cannot modify. The Scala library already has the trait Ordered[T]: if you write the method compare, it gives you <, >, <=, >=.

trait OrderedPoint extends scala.math.Ordered[java.awt.Point]:
  override def compare(that: java.awt.Point): Int =
    if this.x < that.x then -1 else 1
value x is not a member of OrderedPoint
Senza this: java.awt.Point => il trait non sa di essere dentro un Point, quindi this.x non esiste.

It works only if you create the object yourself, because you must write with OrderedPoint. A Point that reaches you already made by a library does not have the trait. The exercise sheet announces that later the type classes will be seen, which solve exactly this.

Two traits with the same method: who wins?

If two traits redefine the same method, Scala puts them in a row: the one on the right wins, and super passes to the next one in the row.

trait Base:
  def saluta: String = "Base"
trait A extends Base:
  override def saluta: String = "A>" + super.saluta
trait B extends Base:
  override def saluta: String = "B>" + super.saluta

class X extends A, B     // X().saluta == "B>A>Base"
class Y extends B, A     // Y().saluta == "A>B>Base"

Results checked by compiling. In the course it is enough to know the rule "the rightmost wins".
