Week 9

Functor: map on every container

Lists, options, generators, parsers, trees: they all have a map with the same shape. The functor is the name of this common interface, and its law says that map does not change the structure.

The same shape, everywhere

In the previous weeks you wrote map several times. The signatures are almost identical:

containersignature of map
Gendef map[A,B](ga: Gen[A])(f: A => B): Gen[B]
Listdef map[A,B](la: List[A])(f: A => B): List[B]
Optiondef map[A,B](oa: Option[A])(f: A => B): Option[B]

State, Par, Parser and Tree follow the same pattern too. So one single interface can be written. The name Functor is the traditional one (the slides admit that Mappable would be clearer).

The Functor trait and its law

The trait has a type constructor F[_] (as in the foldable) and an extension map:

trait Functor[F[_]] with extension [A](fa: F[A]) def map[B](f: A => B): F[B]. The map takes an F[A], applies f to what is inside and returns an F[B].

The identity law (from the slides): fa.map(identity) === fa. With identity nothing changes, so the structure must not change. The composition law is the same idea with two functions: two maps in a row are equivalent to one map of the composition.

The compiler does not check the law. A map that does strange things (for example discards elements) compiles anyway, but it is not a functor.

distribute: a general unzipper

distribute takes an F[(A, B)] and returns a pair (F[A], F[B]): it separates the components. With a list of pairs it is an unzip. The definition uses only map:

(fab.map { _._1 }, fab.map { _._2 }).

map2: combining two containers

With a single map you cannot combine two containers: you need map2, which takes F[A] and F[B] and a function f(a, b). On the slides it is defined with flatMap for Option, List and Gen:

fa.flatMap(a => fb.map(b => f(a, b)))

It is the generalised "zip" (a kind of zipWith). For Option the behaviour is clear: if a value is missing, the result is missing. For lists and generators the meaning changes, and that is why the slide warns that each type has its own intuition.
