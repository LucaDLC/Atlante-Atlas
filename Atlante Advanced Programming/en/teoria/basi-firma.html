Reading a Scala signature

The first line of a function says what comes in and what comes out. If you can read it in pieces, from left to right, half of the exercise is already done: often the types also tell you how to write the body.

A signature, taken apart piece by piece

Let us take the function of exercise 4 of week 1. It checks whether an array is sorted, according to a criterion that you pass it.

def isSorted[A](as: Array[A], ordered: (A, A) => Boolean): Boolean =

The same signature in Java would be static <A> boolean isSorted(A[] as, BiPredicate<A,A> ordered). Scala puts the types after the names, uses [A] in place of <A> and writes the type of the function with an arrow instead of an interface.

When [A] is needed and when it is not

Put [A] only when the function does not need to know what type of elements it has in hand. If it works with real numbers, the type is fixed.

Without [A]

def abs(n: Int): Int =
  if n < 0 then -n else n

abs compares with 0 and changes the sign: it really needs Ints.

With [A]

def isSorted[A](as: Array[A],
    ordered: (A, A) => Boolean): Boolean

isSorted never compares the elements itself: it asks ordered. It works with numbers, strings, people.

Who decides what A becomes? Whoever calls. Look at what happens in a real call:

The type of a function: the arrow =>

To the left of the arrow there is what comes in, to the right what comes out. That is all.

TypeReads asA value of that type
Int => Booleantakes an Int, gives a Booleanx => x < 0
(Int, Int) => Inttakes two Ints, gives an Int(x, y) => x + y
(A, A) => Booleantakes two A, gives a Boolean(x, y) => x <= y when A = Int
A => Btakes an A, gives a B_.toString when A = Int and B = String
() => Atakes nothing, gives an A() => 42 (week 4)

f: A => B does not say what f does. It says only what shape it has: an A comes in, a B comes out. What it really does is decided by whoever passes the function at the moment of the call.

Arrows one inside the other

In exercise 5 this signature appears, which looks like a Russian doll:

def isSortedCurried[A]: Array[A] => ((A, A) => Boolean) => Boolean

Several parameter lists

A function can have several pairs of brackets. In the call you write the same number of them, in the same order.

If the definition has two lists and you call with only one, map(albero, f), it does not compile. Count the pairs of brackets in the definition.

Methods inside an enum: where does A come from?

From week 3 some functions are written inside the type, as methods. Then A is not among the square brackets of the method: it comes from the enum.
