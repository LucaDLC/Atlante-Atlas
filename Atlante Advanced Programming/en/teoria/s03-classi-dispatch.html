Classes and dynamic dispatch

Two object-oriented programming topics with which week 3 opens: the primary constructor (a Java class of 15 lines becomes one line) and dynamic dispatch (which method is really called when a subclass redefines it).

The primary constructor

In Scala the constructor parameters are written right after the class name. The whole rest of the class body is run when the object is created.

Scala

class Person(val name: String, val age: Int):
  println("Just constructed a person")
  def description =
    s"$name is $age years old"

The same in Java

class Person {
  private String name;
  private int age;
  public String name() { return name; }
  public int age() { return age; }
  public Person(String name, int age) {
    this.name = name;
    this.age = age;
    System.out.println("Just constructed a person");
  }
  public String description() {
    return name + " is " + age + " years old";
  }
}

Primary constructors are used with case class and with the cases of enum: Cons(head: A, tail: List[A]) is exactly a primary constructor.

Poll: dynamic dispatch in Java

class Printable            { void hello() { print("printable "); } }
class Triangle extends Printable { void hello() { print("triangle "); } }
class Square   extends Printable { void hello() { print("square "); } }

Square x    = new Square();
Printable y = new Triangle();

x.hello();
((Printable) x).hello();
y.hello();
((Printable) y).hello();

As in Java, Python and JavaScript, all instance methods are virtual: they are chosen on the basis of the real object. (In C# and C++ instead no, unless you declare it.)

What does it print? Answer: square square triangle triangle. The method is chosen on the basis of the real class of the object, decided with new, not on the basis of the type of the variable or of the cast. The cast (Printable) x only changes what the compiler lets you call, not the object.
