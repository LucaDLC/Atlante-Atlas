Testing the LazyList

Week 6, exercises 1–10. The role is reversed: the LazyList is already there, the test file is yours to write. The grader runs your tests on many broken LazyLists (the mutants): every mutant you make fail is worth points. The right LazyList, lazyList00, must pass all your tests, otherwise you lose 35%. Only Exercises.scala is handed in. Theory: Property-based testing.

Laziness: exercises 2, 3, 4, 7

These four exercises ask you to check what a function does not compute. A right result is not enough: one needs a list with bombs placed exactly where the function must not look. If the test finishes without explosions, it returns true.

  • Ex. 2: headOption does not force the tail → bomb in the tail: cons(n, bomba).
  • Ex. 3: take forces neither heads nor tails → one list of bomb-heads and one with a bomb-tail; one calls take(n) without looking at the result.
  • Ex. 4: take(n) does not force head number n+1, not even if you force the first n → n good elements and then a bomb; take(n).toList.
  • Ex. 7: drop(n) does not force the discarded heads, not even if you then force the rest → n bombs and then good elements; drop(n).toList.

In your file the bomb was written with 4 spaces in front, just below /* The test suite */. In Scala 3 indentation decides what is inside what, as in Python, and a comment closes nothing. The significant line before was Gen.const(loop), at 4 spaces, inside infiniteLazyList: so the bomb too ended up inside infiniteLazyList, invisible to the tests.

No: it is English, not Scala. "does not force any heads nor any tails" = "does not force no head and no tail". any in a negative sentence means "none"; Scala's type Any has nothing to do with it. Calling l.take(n) must not open even one envelope of the list l: the heads are computed only when someone reads the result (for example with toList), and that is ex. 4.

Show the solution (ex. 2, 3, 4, 7)
// liste con le bombe
def bombe: LazyList[Int] = cons(bomba, bombe)

def buoniPoiBomba(n: Int, i: Int = 1): LazyList[Int] =
  if n == 0 then cons(bomba, empty) else cons(i, buoniPoiBomba(n - 1, i + 1))

def bombePoi(n: Int, rest: LazyList[Int]): LazyList[Int] =
  if n == 0 then rest else cons(bomba, bombePoi(n - 1, rest))

property("Ex02: headOption does not force the tail") =
  forAll { (n: Int) => cons(n, bomba).headOption == Some(n) }

property("Ex03: take does not force heads nor tails") =
  forAll(genN) { n =>
    bombe.take(n)
    cons(1, bomba).take(n)
    true }

property("Ex04: take(n) does not force the (n+1)st head") =
  forAll(genN) { n => buoniPoiBomba(n).take(n).toList == List.range(1, n + 1) }

property("Ex07: drop(n) does not force dropped heads") =
  forAll(genN) { n => bombePoi(n, LazyList(1, 2, 3)).drop(n).toList == List(1, 2, 3) }

Read: exercises 5, 6, 8

property("Ex05: take(n).take(n) == take(n)") =
  forAll(arbitrary[LazyList[Int]], genN) { (l, n) =>
    l.take(n).take(n).toList == l.take(n).toList } &&

    l.take(n).take(n).toList == l.take(n).toList } &&
  forAll { (la: List[Int]) => forAll(genN) { n =>
    list2lazyList(la).take(n).toList == la.take(n) } }

property("Ex06: drop(n).drop(m) == drop(n + m)") =

  forAll { (la: List[Int]) => forAll(genN) { n =>
    list2lazyList(la).drop(n).toList == la.drop(n) } }

property("Ex08: map(identity) == l") =
  forAll { (l: LazyList[Int]) => l.map(identity).toList == l.toList }

Infinite lists: exercise 9

"map terminates on infinite lists": do map on an infinite list and then take a finite piece. If map is lazy, it computes only that piece; if it is strict, it tries to compute the whole list and never finishes (in practice: StackOverflowError, which counts as a failed test). The infinite lists are given by infiniteLazyList[Int], already in the file.

Show the solution (ex. 9)
property("Ex09: map terminates on infinite lists") =
  forAll(infiniteLazyList[Int], genN) { (l, n) =>
    l.map(_ + 1).take(n).toList == l.take(n).toList.map(_ + 1) }

append: exercise 10

Here you choose the properties. Three ideas: the oracle (append must do what ++ of the Lists does); the laziness (append receives that by name, so it must not compute it until it is needed); the infinite lists (what you attach after an infinite list is never seen).

property("append does not force its argument") =
  forAll { (l: LazyList[Int]) => l.append(bomba); true }
! testing.Ex10.02: append does not force its argument: Exception raised on property evaluation.

Fallisce sulla LazyList giusta: se l è vuota, l.append(that) è that, e restituirlo vuol dire calcolarlo. La proprietà vale solo per l non vuota: forAll(genNonEmptyLazyList[Int]) { l => … }. Errore mio, trovato provando il file su lazyList00: prova sempre i tuoi test sulla versione giusta.
Show the solution (ex. 10)
property("Ex10.01: append = ++ on lists") =
  forAll { (l1: LazyList[Int], l2: LazyList[Int]) =>
    l1.append(l2).toList == l1.toList ++ l2.toList }

property("Ex10.02: append does not force its argument (non-empty this)") =
  forAll(genNonEmptyLazyList[Int]) { l => l.append(bomba); true }

property("Ex10.03: infinite append anything = infinite") =
  forAll(infiniteLazyList[Int], genN) { (l, n) =>
    l.append(bomba).take(n).toList == l.take(n).toList }

The mutants: how to check your tests

We do not have the grader's mutants, but one can make them: copy lazyList00, break one function and see whether at least one test fails. I made 13; with the solution of this page they are all killed, and lazyList00 passes all 13 tests (checked).

Mutant (one function broken)Killed by
headOption computes the tail before answeringEx02
headOption returns the last instead of the firstEx02
take computes the heads at onceEx03
take computes the tails at onceEx03
take touches head n+1Ex03, Ex04
take does not stop: with n ≥ 1 it returns the whole rest of the listEx04, Ex05 (on the infinite list it never ends)
drop computes the discarded headsEx07
drop discards one element lessEx06, Ex07
strict map (computes the whole tail)Ex09
map loses the first elementEx08, Ex09
append ignores thatEx10.01
append computes that at onceEx10.02, Ex10.03
append puts that in frontEx10.01, Ex10.02, Ex10.03

1. Every one of your tests must pass on lazyList00: a wrong test that fails on the right version costs 35%. 2. Every requested function (headOption, take, drop, map, append) must have tests on both the result and the laziness: the mutants break one or the other.
