BFS: breadth-first visit

The BFS (breadth-first search, visit in breadth) explores the graph by layers: first all the nodes at distance 1, then at distance 2, and so on. It is the right algorithm every time the question is "how many steps at minimum".

The problem and the idea

The problem: from a source s I want to know which nodes I can reach and, for each, the minimum number of arcs (the distance, d(v)). The graph has no weights: each arc is worth 1.

The idea is a FIFO queue (first in, first out). The node that entered first leaves first. So the nodes come out in order of distance: first those at distance 0, then 1, then 2. It is the same as going down by layers from the source.

The steps, one by one

  1. Put s in the queue, d(s) = 0, mark s as seen.
  2. Extract the first node u from the queue.
  3. For each neighbour v not yet seen: d(v) = d(u) + 1, parent(v) = u, mark v and put it in the queue.
  4. Repeat from step 2 until the queue is empty.

The parent of a node is the node from which you discovered it. Following the parents backwards you rebuild the minimum path.

A node is marked as seen when it enters the queue, not when it leaves. If you mark it on exit, it can enter the queue several times and the BFS becomes slow, even though the result remains correct.

Why it works

The queue makes the nodes come out in non-decreasing order of distance. So the first time you meet a node v you arrive at it by the shortest possible path. Every arc of the undirected graph connects two nodes of layers that differ by at most 1: that is why no shorter path can escape the layers.

The queue is always sorted by distance, and a node more distant than one already in the queue plus one step is never added.

Cost and when to use it

Every node enters the queue once only, and every arc is looked at at most twice. Cost: O(n + m), linear in the size of the graph.

Use the BFS when the question is one of these:

  • reachability: "from s can I reach t?", "which nodes can I reach?";
  • minimum distance without weights: "the minimum number of moves", "the minimum number of passages";
  • connected components: a BFS for each node not yet visited;
  • bipartiteness: see the following section.

With weights different from 1 the BFS is wrong: use Dijkstra (weights ≥ 0) or Bellman-Ford (weights also negative).

The bipartiteness test

A graph is bipartite if its nodes can be coloured with two colours without two adjacent nodes having the same colour. Equivalently: it has no cycles of odd length.

To check it, do a BFS and colour each layer with a different colour. If an arc connects two nodes of the same layer, you have found an odd cycle and the graph is not bipartite.

At the exam

When the question asks for the minimum number of steps (or of moves, or of arcs) on a graph without weights, the answer is BFS. Write: "Run BFS from s. The first time a node is discovered it is reached by a shortest path, because the queue processes nodes in non-decreasing distance. Time O(n + m)."

Typical mistake: writing DFS. The DFS finds a path, not the shortest one.
