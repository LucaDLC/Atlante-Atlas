Counting the steps: big-O

An algorithm is compared with another by counting how many steps it takes, as a function of the size of the input. The big-O notation says which term dominates when the size grows.

The size of the input

Time is not measured in seconds: it is measured in steps, as a function of a size of the input. The size is the number of elements: n nodes, m edges, W budget. In exam texts the time must be written with the names of the parameters of the text, not with a generic n.

Big-O: the term that dominates

f(n) = O(g(n)) means: from a certain point on, f(n) is at most a constant times g(n). Only the dominant term is kept, and no constant: 3n² + 5n + 7 = O(n²).

  • O(log n) binary search;
  • O(n) a scan; O(n + m) a visit of a graph;
  • O(n log n) sorting by comparisons;
  • O(n²) double nested loop; O(2ⁿ) subsets.

How to count

Loops in sequence are added, nested loops are multiplied. Count how many times the innermost line runs, not how many lines there are. A recursive function becomes a recurrence: T(n) = T(n−1) + O(1) gives O(n), T(n) = T(n−1) + T(n−2) gives the growth of Fibonacci, about 1.618ⁿ.

Bounds: O, Ω, Θ

O is an upper bound. Ω (omega) is a lower bound. Θ (theta) is the case where they coincide: the cost is exactly that. Mergesort is Θ(n log n); sorting by comparisons is Ω(n log n), so mergesort is optimal among the comparison sorts.

At the exam

Write the time with the parameters of the text: "O(n + m)", "O(nW)", "O(N²)" with N = levels. Do not write "O(n)" if the text has no n. When the question says "don't solve the recurrence", stop the answer at the recurrence.
