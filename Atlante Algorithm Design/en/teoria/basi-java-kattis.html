Java for Kattis

Kattis judges correctness and time: a correct algorithm can get 'Time Limit Exceeded' if it reads the input slowly or gets the data types wrong. This page explains the language you need, with the measurements made on this PC.

Reading the input quickly

Scanner is convenient but slow: it parses each token with regular expressions. For large inputs use BufferedReader, which reads one line at a time, and StringTokenizer to split it. Measured on 1 000 000 lines: Scanner.nextInt() about 770 ms, BufferedReader + StringTokenizer about 200 ms.

The name of the public class must match the name of the file, and readLine() can throw IOException: you declare it with throws IOException.

Numeric types and overflow

int (32 bits) goes from −2³¹ to 2³¹ − 1. When it exceeds the limit there is no error: the value restarts from the other side. long (64 bits) is the choice for sums of weights and costs. For comparisons use Integer.compare instead of subtraction.

Arrays, lists and collections

Arrays (int[]) have a fixed length and default values 0 (or false, or null). Lists (ArrayList) grow; a queue is an ArrayDeque: add at the back, poll at the front. A priority queue (PriorityQueue) always comes out with the minimum according to a comparator.

Lambdas and comparators

A comparator is a function that says whether one element comes before another. In Java it is written as a lambda: (x, y) -> Integer.compare(x[1], y[1]) sorts by column 1. The lambda is an unnamed function passed as an argument.
