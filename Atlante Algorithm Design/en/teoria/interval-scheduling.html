Interval scheduling: the first to finish

Given a set of intervals, choose the maximum number of intervals that do not overlap. The greedy rule is simple: always take the one that finishes first. Proving it is the classic exercise of the exchange argument.

The problem and the rule

Each interval has a start s and an end f. Two intervals are compatible if they do not overlap: the second starts no earlier than the first finishes. You want the maximum number of compatible intervals.

The greedy rule: sort by increasing end and take an interval if it is compatible with the last one taken. The intuition: an interval that finishes early leaves more free time for the others.

Why it is optimal

Greedy stays ahead proof: after k choices, the greedy has the first interval that finishes no later than any other solution with k intervals. So it always has at least as much room as another solution for the next choice.

Or the exchange argument: if an optimum chooses an interval that finishes later than the greedy's, you replace it with the greedy's one without creating overlaps (the greedy finishes earlier). The number stays the same.

The cost

Sorting costs O(n log n). Then a single scan, O(n), with a single variable: the end of the last interval taken. Total O(n log n). If the intervals are already sorted, the scan is enough: O(n).

Sorting by duration is wrong: a short interval can overlap two long ones that together are compatible. Sorting by start is wrong: an interval that starts early can be very long.

Interval partitioning: how many rooms

Different variant: all the intervals must be assigned, using the minimum number of rooms. A room contains non-overlapping intervals.

The greedy: sort by increasing start. For each interval, use a free room if there is one, otherwise open a new room. The number of rooms is the depth of the intervals, that is the maximum number that overlap at the same instant. So it is optimal: no solution can use fewer rooms than the depth.

Scheduling with minimum lateness (EDF)

One machine, several jobs. Each job j has a duration tⱼ and a deadline dⱼ: the moment by which it should be finished. If j starts at time sⱼ, it finishes at fⱼ = sⱼ + tⱼ.

The lateness of a job is ℓⱼ = max(0, fⱼ − dⱼ). The max(0, …) takes the larger between zero and the number: a job finished early has lateness 0, never negative. The goal is the maximum lateness L = maxⱼ ℓⱼ, as small as possible.

Two greedy rules that seem obvious are wrong:

rulecounterexample
shortest duration firstdurations (1, 10), deadlines (100, 10): the short job goes first, the second finishes at 11 with lateness 1. In the other order the lateness would be 0.
smallest slack dⱼ − tⱼ firstdurations (1, 10), deadlines (2, 10): slacks 1 and 0. Putting the second first makes the first overrun by 9; the opposite order gives lateness 1.

The rule that works is EDF (earliest deadline first, closest deadline first): sort by increasing dⱼ and make the machine work without pauses. Leaving it idle never helps, and EDF does not need it either.

  1. An inversion is a pair of jobs i, j with i before j but dᵢ > dⱼ: the job with the more distant deadline goes first.
  2. An order without inversions is EDF (equal deadlines can be swapped without harm).
  3. If there is an inversion, there is one between two consecutive jobs: if all the neighbours are in order, the whole row is.
  4. I swap the two consecutive jobs. j now starts earlier and finishes before fⱼ, so its lateness does not grow. i finishes at the old fⱼ, and its lateness fⱼ − dᵢ is smaller than fⱼ − dⱼ, which is at most the maximum lateness L. So the maximum does not grow.
  5. Each swap removes an inversion and creates no new ones. After at most n(n−1)/2 swaps there are none left. Starting from an optimum you arrive at EDF without worsening the maximum lateness: EDF is optimal.

At the exam

Interval scheduling (maximum number of compatible activities) → earliest finish time. Interval partitioning (minimum number of rooms) → earliest start time, number of rooms = depth. Phrase: "Sort the jobs in increasing order of finish time. Take a job if it starts no earlier than the finish of the last job taken. Time O(n log n)."

With different weights on the jobs it is no longer greedy: it is weighted interval scheduling (DP).
