Graphs: basic vocabulary

A graph is a set of connected objects. Before any algorithm you need four words: node, edge, degree, path. Every page of this atlas uses them.

Nodes and edges

A graph is a pair G = (V, E). V is the set of nodes (vertices), E is the set of edges. An edge connects two nodes. Write n = |V| for the number of nodes and m = |E| for the number of edges: they are the two parameters with which almost every algorithm is measured.

A graph is undirected if the edge {u, v} can be traversed in both directions, directed if the edge u → v goes only from u to v. A graph can have weights on the edges: one number per edge, for example a cost or a distance.

|X| means "how many elements X has". So |V| = n and |E| = m. In algorithms the time is always written in n and m, never as "the number of nodes" in words.

Two ways of storing it

An algorithm must ask the graph two things: what are the neighbours of a node? and is there the edge u–v?. There are two classic structures, and the choice changes the cost.

  • Adjacency list: for each node, a list of neighbours. Space O(n + m). Scanning the neighbours of u costs O(degree(u)). Checking an edge costs the degree of a node.
  • Adjacency matrix: an n × n table with 1 where there is an edge. Space O(n²). Checking an edge costs O(1), but scanning the neighbours costs O(n).

For almost all the algorithms of this course the adjacency list is the right choice: the graph is sparse, that is m is much smaller than n².

At the exam

When you write the time of an algorithm on graphs, declare which structure you use and why. Ready phrase: "We store the graph as adjacency lists, so the space is O(n + m) and scanning the neighbours of a vertex costs O(degree)."
