Dijkstra: shortest paths with non-negative weights

Dijkstra's algorithm finds the minimum cost from one source to all the other nodes, when all the weights are ≥ 0. It is greedy: at each step it makes final the smallest distance.

The problem and the idea

The problem: edges with weight (cost) ℓ(u, v) ≥ 0, and a source s. I want the minimum cost from s to every node.

The idea: each node keeps a provisional distance d(v), at the start 0 for s and ∞ for the others. At each step you take the node with the smallest d among those not yet fixed: that distance becomes final.

Relaxation

The step that updates the distances is called relaxation. For each edge u → v with weight ℓ:

if d(u) + ℓ < d(v) then d(v) = d(u) + ℓ and parent(v) = u

It means: "going through u I reach v with cost d(u) + ℓ; if that is better than what I already know, I keep it."

Why it works, and why the weights must be ≥ 0

When you fix the node u with distance d(u), no path that passes through nodes not yet fixed can cost less: every edge adds a cost ≥ 0, so a path with more edges does not become cheaper. With a negative weight this guarantee fails: a path that looks more expensive can become cheap further on.

With negative weights Dijkstra gives wrong results, even when there are no negative cycles. For that case use Bellman-Ford (the dynamic programming page).

Cost and priority queue

It needs: n insertions, n extractions of the minimum and at most m decrease-key operations. With a binary heap (priority queue) the cost is O(m log n). With an unsorted array O(n²), good for dense graphs. With a Fibonacci heap O(m + n log n), more theoretical.

At the exam

Shortest cost from one source with non-negative weights → Dijkstra. Write: "Run Dijkstra's algorithm [KT, Sec. 4.4] from s, using a binary heap. Each edge is relaxed at most once, so the time is O(m log n)."

If the graph has negative weights: Bellman-Ford. If all the edges have weight 1: BFS.
