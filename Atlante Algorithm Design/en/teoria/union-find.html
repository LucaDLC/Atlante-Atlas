Union-find: disjoint sets

The union-find (disjoint sets) keeps groups that merge, and answers in almost constant time the question: are x and y in the same group? It is the structure behind Kruskal.

The three operations

  • make-set(x): creates the group {x}, with x as root of itself.
  • find(x): climb the parents up to the root. The root is the representative of the group.
  • union(x, y): finds the two roots and links the smaller under the larger.

Two elements are in the same group if and only if find gives the same root.

Why it keeps the trees low

Without precautions a tree can become a long chain, and find would cost O(n). Two rules avoid it:

  • link by size / rank: under the larger root goes the smaller one. The height grows only when two trees of the same height join, so it stays ≤ log n.
  • path compression: during a find, each node met is linked directly to the root.

The cost

With link by size and path compression together, m operations cost O(m · α(m, n)) in total, where α is the inverse of Ackermann: it grows so slowly that in practice it is a constant (≤ 4 for any real input). Without path compression but with link by size: O(log n) per operation.

At the exam

Connectivity that grows over time, or Kruskal: write "We maintain disjoint sets with union-find, using union by size and path compression; m operations cost O(m α(m, n))."

If the question asks to check whether two nodes are connected just once, a BFS is enough; if the edges arrive one at a time and the answer is needed after each edge, union-find.
