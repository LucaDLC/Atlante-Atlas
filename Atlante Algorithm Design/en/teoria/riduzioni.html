Polynomial reductions

A reduction P2 ≤p P1 transforms every instance of P2 into an instance of P1 with the same answer, in polynomial time. If P1 were easy, P2 would be easy too: this is how one proves that P1 is NP-hard.

The direction

You want to prove that P1 is NP-hard. Take a problem P2 already known as NP-hard, and show P2 ≤p P1: an algorithm for P1 would give an algorithm for P2. The direction is always from the known problem to the new one. Not the other way round.

The six steps

  1. Choose P2 from the catalogue by looking at the structure. Do the special-case test: fix a parameter of P1 (for example k = 2).
  2. Decision version of P1 (yes/no on the size).
  3. Construction: "Given an instance of P2, we construct an instance of P1 as follows: …". Say how large it is.
  4. Polynomial time of the construction.
  5. Correctness in both directions: yes for P2 implies yes for P1, and vice versa.
  6. Complete small example: the instance of P2 and the constructed instance.

Traps

Do not prove that it is NP-hard starting from a solution: the construction starts from the instance of P2. Do not forget the direction ⇐. Respect the input constraints of P1: if P1 promises something (for example strings all different), your instance must respect it.

At the exam

Mandatory phrase: "Given an instance of P2, we construct an instance of P1 as follows: …". Then: construction in polynomial time, ⇒, ⇐, small example.
