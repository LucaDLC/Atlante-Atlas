21 December 2023, worked out

Five problems on bitstrings. Classification: Bit Shelter → NP-hard, Cluster → graphs, Decrease → DP (and the counterexample), Expensive Ones → greedy, To Xor Or Not To Xor → flow. Everything that follows I have checked with programs on the examples of the text and against brute force.

1 · Counterexample: Gordon Gecko's greedy on Decrease

Gordon's idea: start from the bitstring with the most 1s; then, among those where you can decrement, take the one with the most 1s; repeat.

2 · Greedy: Expensive Ones

Sort by increasing number of 1s and take while the 1s used stay ≤ R. Time O(NK + N log N). On the 4 examples of the text it gives 3, 2, 1, 0 bitstrings, like brute force. (The first example prints 00000, 10000, 01010: another valid solution of 3, "any will do".) Model sentence in the 6 questions.

3 · Graph traversal: Cluster

The grid of 1s is a graph; the answer is the largest connected component, with BFS from each unvisited cell. O(NK). Java code checked on the 4 examples (8, 2, 16, 0) in graphs, BFS and DFS.

4 · Dynamic programming: Decrease

5 · Flow: To Xor Or Not To Xor

Pairs → obtainable strings → t, all with capacity 1; d = maximum flow. Drawing on example 1, model answer and checks in reducing to a flow.

6 · NP-hard: Bit Shelter

(a) Bit Shelter; (b) Set Cover; (c) Set Cover ≤P Bit Shelter; (d) each set becomes the bitstring of its positions. Complete answer, with the two cautions about the guarantees of the input, in writing an NP-hardness proof.

Question 5 worked: To Xor Or Not To Xor

Given n pairs of bitstrings of length k, I build a flow network:

  • a source s, a sink t, one node for each pair i (n nodes), and one node for each distinct bitstring obtainable as the AND, OR or XOR of a pair (at most 3n nodes);
  • arc s → i of capacity 1 for each pair; arc from i to each of the at most 3 strings it can produce, capacity 1; arc from each string-node to t, capacity 1. In all at most 7n arcs.

An integer flow of value d chooses d pairs and assigns them d different strings. So the maximum flow is the maximum number d of different strings. The remaining pairs can use any operation.

Cost: computing the strings O(nk). The flow with Ford-Fulkerson costs O(m·C) = O(n²), because m = O(n) and the value is at most C = n.

The Java code of this reduction gives d = 3 and d = 2 on the two examples of the text. On 500 small random instances the maximum flow coincides with brute force, which tries all the 3ⁿ choices.

Question 6 worked: Bit Shelter is NP-hard

The other five problems are: Cluster (BFS), Decrease (DP on the DAG), Expensive Ones (greedy) and To Xor (flow, above). The NP-hard question remains, in three parts:

questionanswer
(a) which problem is NP-hard? (P1)Bit Shelter: choosing the minimum number of bitstrings whose OR gives all 1s
(b) which known NP-hard problem? (P2)Set Cover: each bitstring is the set of positions where it has a 1
(c) P1 ≤p P2 or P2 ≤p P1?P2 ≤p P1: Set Cover ≤p Bit Shelter

Small instance: U = {1, 2, 3, 4}, S1 = {1, 2}, S2 = {2, 3}, S3 = {3, 4}, S4 = {4}. With K = |U| = 4 and N = 4 sets, bitstring i has a 1 in position j if and only if j ∈ Sᵢ: 1100, 0110, 0011, 0001. The OR of 1100 and 0011 is 1111, because S1 ∪ S3 = U. The minimum is 2, checked by brute force.

The reduction: given U = {1, …, K} and F = {S₁, …, S_N}, I build N bitstrings of length K, the i-th with a 1 in position j if and only if j ∈ Sᵢ. Cost O(NK). A set of bitstrings has OR equal to 1…1 exactly when the corresponding sets cover U: so the minimum of Bit Shelter is the minimum of Set Cover, and vice versa.

Bit Shelter guarantees that the OR of all the strings is 1…1 and that the strings are distinct. So first I check in polynomial time that the union of F is U (if not, the answer to Set Cover is "no"), and I remove the duplicate sets, which do not change the optimum.

This is the kind of precision the teacher asks for: the reduction must work for every instance of the known problem, even for those that violate the guarantees of the input of the new problem.
