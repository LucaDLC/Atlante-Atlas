Le 6 domande, una per una

Le domande sono sempre le stesse, con le stesse richieste. Per ognuna: cosa vuole il docente, lo schema della risposta, e una frase modello in inglese. Il testo fra virgolette è preso dall'esame del 21 dicembre 2023.

1 · Counterexample (3 punti)

"Give a small but complete instance… on which [the] algorithm is guaranteed to fail to find an optimal solution. Specify a nonoptimal solution that would be found… and what an optimal solution would be instead."

Il greedy sbagliato è quasi sempre proposto per il problema che in realtà è DP (nel 2023: Gordon Gecko e Decrease). Pensa a cosa perde la scelta miope: un elemento "grande" subito che blocca tanti elementi piccoli dopo. Esempio svolto in vecchie prove.

2 · Greedy (1 + 2 + 1)

"Describe the algorithm… be sure to make it clear which order this is… In other words, don't just write 'sort the input.'" "State the running time… (It must be polynomial in the input size.)"

"Expensive Ones. Sort the bitstrings by increasing number of 1s. Scan them in this order, keeping a counter c of the 1s used so far; take the next bitstring if c plus its number of 1s is at most R, otherwise stop. Output the bitstrings taken. Counting the 1s takes O(NK), sorting O(N log N), so the total time is O(NK + N log N)."

Non si chiede la prova di ottimalità, ma l'ordine deve essere quello giusto. Qui: prendere le più economiche per prime non è mai peggio (argomento di scambio).

3 · Graph traversal (1 + 2 + 1)

"As much as you can, make use of known algorithms… don't re-invent a well-known algorithm. Instead, write something like 'I will use Blabla's algorithm [KT, p. 342] to find a blabla in the blabla.'"

"Cluster. Build a graph with one vertex for each 1 in the input and an edge between two vertices if their positions are adjacent (up, down, left, right). The answer is the size of the largest connected component, which I find by running BFS [KT 3.2] from every unvisited vertex and counting the vertices it reaches. The graph has at most NK vertices and 2NK edges, so the total time is O(NK)."

4 · Dynamic programming (1 + 3 + 1)

"Let OPT(…) denote the value of a partial solution… tell me what the parameters are… and what their range is… Give a recurrence relation for OPT, including relevant boundary conditions and base cases. Which values of OPT are used to answer the problem?"

"Decrease. Sort the bitstrings x₁, …, x_N by decreasing number of 1s (if x can be decreased into y and x ≠ y, x has more 1s). Let OPT(i), for i ∈ {1, …, N}, be the length of the longest valid sequence that ends with xᵢ. Then OPT(i) = 1 + max{ OPT(j) : j < i and xⱼ can be decreased into xᵢ }, and OPT(i) = 1 if there is no such j. The answer is max over i of OPT(i); the sequence is recovered by storing the maximizing j. Checking one pair takes O(K), so the time is O(N²K) and the space O(N)."

5 · Flow (1 + 3 + 1)

"Start by drawing the graph corresponding to Sample Input 1. Be ridiculously precise about which nodes and arcs there are, how many there are… what the capacities are… What does a maximum flow mean in terms of the original problem?" "This part merely has to be correct. There is no requirement about choosing the cleverest flow algorithm."

La ricetta e la risposta completa per To Xor Or Not To Xor sono in ridurre a un flusso.

6 · NP-hard (1 + 1 + 0 + 3)

"(c) Do you now need to prove P1 ≤P P2 or P2 ≤P P1?" vale 0 punti, ma se sbagli la direzione anche la (d) è sbagliata. Risposta: P2 ≤P P1, dal problema noto al nuovo.

Il modello da seguire parola per parola e l'esempio del 2023 svolto: scrivere una prova di NP-hardness.

Errori che costano punti

"Sort the input"

Senza dire per cosa e in che verso. Il testo lo vieta esplicitamente.

Tempo senza parametri

"O(n)" quando il problema ha N e K. Dichiara cosa sono i simboli.

Reinventare

Descrivere la BFS riga per riga invece di citarla con il riferimento al libro.

Riduzione al contrario

"Given an instance of [nuovo]…": 0 punti sulla (d).

OPT senza significato

Una ricorrenza senza dire cosa rappresenta OPT(i, j) e il range degli indici.

Controesempio con parità

Se l'algoritmo potrebbe scegliere bene rompendo un pareggio, non è "guaranteed to fail".
