Java per Kattis

Kattis giudica correttezza e tempo: un algoritmo giusto può prendere 'Time Limit Exceeded' se legge l'input lentamente o se sbaglia tipi di dato. Questa pagina spiega il linguaggio che serve, con le misure fatte su questo PC.

Leggere l'input velocemente

Scanner è comodo ma lento: analizza ogni token con espressioni regolari. Per input grandi si usa BufferedReader, che legge una riga alla volta, e StringTokenizer per spezzarla. Misurato su 1 000 000 di righe: Scanner.nextInt() circa 770 ms, BufferedReader + StringTokenizer circa 200 ms.

Il nome della classe pubblica deve coincidere con il nome del file, e readLine() può lanciare IOException: la dichiari con throws IOException.

Tipi numerici e overflow

int (32 bit) va da −2³¹ a 2³¹ − 1. Quando supera il limite non c'è errore: il valore ricomincia dall'altra parte. long (64 bit) è la scelta per somme di pesi e costi. Per i confronti usa Integer.compare invece della sottrazione.

Array, liste e collezioni

Gli array (int[]) hanno lunghezza fissa e valori di default 0 (o false, o null). Le liste (ArrayList) crescono; una coda è una ArrayDeque: add in fondo, poll in testa. Una coda di priorità (PriorityQueue) esce sempre col minimo secondo un comparatore.

Lambda e comparatori

Un comparatore è una funzione che dice se un elemento viene prima dell'altro. In Java si scrive come lambda: (x, y) -> Integer.compare(x[1], y[1]) ordina per la colonna 1. La lambda è una funzione senza nome passata come argomento.
