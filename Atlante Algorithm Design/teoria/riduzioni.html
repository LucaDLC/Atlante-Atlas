Riduzioni polinomiali

Una riduzione P2 ≤p P1 trasforma ogni istanza di P2 in un'istanza di P1 con la stessa risposta, in tempo polinomiale. Se P1 fosse facile, anche P2 lo sarebbe: così si dimostra che P1 è NP-hard.

La direzione

Vuoi dimostrare che P1 è NP-hard. Prendi un problema P2 già noto come NP-hard, e mostra P2 ≤p P1: un algoritmo per P1 darebbe un algoritmo per P2. La direzione è sempre dal problema noto a quello nuovo. Non viceversa.

I sei passi

  1. Scegli P2 dal catalogo guardando la struttura. Fai il test del caso particolare: fissa un parametro di P1 (per esempio k = 2).
  2. Versione decisionale di P1 (sì/no sulla taglia).
  3. Costruzione: "Given an instance of P2, we construct an instance of P1 as follows: …". Di' quanto è grande.
  4. Tempo polinomiale della costruzione.
  5. Correttezza nelle due direzioni: sì per P2 implica sì per P1, e viceversa.
  6. Esempio piccolo completo: l'istanza di P2 e l'istanza costruita.

Trappole

Non dimostrare che è NP-hard partendo da una soluzione: la costruzione parte dall'istanza di P2. Non dimenticare la direzione ⇐. Rispetta i vincoli d'input di P1: se P1 promette qualcosa (per esempio stringhe tutte diverse), la tua istanza deve rispettarlo.

All’esame

Frase obbligatoria: "Given an instance of P2, we construct an instance of P1 as follows: …". Poi: costruzione in tempo polinomiale, ⇒, ⇐, esempio piccolo.
