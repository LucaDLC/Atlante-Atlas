Kernel and feature transformations

The lecture of week 5: how to obtain non-linear models while still using linear algebra. The trick is to transform the inputs with a function φ (in this course it is called the kernel or feature mapping) and then do least squares on the new features. Here: the idea, the function φ, the design matrix Φ, the two-input case of Assignment 1, a kernel different from polynomials, and the price to pay.

The idea: a curve becomes a line

Many data follow curved relations, and a line does not describe them. Instead of inventing a new method for each curve, one transforms the data: one builds new features (for example x²) so that, in the new space, the relation becomes linear. Then one uses the usual method, least squares.

In the example the points lie on the parabola y = 1 + 0.5x². With the new feature z = x² the relation becomes y = 1 + 0.5z: a line in the space (z, y). The line is learned with linear algebra, and going back to x one has the parabola.

It is the goal "understand how feature transformations extend linear models" of week 5: the non-linearity lies entirely in the features, the weights remain linear.

The kernel φ: from a number to a vector

A function φ(x) that transforms the input into a feature vector. The model is y = w · φ(x): non-linear in x, linear in w. For the polynomial of degree 2: φ(x) = [1, x, x²].

φ is read "fi". It takes an input (even a single number) and returns a vector, usually longer: the datum passes into a feature space (feature space) with more dimensions. The choice of φ is a choice of model: it says which shapes of curve the model will be able to represent.

Watch the name: later "kernel" also means the kernel trick of SVMs (week 10), and in the filters one prefers to say "filter" precisely to avoid confusion (week 8).

The design matrix Φ

With a kernel the design matrix is built in the same way, only each row is φ(xᵢ) instead of [1, xᵢ]. It is called Φ (capital Phi).

Two inputs: the quadratic kernel of Assignment 1

With two inputs (x, y) the complete polynomial of degree 2 has 6 terms: 1 constant, 2 linear (x, y), 3 quadratic (x², xy, y²). The mixed term xy is the one most often forgotten, and it is the one that lets the model bend along the diagonal.

In Assignment 1 (gaze estimation) one starts from an affine model, x′ = ax + by + c, and then improves it precisely with this kernel: f(x, y) = a·x² + b·y² + c·xy + d·x + e·y + f, with 6 parameters for each coordinate of the screen, so 12 in all. At least 6 calibration points are needed, and better many more.

The function that builds Φ must be used identical in training and in prediction. If at one point the columns are [x², y², xy, …] and at another [x², xy, y², …], the weights get multiplied by the wrong features: no Python error, only wrong predictions.

Not only polynomials: sines and cosines

The kernel does not have to be a polynomial. Any set of known functions can serve as columns: the only condition is that the model be "weights for known functions, then sum". For data that oscillate over time the natural kernel is φ(t) = [1, sin t, cos t].

It is here that the meaning of "kernel = hypothesis about the problem" is seen: a high-degree polynomial could also chase the wave on the data seen, but it would diverge as soon as one goes outside; sines and cosines oscillate by themselves, even where there are no data. Choosing φ well is worth more than adding features at random.

The price: more features, more data, overfitting

Going into a larger feature space has three advantages: a non-linear problem becomes linear, flexibility is gained, and the solution remains in closed form (no iterative optimisation).

The price: each feature is one more parameter, so more data are needed; and a model too flexible for the data also fits the noise. The error on the training data keeps going down, while that on new data at some point goes up again. This is overfitting, and choosing the right complexity is the theme of week 7 (model complexity).
