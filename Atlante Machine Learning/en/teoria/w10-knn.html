k-nearest neighbour: the exercise

Exercise of week 10 K-Nearest-Neighbour Classifier (Tasks 1–4) and lecture 9. A new point takes the class of the majority of its k neighbours. Here we calculate by hand, with the data of the notebook, the ties that the eye misses, the effect of k, the effect of the dimensions and the comparison with the linear classifier.

The k-nearest neighbour in four steps

Tasks 1–2: the 20 points and the five questions

The notebook gives 10 points of class A, 10 of class B and five points to classify. Task 1 only asks to look at them; Task 2 asks for the class of each Q with k = 2, 3, 5 "by eye". Here we calculate the distances, and see where the eye is not enough.

The votes are written as "how many A – how many B". Where the cell says "A / B" the result is A or B, depending on how the tie explained below is resolved.

With integer coordinates distances repeat: from Q4 three points are all at √2. If the k-th place is contested by several points at the same distance, the method alone does not decide: a rule is needed. The most common: keep all the tied points (then there are more than k neighbours), choose by the order of the data, or weight the votes by distance. In the exercise the honest thing is to say that there is a tie and that the answer depends on how it is resolved.

With KNeighborsClassifier of scikit-learn 1.9.0 the output is: for Q4, A with k = 2, 3, 5; for Q5, A with k = 2 and 3, B with k = 5. It picks among the tied points itself and, on a tied vote, gave A: this is an implementation detail, not a rule of the method.

Q1, Q2 and Q3 lie inside a group: the neighbours are almost all of the same class and changing k does not change the answer. Q4 and Q5 lie between the two groups, close to the decision boundary: there any change of k, of distance or of tie can flip the class.

How the answer changes with k (Task 2)

The question of the notebook: what happens when k is very small or very large, and how does it relate to overfitting and underfitting?

  • Small k (at the limit 1): a single point decides. A point out of place, because of noise or measurement error, changes the answer all around it. The boundary is jagged and follows the noise: overfitting.
  • Large k: every answer is an average over many points. The boundary smooths out; real details are lost. At the limit k = N all the points vote for every Q: here 10–10, a single class everywhere, 0.5 accuracy: underfitting.
  • In between there is the right k, and it is chosen with a validation set (Validation), because k is a hyperparameter.

With this rule (A before B) the code gives, for k = 2, 3, 5: Q1 [2 0], [2 1], [3 2]; Q2 [2 0], [3 0], [5 0]; Q3 [0 2], [0 3], [0 5]; Q4 [2 0], [2 1], [3 2]; Q5 [1 1], [2 1], [2 3]. The "A / B" cells of the table are those where another rule would give a different result.

Task 3: more dimensions

The notebook gives a second set, in four dimensions, with a single point to classify, Q = [0, 0, 0, 0]. The distance is computed as before, with four terms under the root.

Class AA1A2A3A4
(x₁, x₂, x₃, x₄)(1, 0, 0, 0)(1, 1, 0, 0)(2, 2, 1, 0)(3, 2, 2, 0)
Class BB1B2B3B4
(x₁, x₂, x₃, x₄)(2, 0, 0, 0)(2, 1, 0, 0)(2, 2, 0, 0)(3, 3, 0, 0)
  • k = 2: A1, A2 → A. k = 3: A1, A2, B1 → A (2–1). k = 5: A1, A2, B1, B2, B3 → B (2–3).
  • In this example no distance repeats, so there is no tie.
  • Why the dimension matters: A3 and B3 have the same x₁ and x₂ and differ only in x₃. In two dimensions they would be the same point and the fifth place would be a tie (A or B). The third coordinate separates them and decides the fifth place: one more feature changes the answer, even if it says nothing useful about the class.

Every extra coordinate adds a term to the distance and can move the neighbours. A useless feature (or one on a much larger scale than the others) brings noise into the distance. With many dimensions, moreover, distances become almost all equal and the "closest" is not much closer than the others: see the curse of dimensionality in PCA.
