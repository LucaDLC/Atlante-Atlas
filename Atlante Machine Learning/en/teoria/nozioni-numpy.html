NumPy: shapes, axes, errors

Almost all the problems with NumPy are problems of shape: a vector that was meant to be a column, a mean taken on the wrong axis, a subtraction that produces a matrix instead of a vector. Here the rules, with real output and errors (NumPy 2.4).

The shape: (n,), (n, 1), (1, n)

Every NumPy array has a shape (.shape): a tuple with the length of each dimension. The same three numbers can be in three different shapes, and NumPy treats them differently in the calculations. Knowing how to tell them apart avoids half of the errors.

Print .shape. Before every product or subtraction check the shapes, as in the page Dimensions in products between matrices.

axis: in which direction one squashes

axis=k makes dimension k disappear. With the data in the form (data × features): axis=0 gives one number per feature (means, standard deviations of the columns); axis=1 one number per datum. Without axis everything is squashed into a single number (M.mean() = 3.5).

Broadcasting: convenient and dangerous

When two arrays have different shapes, NumPy tries to "widen" the smaller one. To centre the data it is convenient. But sometimes NumPy widens when you did not want it, and it gives no error.

y = np.array([[1.], [2.], [5.]])       # colonna (3, 1)
pred = np.array([1., 3., 5.])          # vettore (3,)
np.mean((y - pred) ** 2)
(y - pred).shape  →  (3, 3)
np.mean((y - pred) ** 2)  →  5.666666666666667

No error, but the loss is wrong: the right one is (0² + 1² + 0²) / 3 = 0.333. It happens when y is read as a column and the prediction X @ w is 1D. Remedy: make both 1D, y.ravel() (or y[:, 0]), and check that (y - pred).shape is (3,).

Operators that seem equal

I writeOn NumPy arraysExample (verified)
a * belement by element[1, 2, 3] * [1, 2, 3] → [1, 4, 9]
a @ binner product / matrix product[1, 2, 3] @ [1, 2, 3] → 14
a ** 2power, element by element[1, 4, 9]
a / 2division with the decimal point[0.5, 1., 1.5]
a // 2integer division (truncated)[0, 1, 1]

On lists the same symbols do something else: [1, 2, 3] * 2 → [1, 2, 3, 1, 2, 3] (repeats) and [1, 2] + [3, 4] → [1, 2, 3, 4] (joins). With np.array: [2, 4, 6] and [4, 6]. To do calculations, first np.array(...).

Building the design matrix

The design matrix of a line has a column of 1s next to the column of the xs. NumPy has several functions to "put together" arrays, and not all of them put the vectors as columns.

Other silent traps

The worst traps are those without an error message: the code runs, the result is wrong. Two classics: assigning an array to another name does not copy it, and an array of integers truncates the decimals.

b = np.array([1, 2, 3])
c = b
c[0] = 99
>>> b
array([99,  2,  3])

c = b does not copy: it gives a second name to the same array. For an independent copy: c = b.copy().

v = np.array([1, 2, 3])
v[0] = 2.7
>>> v
array([2, 2, 3])

The array is of integers (dtype int64), so 2.7 is truncated to 2. If decimals will go in, create it with decimals: np.array([1., 2., 3.]) or dtype=float.

X = np.array([[1., 2.], [3., 5.], [5., 11.]])   # 3 dati, 2 feature
np.cov(X)
array([[ 0.5,  1. ,  3. ],
       [ 1. ,  2. ,  6. ],
       [ 3. ,  6. , 18. ]])

A 3 × 3 covariance for 2 features makes no sense: np.cov by default treats the rows as variables. With the data by rows: np.cov(X, rowvar=False) → [[4, 9], [9, 21]]. That one divides by N − 1; the course notes (DW) divide by N: np.cov(X, rowvar=False, bias=True) → [[2.67, 6], [6, 14]], equal to Xc.T @ Xc / N with the centred data.

Errors with a message

These at least stop with a message. The message already says what is wrong: "Singular matrix" means determinant zero, "cannot reshape" means that the number of cells does not match.

np.linalg.inv(np.array([[1., 2.], [2., 4.]]))
LinAlgError: Singular matrix

The second row is twice the first: determinant 0, the inverse does not exist (linear systems). In least squares it happens when two columns of the design matrix are dependent. np.linalg.lstsq still gives a solution.

np.arange(6).reshape(4, 2)
ValueError: cannot reshape array of size 6 into shape (4,2)

6 numbers do not fill 4 × 2 = 8 cells. The product of the new dimensions must equal the number of elements: reshape(2, 3) or reshape(3, 2).
