What machine learning is

The first lecture in six ideas: instead of writing rules, you let the computer learn them from the data. Here you find the difference from traditional programming, the pipeline to memorise, the types of problems, why data alone is not enough, and the recipe that the course repeats for 14 weeks.

Programming or learning from data

A traditional programme is a list of rules written by a person. To recognise a cat in a photo you would have to write, by hand, what ears, whiskers and fur look like: in practice impossible, because cats are all different and photos change with the light.

In machine learning the work is reversed. You do not write the rules: you collect many examples whose answer you already know (this photo: cat; this one: not a cat) and let the computer find a rule that explains them. The rule found is called a model (model): it is, in every respect, a programme, only nobody wrote it line by line.

Two consequences that come back throughout the course. First: the model is only as good as the data it has seen; if the examples are few or wrong, the rule will be wrong. Second: the model must always be checked on new examples, because a rule that works only on the examples already seen is useless.

The pipeline: from raw data to prediction

Slide 21 literally says "memorize this": it is the scheme of every ML project, and every week of the course explores one piece of it. There are two phases.

In the training phase the raw data (raw data) are cleaned (data wrangling: errors and noise are removed, the scales are normalised), then transformed into feature vectors (feature vectors): each example becomes a list of numbers. The model receives these vectors together with the labels (labels, the right answers) and adjusts its parameters so as to get as few things wrong as possible.

In the prediction phase new data arrive. They go through the same transformations as in training, enter the already trained model, and the prediction comes out. Finally the evaluation (evaluation) compares the predictions with the truth, on data the model has not used to learn, with a metric chosen in advance (for example sensitivity and specificity in the medical example of slide 6).

The questions that the slides mark as likely at the exam all come from here: what a model is and how models differ, how a good model is chosen, how the parameters are found.

Supervised and unsupervised

A dataset is a table: one row per example, one column for each measured feature (in slide 17: height, weight, shoe size, gender). Each row becomes a vector.

In supervised learning (supervised learning) the dataset also has a column with the answer we want to predict (in the slide: "Ballet?"). The model learns the relation between the input columns and the answer. If the answer is a category (yes/no, cat/dog) the problem is called classification; if it is a number (a price, a gaze position) it is called regression.

In unsupervised learning (unsupervised learning) the column of answers is not there: "no predefined and known set of outcomes". The model looks for hidden structures, for example groups of similar examples (clustering, week 13) or directions in which the data vary most (PCA, week 12).

True function, data and noise

The basic idea of ML: there exists a true function (ground truth) that links the input x to the output y, for example the pupil position and the point looked at on the screen. We do not know it. We can only collect data: measured pairs (x, y).

Each measurement contains a small random error, the noise (noise): the instrument is not perfect, the person moves. That is why the points do not lie exactly on the true function.

The model is our attempt to reconstruct the true function starting only from the points. Its aim is not to pass through the points already seen, but to predict new points well (unseen data). A model flexible enough to pass through all the points also copies the noise and gets it badly wrong elsewhere: it is the problem of overfitting, which returns in weeks 6–7.

To choose, you must make a hypothesis about the shape of the function (is it a line? is it smooth?). This hypothesis is called inductive bias (inductive bias): without it, from a finite number of points nothing can be learned.

Training and test: machine learning in brief

Slide 25 sums it all up in two sentences. Training: given a set of labelled examples {(x₁, y₁), …, (x_N, y_N)}, one estimates the prediction function f by making the error on the examples as small as possible. Test: f is applied to an example x never seen, and the predicted value ŷ = f(x) is returned.

The symbols, one by one. x is the input, usually a feature vector. y is the right output. The subscript i in xᵢ numbers the examples, from 1 to N. f is the model. ŷ ("y hat") is the predicted output: the hat distinguishes the prediction from the measured value.

The function f depends on parameters (model parameters, often called weights w): for a line they are the intercept w₀ and the slope w₁. Learning means finding the values of the parameters; once they are fixed, the model is an ordinary function.

The recipe: model, loss, parameters

Slide 33 gives the recipe that the course applies to every method. 1: you have training data. 2: you choose two things, the model (the family of functions, for example "all the lines") and the loss function (loss or objective function), that is the number that measures how much the model gets wrong. 3: the goal is to make the loss as small as possible. 4: you learn the parameters, that is you look for the values that reach that minimum.

The two functions have different roles (slide 29). The prediction function contains our hypotheses about how the problem works; the parameters are its "brain". The loss function says how much it costs to get it wrong; changing the parameters tries to make it go down.
