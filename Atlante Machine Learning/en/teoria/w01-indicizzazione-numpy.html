Indexing and slicing NumPy arrays

How to read A[:2, 1]: first the rows, then the columns, and the end of the interval is never included. Here the shape of an array, the comma, the slices, the cell of Task 4, the shape of the result and the method for Task 5 of Practical introduction to Python and Numpy, week 1.

NumPy arrays: shape and indices from 0

NumPy (imported with import numpy as np) is the library for calculations with vectors and matrices. np.array turns a Python list into an array: a list of numbers becomes a vector, a list of lists becomes a matrix, one row for each inner list.

A = np.array([
    [1, 2, 3],    # riga 0
    [3, 4, 9],    # riga 1
    [5, 7, 3]     # riga 2
])
#  col: 0  1  2

Every array has a shape (.shape): a tuple with the length of each dimension, first the rows then the columns. Here A.shape is (3, 3). The number of dimensions is read with .ndim: 1 for a vector, 2 for a matrix.

The "second row" is the index 1. The "first column" is the index 0. The last element of a row of length 3 has index 2, or −1.

One element: A[row, column]

To read an element one writes the indices in square brackets, separated by a comma: first the row, then the column. A[1, 2] is the element in row 1 and column 2, that is 9.

SymbolMeaning
A[ ]take from A
,separates row (first) and column (after): A[row, column]
-1, -2the last, the penultimate: one counts from the end

With a single index, A[0], NumPy does not take an element but the whole row: it is like writing A[0, :]. It is a classic source of errors, because it looks like an element and is instead a vector.

Slice: start:end, with the end excluded

A slice takes an interval of indices with the notation start:end. The rule to remember: the start is included, the end is excluded. v[1:4] takes the indices 1, 2 and 3.

WrittenMeaning
start:endfrom start (included) to end (excluded)
:2from the beginning up to 2 excluded: indices 0 and 1
3:from 3 to the end
: aloneeverything
::2everything, with step 2 (one yes and one no)

Why the end is excluded: the number of elements taken is simply end − start, and v[:k] and v[k:] fit together without gaps or duplicates. On a matrix one puts a slice for each dimension, separated by the comma.

Bare number or slice: the shape of the result

The same elements can be taken in two ways, and the result has a different shape. A bare number in place of a dimension removes it; a slice, even of length 1, keeps it.

A[0:1, :] is still a 1×3 matrix, and is printed with double brackets [[1 2 3]]. A[0, :] is a vector of 3 elements, [1 2 3].

Why it matters: a matrix (3, 1) and a vector (3,) contain the same numbers, but in products and in element-by-element operations they behave differently (broadcasting can turn a sum into a 3 × 3 matrix). The complete trap is in NumPy: shapes, axes, errors.

Neither one nor the other: it is not a view. .T swaps rows and columns and changes the shape: (2, 3) becomes (3, 2). On a 1D array instead nothing changes, and NumPy gives no error. In full: Matrices and NumPy.

Translating a request into indices (Task 5)

Task 5 asks the opposite of Task 4: from a sentence ("the top right corner", "the second row") write the index. The method is always the same, two questions: which rows? and which columns? Each becomes a bare number (a single row or column, dimension removed) or a slice start:end. Then they are joined with the comma.

Two checks before running: the indices start from 0, and the end of the slice is excluded. Afterwards: the .shape of the result must be the one asked for (a 2 × 2 must have shape (2, 2)).
