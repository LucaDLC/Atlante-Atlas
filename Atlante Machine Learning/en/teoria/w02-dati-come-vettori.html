Data as vectors

The idea of week 2 (Vector representations): any datum can be written as a list of numbers, that is a vector. Here: what a vector is, how a table, a pose and an image become vectors, the two basic operations, the linear combination and the move to many dimensions.

What a vector is

A vector is an ordered list of numbers. Each number is called a component. In the slides it is written as a column (column vector), in the text often in square brackets: v = [3, 2]. In NumPy it is a 1D array: np.array([3, 2]).

The order matters: the first component always says the same thing (for example the height), the second another (the weight). Swapping them changes the meaning, so [3, 2] and [2, 3] are different vectors.

A vector with 2 components can be drawn in two equivalent ways: as a point of the plane, or as an arrow that starts from the origin and reaches that point. The number of components is the dimension: it is written v ∈ ℝⁿ, "v belongs to R-n", that is v is a list of n real numbers.

Writing a datum (a pose, an image, a measurement) as a list of numbers. It is the bridge that allows using length, distance and inner product on things that are not arrows.

Feature: each measurement is a component

On slide 38 the question is: "which characteristics distinguish a person?" Height, weight, shoe size… Each one is a feature (measured characteristic). Putting the features of a person in a row gives their feature vector (feature vector).

A table of data is therefore a stack of vectors: one row per example, one column per feature. With 2 features each example is a point of the plane; with 50 features a point of ℝ⁵⁰.

The gain is huge: similar examples become nearby points. The question "how similar are two people?" becomes "how far apart are two points?", and distances can be computed. Watch the units: if one feature is in centimetres and the other in kilograms, the one with the larger numbers weighs more in the distance; that is why one normalises first (week 7).

How a pose becomes a vector

The exercise 01-poses uses badminton poses: a body described by 25 points (head, shoulders, elbows…), each with an x and a y. To make a vector all the coordinates are put in a row, always in the same order: x₁, y₁, x₂, y₂, …, x₂₅, y₂₅. Result: a vector of 50 components.

The file poses.npy has shape (18, 50): 18 poses, one per row, 50 numbers each. The fixed order is essential: component 3 must be the x of the second point in all the poses, otherwise comparing them component by component would make no sense.

"Each pose is represented as a vector in R50, so the similarity between two poses is the Euclidean distance between their vectors."

Images as vectors

A digital greyscale image is a grid of pixels, and each pixel is a number (usually from 0, black, to 255, white). A grid is a matrix, but for many models a vector is needed: the image is flattened (flatten) by putting the rows one after the other.

An image of 28 × 28 pixels thus becomes a vector of 784 components, a point of ℝ⁷⁸⁴ (slide 40: "images as vectors, feature vectors"). In NumPy: img.flatten() or img.reshape(-1). For colour images each pixel has 3 numbers (red, green, blue), and the vector becomes three times longer.

Using the pixels directly as features is the simplest way; in weeks 8 and 11 better features computed from the pixels are seen (edges, histograms of gradients).

Vector sum and scalar multiplication

The two basic operations (slide 43) are done component by component.

Sum: u + v = [u₁ + v₁, u₂ + v₂, …]. Only vectors of the same dimension can be added. In the drawing, the arrow v is attached at the tail of arrow u: the sum goes from the origin to the end of the chain.

Scalar multiplication: a scalar is a single number, c. c·u = [c·u₁, c·u₂, …]. The arrow stays on the same line: it lengthens if |c| > 1, shortens if |c| < 1, and reverses direction if c is negative.

From these two comes the difference: u − v = u + (−1)·v, the arrow from the tip of v to the tip of u. It is the basis of the distance between two data.

Linear combination

A linear combination puts the two operations together: each vector is multiplied by a number (a weight, or coefficient) and the results are summed. With the vectors v₁, …, vₖ and the weights c₁, …, cₖ: c₁v₁ + c₂v₂ + … + cₖvₖ.

u = [1, 0]   v = [0, 1]  →  3u + 2v = [3, 2]

Two readings that the course always uses. Composing: with the right weights one builds other vectors (here [3, 2]). Decomposing: given a vector, find the weights that produce it (slide 23 of lecture 2, "composition and decomposition of vectors"). With u = [1, 0] and v = [0, 1] every vector of the plane is obtained this way, and the weights are exactly its components.

w1x1 + w2x2 is a linear combination: numbers (the weights) times quantities, then summed. Learning a model means finding the weights of the right combination. And the matrix-vector product of week 3 is a linear combination of the columns of the matrix.

From 2 to many dimensions

One of the goals of the week is "the transition from two-dimensional vector spaces to higher-dimensional spaces". The idea is reassuring: nothing changes in the rules. Sum, scalar multiplication, difference, length, distance and inner product are computed component by component, and with n components the formulas simply have n terms instead of 2.

What is lost is the drawing: beyond 3 dimensions one can no longer see. That is why one reasons in 2D, where one can see, and trusts the formulas for the rest. The file of poses is the concrete example: two poses are two points of ℝ⁵⁰, and their distance is computed exactly as between two points of the plane.
