Polynomials: models linear in the parameters

On the slides the question is: "Why is a polynomial a non-linear function but can be written as an inner product?" The answer is the central idea of weeks 4 and 5: a model can be curved in x but linear in the weights w, and then it is learned with linear algebra. Here: the design matrix and the three cases: as many points as parameters, more, fewer.

Curved in x, linear in the weights

A polynomial of degree 2, y = w₀ + w₁x + w₂x², draws a curve: it is not linear in x (doubling x does not double y).

But in training x is a known datum and the unknowns are the weights. With respect to the weights the polynomial is a sum of weights times known numbers (1, x, x²): it is linear in w. In the form of an inner product, y = [w₀, w₁, w₂] · [1, x, x²].

The design matrix

With N points and a model linear in the parameters, each point gives an equation. Together they are written Xw = y, where X is the design matrix: one row per point, one column per parameter. Column j contains the number that multiplies wⱼ in each equation.

np.vander(x, 3, increasing=True) puts the columns in the order 1, x, x², and the weights come out as [w₀, w₁, w₂]. np.polyfit instead returns the coefficients from the highest degree: for the same 4 points of the section below it gives [0.5, 0.9, 0.9] instead of [0.9, 0.9, 0.5]. Same numbers, reversed order (verified).

As many points as parameters: the exact solution

If the number of points equals the number of parameters, X is square. If the points have all different x, X is invertible and the system has one single solution: w = X⁻¹y, in practice np.linalg.solve(X, y).

The model found passes exactly through all the points. For two points it is the line of week 1, for three points a parabola, in general a polynomial of degree N − 1 for N points: it is exercise 13 of the test (exercises by hand).

More points than parameters: the overdetermined system

With real data the points are almost always many more than the parameters, and because of the noise no model passes through all of them. X is tall and narrow (N × p with N > p), the system is overdetermined and has no exact solution.

The question then changes: not "which w makes all the equations true", but "which w makes them nearly true, getting it wrong as little as possible". With the least squares loss the answer is unique and is computed with np.linalg.lstsq; the formula and the geometry are in week 5 (least squares). It is the goal of week 4: "relate overdetermined systems of equations to least squares optimization".

Fewer points than parameters: infinitely many solutions

The opposite case: more parameters than points. The system is underdetermined and has infinitely many solutions: many different models pass exactly through the data, and the data give no way to choose one.

The problem shows as soon as a new prediction is made: models equally perfect on the data give very different answers outside. It is the extreme form of overfitting: a model too flexible for the available data.

"Explain how linear and certain non-linear models can be learned by solving systems of linear equations… Discuss how model complexity, such as polynomial degree, affects the number of parameters and therefore the amount of training data required." Higher degree ⇒ more parameters ⇒ more points needed; and with too many parameters relative to the data the model chases the noise (overfitting, week 7).

More features: the same design matrix

Everything that holds for polynomials also holds for models with more features. For the plane y = w₀ + w₁x₁ + w₂x₂ the row of the design matrix is [1, x₁, x₂]; for a hyperplane in n dimensions [1, x₁, …, xₙ].

The general rule: the columns of the design matrix can be any known function of the features (x₁, x₁², x₁·x₂, sin x₁, …). As long as the model is "weights for known columns, then sum", it is linear in the parameters and it is learned by solving Xw = y, exactly or with least squares. Choosing the right columns is the transformation of the features of week 5.
