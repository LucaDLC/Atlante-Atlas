NumPy: forme, assi, errori

Quasi tutti i problemi con NumPy sono problemi di forma: un vettore che doveva essere una colonna, una media fatta sull'asse sbagliato, una sottrazione che produce una matrice invece di un vettore. Qui le regole, con output ed errori veri (NumPy 2.4).

La forma: (n,), (n, 1), (1, n)

Ogni array NumPy ha una forma (.shape): una tupla con la lunghezza di ogni dimensione. Gli stessi tre numeri possono stare in tre forme diverse, e NumPy le tratta in modo diverso nei conti. Saperle distinguere evita metà degli errori.

Stampa .shape. Prima di ogni prodotto o sottrazione controlla le forme come nella pagina Dimensioni nei prodotti tra matrici.

axis: in che direzione si schiaccia

axis=k fa sparire la dimensione k. Con i dati nella forma (dati × feature): axis=0 dà un numero per feature (medie, deviazioni standard delle colonne); axis=1 un numero per dato. Senza axis si schiaccia tutto in un numero solo (M.mean() = 3.5).

Broadcasting: comodo e pericoloso

Quando due array hanno forme diverse, NumPy prova ad "allargare" quello più piccolo. Per centrare i dati è comodo. Ma a volte NumPy allarga quando tu non volevi, e non dà nessun errore.

y = np.array([[1.], [2.], [5.]])       # colonna (3, 1)
pred = np.array([1., 3., 5.])          # vettore (3,)
np.mean((y - pred) ** 2)
(y - pred).shape  →  (3, 3)
np.mean((y - pred) ** 2)  →  5.666666666666667

Nessun errore, ma la loss è sbagliata: la giusta è (0² + 1² + 0²) / 3 = 0.333. Succede quando y viene letto come colonna e la previsione X @ w è 1D. Rimedio: rendere tutti e due 1D, y.ravel() (oppure y[:, 0]), e controllare che (y - pred).shape sia (3,).

Operatori che sembrano uguali

a @ bprodotto interno / di matrici[1, 2, 3] @ [1, 2, 3] → 14

a / 2divisione con la virgola[0.5, 1., 1.5]
a // 2divisione intera (tronca)[0, 1, 1]

Sulle liste gli stessi simboli fanno altro: [1, 2, 3] * 2 → [1, 2, 3, 1, 2, 3] (ripete) e [1, 2] + [3, 4] → [1, 2, 3, 4] (attacca). Con np.array: [2, 4, 6] e [4, 6]. Per fare i conti, prima np.array(...).

Costruire la design matrix

La design matrix di una retta ha una colonna di 1 accanto alla colonna delle x. NumPy ha più funzioni per "mettere insieme" array, e non tutte mettono i vettori come colonne.

Altre trappole silenziose

Le trappole peggiori sono quelle senza messaggio d'errore: il codice gira, il risultato è sbagliato. Due classiche: assegnare un array a un altro nome non lo copia, e un array di interi tronca i decimali.

b = np.array([1, 2, 3])
c = b
c[0] = 99
>>> b
array([99,  2,  3])

c = b non copia: dà un secondo nome allo stesso array. Per una copia indipendente: c = b.copy().

v = np.array([1, 2, 3])
v[0] = 2.7
>>> v
array([2, 2, 3])

L'array è di interi (dtype int64), quindi 2.7 viene troncato a 2. Se ci andranno decimali, crealo con decimali: np.array([1., 2., 3.]) o dtype=float.

X = np.array([[1., 2.], [3., 5.], [5., 11.]])   # 3 dati, 2 feature
np.cov(X)
array([[ 0.5,  1. ,  3. ],
       [ 1. ,  2. ,  6. ],
       [ 3. ,  6. , 18. ]])

Una covarianza 3 × 3 per 2 feature non ha senso: np.cov di default tratta le righe come variabili. Con i dati per righe: np.cov(X, rowvar=False) → [[4, 9], [9, 21]]. Quella divide per N − 1; le note del corso (DW) dividono per N: np.cov(X, rowvar=False, bias=True) → [[2.67, 6], [6, 14]], uguale a Xc.T @ Xc / N con i dati centrati.

Errori con messaggio

Questi almeno si fermano con un messaggio. Il messaggio dice già cosa non va: "Singular matrix" vuol dire determinante zero, "cannot reshape" vuol dire che il numero di caselle non torna.

np.linalg.inv(np.array([[1., 2.], [2., 4.]]))
LinAlgError: Singular matrix

La seconda riga è il doppio della prima: determinante 0, non esiste l'inversa (sistemi lineari). Nei minimi quadrati succede quando due colonne della design matrix sono dipendenti. np.linalg.lstsq dà comunque una soluzione.

np.arange(6).reshape(4, 2)
ValueError: cannot reshape array of size 6 into shape (4,2)

6 numeri non riempiono 4 × 2 = 8 caselle. Il prodotto delle dimensioni nuove deve essere uguale al numero di elementi: reshape(2, 3) o reshape(3, 2).
