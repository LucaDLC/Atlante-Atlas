Mutua Esclusione e Lock

Senza lock i quattro passi si mescolano in 70 modi. Con lock() / unlock() ne restano 2, ed entrambi danno il risultato giusto. Costruisci le sequenze e guarda i passi bloccarsi.

La sezione critica protetta

Lock l = new ReentrantLock();
long counter = 0;

public void run() {
    l.lock();            // (1)
    int temp = counter;  // (2)
    counter = temp + 1;  // (3)
    l.unlock();          // (4)
}

Le due operazioni

lock() — acquisisce il lock se libero, altrimenti blocca il thread. È bloccante.

unlock() — se ci sono thread in attesa ne sveglia uno, altrimenti rilascia il lock. In ogni caso il thread prosegue. Non è bloccante.

Sono synchronization operations: stabiliscono un ordine di esecuzione fra operazioni di thread diversi. È esattamente questa proprietà che il memory model formalizzerà nella Lezione 3.

Il lock non rende counter++ atomico a livello hardware. Rende indivisibile la sezione critica: nessun altro thread può eseguire la propria fra (1) e (4).

Questo interleaving è possibile?

Domanda tipica da orale. Si risponde senza eseguire nulla: si assume la sequenza, si aggiungono i vincoli, e si cerca una contraddizione.

Le tre proprietà di una buona soluzione

01

Mutua esclusione

Al più un thread esegue la sezione critica alla volta. È la proprietà che il lock garantisce direttamente.

02

Assenza di deadlock

I thread escono prima o poi dalla sezione critica, permettendo agli altri di entrare. Si rompe, per esempio, dimenticando unlock() su un percorso di eccezione — motivo per cui va in finally.

03

Assenza di starvation

Se un thread è pronto a entrare nella sezione critica, deve prima o poi riuscirci. È la più fragile: un lock può garantire mutua esclusione e lasciare comunque un thread fuori per sempre.

Formulate da Edsger W. Dijkstra, che per primo definì il problema della mutua esclusione e ne diede un protocollo di soluzione. La terza proprietà è quella che ritorna nella Lezione 2 con i monitor: il ReadWriteMonitor garantisce mutua esclusione ma affama gli scrittori.

Ogni sezione critica ha un lock associato, ma più sezioni critiche possono usare lo stesso lock. Due thread che usano lock diversi non si escludono a vicenda — un errore facile con synchronized su metodi di istanza, come vedrai nella Lezione 2.
