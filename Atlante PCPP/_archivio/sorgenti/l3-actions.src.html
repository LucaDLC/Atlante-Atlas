Il memory model

Un insieme di regole a livello di linguaggio che determinano quali esecuzioni di un programma sono valide.

La JVM è progettata per generare solo bytecode le cui esecuzioni sono valide nel modello. Questo vale su ogni hardware e ogni runtime.

Risultato: il programmatore può predire il comportamento dei programmi concorrenti. Java è stato il primo linguaggio a definire formalmente il proprio memory model — oggi ce l’hanno C++, C#, Rust, Go, e il ragionamento si trasferisce identico.

Sequential consistency

Introdotta da Leslie Lamport alla fine degli anni Settanta, definisce ciò che il programmatore considera comportamento normale. Un’esecuzione concorrente è sequenzialmente consistente se e solo se:

1

preserva il program order intra-thread — le operazioni di un singolo thread appaiono nel loro ordine sorgente;

2

le operazioni appaiono avvenire istantaneamente — atomicamente, in un unico ordine totale visto da tutti.

Nessuna delle sei esecuzioni produce (0,0). Non è una questione di probabilità: non esiste un ordine totale che lo generi. Eppure PossibleReordering.java lo stampa. Quell’esecuzione non è sequenzialmente consistente.

Perché (0,0) richiede un ciclo

per avere x == 0 serve che x=b preceda b=1[lettura del vecchio valore]
per avere y == 0 serve che y=a preceda a=1[lettura del vecchio valore]
a=1 precede x=b[program order di t1]
b=1 precede y=a[program order di t2]
a=1 → x=b → b=1 → y=a → a=1[ciclo — nessun ordine totale lo ammette]

Garantire sequential consistency per ogni programma richiederebbe di disattivare proprio quelle ottimizzazioni che danno performance. Java non la garantisce sempre. Invece: il memory model definisce per quali programmi è possibile garantirla — e la risposta, in una riga, è: quelli senza data race.

Azioni

Un’azione è una coppia t(o) dove t è l’identificatore del thread e o l’operazione. Ce ne sono di tre tipi:

Variable access

Read e write sulle variabili del programma.

Synchronization action

Primitive di sincronizzazione: acquisire e rilasciare un lock o un monitor, avviare un thread, attendere che un thread termini, accessi volatile.

Other

Qualunque azione non rientri nelle due categorie precedenti.

x=0; // (init(x))
y=0; // (init(y))
a=0; // (init(a))
b=0; // (init(b))

Thread one = new Thread(() -> {
    a=1; // (1)
    x=b; // (2)
});
Thread other = new Thread(() -> {
    b=1; // (3)
    y=a; // (4)
});

one.start();   // (start(t1))
other.start(); // (start(t2))
one.join();    // (join(t1))
other.join();  // (join(t2))
System.out.println(…); // (5)

Le etichette non cambiano il programma — sono notazione. Servono per poter scrivere t1(2) invece di “la seconda istruzione del lambda eseguito da one”. Convenzione della lezione: t1 = one, t2 = other, m = main thread.

Classifica le azioni

La distinzione che conta: le synchronization action sono le uniche che possono creare ordine fra thread diversi.

Un’azione è un evento di esecuzione, non una riga di codice. La stessa operazione nel sorgente, eseguita da tre thread, dà tre azioni distinte — ed è per questo che il modello parla di coppie e non di sole operazioni.
