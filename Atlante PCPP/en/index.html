        How to read the atlas

        The explanations are sheets written one step at a time (Forward, or the arrows ← → after clicking on the sheet). The colours always have the same role:

        arancio · la cosa che cambia adesso blu · il dato di partenza (e il thread t1) viola · un secondo ruolo (e il thread t2) verde · il risultato rosso · scartato o sbagliato

        The typical tool of this atlas is the interleaving builder: you are the scheduler and decide which thread goes ahead. Try it: two threads do counter++, written as two steps. Can you get counter = 1?

        What you must be able to do at the end

        From the official description, in simple words:

        • Analyse the correctness of concurrent Java software and connect it to the Java Memory Model.
        • Analyse the performance of concurrent software.
        • Use threads, locks, final and volatile fields and concurrent collections to build correct and fast software.
        • Use tools to test and analyse concurrency problems.
        • Compare shared memory and message passing.
        • Apply the actor model in Erlang.
        • Describe the differences between multicore CPUs and GPUs and the consequences for performance.

        Estimated time: 30% assignments, 30% preparation, 16% exam, 12% lectures, 12% exercises. Generative AI: allowed during the course as a study tool, forbidden at the exam.
