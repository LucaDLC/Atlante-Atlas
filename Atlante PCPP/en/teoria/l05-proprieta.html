Properties and counterexamples

Lecture 5 (Testing & Verification), first part. A concurrent program is correct if it respects its specification, that is a set of properties. To test it you must know what shape a counterexample has: an interleaving that violates the property. Goetz, chapter 12.

Safety and liveness

SafetyLiveness
intuition"something bad never happens""something good eventually happens"
examples from the slidestwo traffic lights at a crossing are never green together; the size field of a collection is never < 0the light eventually turns red; it will always be possible, eventually, to add elements to the collection
counterexample (the true definition)a finite prefix of an interleaving, ending with the action that violates the propertyan infinite interleaving in which the good thing never arrives

Deadlock-freedom is a property of safety: a deadlock is a state in which no thread can go on any more, and it is reached by a finite interleaving (the philosophers who all take the right fork first). The absence of starvation ("every thread eventually enters") is instead liveness: the counterexample is an infinite execution in which one thread stays out forever, like w2 above.

"Program testing can be used to show the presence of bugs, but never to show their absence!" (Dijkstra, in the slides). A test that fails shows a counterexample; a test that passes proves nothing. For safety properties a test can find the counterexample, because it is finite. The lecture focuses only on safety.
