Formal verification and JavaPathFinder

Lecture 5, last part. Tests run the program and see only the interleavings that happen to occur. Formal verification treats the program and the property as mathematical objects and checks all the interleavings. JavaPathFinder (NASA) does it for Java programs with model checking.

Why it is not always used

  • State explosion: even small programs can have more states than can be visited. It is reduced with abstractions, approximations, and by restricting the problem.
  • Tools: interactive provers (Rocq, Isabelle, Lean), model checkers, SAT/SMT solvers, static analysis. Example of the teacher's research: finding data races in large Java code bases with CodeQL (200 000 lines in less than 2 minutes).
  • Industry uses it more and more (Intel for hardware; NASA used JPF for part of the Curiosity rover).

Tests = generators of interleavings: they find counterexamples but do not prove the absence of errors. Formal verification = all the interleavings, with the cost of the state explosion. Being able to say what kind of property is being checked (safety or liveness) and how its counterexample looks.
