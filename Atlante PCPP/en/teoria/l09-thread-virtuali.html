Platform threads and virtual threads

The lecture of 26 October starts here: which thread to use, and why. A virtual thread that waits does not occupy a system thread; a platform thread does. The example code is compiled and run.

Two kinds of thread

A platform thread is an operating-system thread: heavy, and the system has a limited number of them. A virtual thread is a thread managed by Java: many can exist together. Java runs them on a small group of platform threads (the carriers) only while they work. When a virtual thread blocks (network, file, sleep), it is detached and the carrier serves another one.

They are created like this: Thread.ofVirtual().start(task) and Thread.ofPlatform().start(task). Thread.ofVirtual() returns a Thread.Builder, that is the object that knows how to build threads of that kind.

When to use what

The indications of the lecture, in order of priority:

situationchoice
you want many platform threadsno: do not create many of them
operations that wait (I/O, database, network)virtual threads
work that uses the CPU, and performance matterstasks of the executor (next page)
everything else, for simplicityvirtual threads for everything
The virtual thread does not make a pure computation faster. In the lecture, up to 64 threads, platform and virtual threads take the same time on the count of primes; the difference shows with 2048 threads, where the platform threads are much slower.

Practical rules

For operations that wait, one virtual thread per operation. For heavy computations, use the executor with a fixed number of threads (next page).
Virtual threads are cheap to create and block without holding an OS thread, so they suit I/O-bound work; platform threads are costly and should not be created in large numbers.
