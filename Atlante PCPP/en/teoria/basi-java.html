Java for concurrency

The minimum of Java needed to read the course code: creating and starting a thread, waiting for it, what changes between static and not, and how to launch an exercise with Gradle (also from PowerShell).

Three ways of writing a thread

A thread is a sequence of instructions that advances concurrently with the others: in mixed pieces on one core, or really in parallel on several cores. In Java the behaviour of the thread is written in the run() method.

start() and join()

turnstile.run() does not create a thread: it runs run() as an ordinary method, in the thread that calls it. For concurrency you need start().

join() can throw InterruptedException (if someone interrupts the thread that is waiting). It is a checked exception: Java forces you to handle it with try { … } catch (InterruptedException e) { … } or to declare it with throws. The same holds for await(), wait(), sleep(), acquire().

Why the code of the lectures sits in the constructor

In the code of the lectures the main does almost nothing: it creates an object, and all the work is in the constructor. The reason is a Java rule: main is static, so it belongs to no object and does not see the instance fields. By putting the shared fields (the counter, the lock) in an object, and the threads in an inner class, all the threads see the same fields.

static against instance

Instance field

class Conto { int saldo; }
Conto a = new Conto();
Conto b = new Conto();

Each object has its own saldo: a.saldo and b.saldo are two different variables.

Static field

class Conto { static int totale; }
Conto a = new Conto();
Conto b = new Conto();

There is only one totale for the whole class, shared by all the objects.

It matters a lot for locks: synchronized on an instance method uses the lock of the object, on a static method it uses the lock of the class. They are two different locks: see synchronized (exercise 2.3).

Launching an exercise with Gradle

Command (from the folder week01exercises)What it does
gradle compileJavacompiles everything in app/src/main/java
gradle -PmainClass=exercises01.TestLongCounterExperiments runcompiles and runs the given class (bash, macOS, Linux)
gradle "-PmainClass=exercises01.TestLongCounterExperiments" runthe same thing in PowerShell: the quotes are needed
 
PS> gradle -PmainClass=lecture01.CounterThreads run
Task '.CounterThreads' not found in root project 'lecture01' and its subprojects.
PowerShell spezza il parametro al punto e Gradle riceve .CounterThreads come nome di un task. Metti tutto il parametro tra virgolette: gradle "-PmainClass=lecture01.CounterThreads" run (lo dice anche la guida Gradle del corso).

The files go in app/src/main/java/exercises01/ and the first line of each file is package exercises01;. The name of the class with main is what you pass to -PmainClass, preceded by the package.
