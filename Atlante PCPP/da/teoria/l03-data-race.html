Data race og korrekthed

I JMM er et program korrekt, hvis ingen udførelse har en data race. For at bevise det behøves to ingredienser mere: de konfliktende handlinger og synchronization order. Derefter ser man, hvordan en lås ordner handlingerne, og hvorfor volatile ændrer reglerne.

Synchronization order og velformede udførelser

Den totale rækkefølge, hvori synkroniseringshandlingerne i en udførelse finder sted. Den skal respektere gensidig udelukkelse (låse rigtigt indlejret) og happens-before. Et program kan have mere end én: enhver udførelse har én.

En udførelse er velformet, hvis den er i overensstemmelse med program order, happens-before og synchronization order. JVM'en producerer kun velformede udførelser.

PossibleReordering har kun én synchronization order: m(start(t1)), m(start(t2)), m(join(t1)), m(join(t2)). Trådene har ingen synkroniseringshandlinger af egen.

Konflikterende handlinger og data race

To handlinger er i konflikt, hvis de tilgår den samme ikke-volatile variabel, og mindst én af dem er en skrivning.

Der er en data race mellem a og b, hvis 1) de er i konflikt og 2) de ikke er ordnet af happens-before.

Et program er korrekt synkroniseret, hvis ingen af dets udførelser indeholder en data race. JVM'en garanterer, at alle dens udførelser er sekventielt konsistente: ikke flere paradoksale adfærdsmønstre.

Ret det med en lås, og bevis det

l = new ReentrantLock();   // (init(l))
x = 0; y = 0; a = 0; b = 0;
Thread one = new Thread(() -> {
    l.lock();     // (1)
    a = 1;        // (2)
    x = b;        // (3)
    l.unlock();   // (4)
});
Thread other = new Thread(() -> {
    l.lock();     // (5)
    b = 1;        // (6)
    y = a;        // (7)
    l.unlock();   // (8)
});
one.start();   // (start(t1))
other.start(); // (start(t2))

At forudsige værdierne: synlighed

Hvis a → b, er effekten af a synlig for b. Så man kan bevise, hvilke værdier der er mulige.

Volatile-reglen

Hvis a er en skrivning til en volatile variabel og b en senere læsning af den samme variabel, så er a → b.

  • Adgange til volatile-variable er synkroniseringshandlinger, men giver ikke gensidig udelukkelse: de øger kraftigt de mulige synchronization orders.
  • Ifølge definitionen er adgange til volatile-variable aldrig i konflikt. Så de kan ikke give en data race.

Med volatile a, b i PossibleReordering er kun adgangene til x og y stadig i konflikt, allerede ordnet af start- og termineringsreglerne: programmet er korrekt synkroniseret. De mulige udskrifter er (1,0), (0,1), (1,1); (0,0) ikke.

Du skrev, at der med count volatile er en data race mellem de to skrivninger. Efter kursets definition er det nej: adgange til volatile-variable er ikke i konflikt, så der er ingen data races, og programmet er korrekt synkroniseret. Men race condition'en består: begge tråde kan læse 0 og skrive 1, så count kan være 1. Det er netop sammenligningen, der spørges om i 3.1.9: versionen med låsen udskriver altid 2, den volatile kan udskrive 1. Detaljer i øvelse 3.1 gennemgået.

Strategien i 6 trin (slide 48)

Strategien er en mekanisk fremgangsmåde: der er ingen grund til at "gætte", hvor problemet ligger. Man starter fra handlingerne, tilføjer parrene, der gælder altid (program order, start, termination), og ser derefter på, hvad der afhænger af udførelsen (hvem der tager låsen først, hvilken volatile der læses bagefter). Hvert forskelligt tilfælde giver et andet HB-sæt; til sidst løses hvert eksamensspørgsmål (data race? korrekt synkroniseret? hvilke værdier kan den udskrive?) ved at lede efter stier i disse sæt.

  1. Identificér handlingerne, og klassificér dem (variable access, synchronization, other).
  2. Skriv parrene af program order.
  3. Skriv parrene af synkroniseringshandlingerne: start, termination, monitor, volatile.
  4. Opregn de mulige synchronization orders.
  5. Se på hvilke happens-before-par der ændrer sig fra en synchronization order til den anden.
  6. For hver forskel skriv det tilsvarende happens-before-sæt (f.eks. HB1, HB2).

Med disse sæt kan du: finde data races, bevise at der ikke er nogen (korrekthed), forudsige variablernes værdier.
