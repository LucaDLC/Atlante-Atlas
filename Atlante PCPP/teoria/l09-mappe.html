Mappe concorrenti: dal lock unico a ConcurrentHashMap

Il secondo caso di studio: otto implementazioni di una mappa hash thread-safe, dal lock unico alle strutture senza lock. La regola che le attraversa tutte è la stessa del contatore: tenere i dati scritti vicini a un solo thread.

Le otto mappe

Il secondo caso di studio è una mappa hash thread-safe. La lezione confronta otto implementazioni, dalla più semplice alla libreria di Java:

nomeidea
SynchronizedMapun lock unico sulla mappa intera
StripedMapun array di lock: ogni lock protegge una parte dei bucket. Le slide dicono 16 lock in un punto e 32 in un altro
StripedMapPaddedcome sopra, con padding tra i lock
StripedWriteMapcome StripedMap, ma le liste di coppie (chiave, valore) sono immutabili: le letture non prendono lock
StripedWriteMapPaddedcome sopra, con padding
StripedLevelWriteMapdue livelli: un array di array, ognuno con il suo lock; i sotto-array si ridimensionano separatamente
HashTrieMapsenza lock: operazioni CAS su un hash array mapped trie (Prokopec, Bagwell)
WrapConcHashMapil java.util.concurrent.ConcurrentHashMap di Doug Lea: lock e CAS insieme, con padding

Cosa mostrano le misure

  • Il lock unico (SynchronizedMap) non scala: più thread, più tempo. Sul server è molto peggiore che sul laptop.
  • Con carico bilanciato o dominato dalle scritture, nessuna versione scritta a mano scala bene: vince la ConcurrentHashMap della libreria.
  • Con carico dominato dalle letture, la ConcurrentHashMap resta la migliore; il padding aiuta le versioni con letture non bloccanti.
  • Le letture non bloccanti (liste immutabili) funzionano bene solo se la mappa è letta molto più di quanto è scritta.

Le versioni non bloccanti hanno un costo in memoria: ogni scrittura crea una coppia nuova, quindi servono un garbage collector e una gestione attenta. È per questo che la lezione dice che la tecnica non è praticabile in C o C++ senza un GC.

Le lezioni

Come scegliere

Non scrivere una mappa concorrente da zero: usa ConcurrentHashMap. Scrivi una versione tua solo per capire il trade-off, o se misuri che la libreria non basta per un caso preciso.
Striped locks and padding keep frequently written data core-local, so the cache lines can stay in the Modified state; ConcurrentHashMap combines these ideas in the library.
