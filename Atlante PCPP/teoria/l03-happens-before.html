Happens-before: le regole

Il program order ordina le azioni dentro un thread. Per sapere se un'azione di un thread viene sicuramente prima di un'azione di un altro thread (e quindi se il secondo vede l'effetto del primo) servono le regole di happens-before.

Le coppie: cosa vuol dire a → b

Date due azioni a, b di un'esecuzione, a happens-before b (scritto a → b) se la coppia è ottenuta da una delle regole qui sotto. Se a → b, l'effetto di a è visibile a b.

Le otto regole

Happens-before non si "sente": si costruisce, e solo con queste otto regole. Una coppia (a, b) sta nell'insieme soltanto se una regola la produce. Tre regole lavorano dentro un thread o prima di tutto (program order, default init, final field init). Quattro collegano thread diversi e sono le uniche che permettono a un thread di vedere le scritture di un altro (monitor, volatile, start, termination). L'ultima, la transitiva, incolla le altre in catene. Se fra due azioni di thread diversi non riesci a costruire una catena con queste regole, quelle azioni non sono ordinate.

Il grafo, regola per regola

Start rule: m(start(t1)) → t1(1), m(start(t2)) → t2(3). Termination rule: t1(2) → m(join(t1)), t2(4) → m(join(t2)). Attenzione: la start rule lega start solo alla prima azione del thread, la termination rule solo l'ultima. Le altre seguono per transitività con il program order.

Costruire gli insiemi come nelle slide

All'esame il grafo si scrive come insiemi di coppie: uno per ogni regola che interviene (POm, PO1, PO2 per il program order, S per start, T per termination, poi eventualmente M per il monitor e V per volatile). L'happens-before è la chiusura transitiva dell'unione, indicata con ⁺: si aggiungono tutte le coppie che seguono da una catena. Per decidere se due azioni sono ordinate basta cercare un percorso nel grafo, in un verso o nell'altro.
